404 Not Found

Last updated: March 8, 2026

A 404 error means the server is up and responding, but the specific page or resource you requested does not exist at that URL. Here is what causes it and how to address it.

You might see this error as:

  • HTTP 404
  • 404 Not Found
  • Error 404
  • 404 error
  • Page not found
  • 404 file not found
  • The requested URL was not found
  • 404 nginx
  • 404 Apache

What Does a 404 Error Mean?

The HTTP 404 Not Found status code tells the client (your browser) that the server understood the request but cannot find the resource at the given URL. Crucially, the server is working — it just does not have what you asked for at that path.

For example, if you request https://example.com/old-page and that page has been deleted or moved, the server returns a 404 instead of content.

Common Causes

  • Mistyped URL — an incorrect path, wrong capitalization, or extra characters in the URL.
  • Page deleted or moved — the content existed but was removed or relocated without a redirect.
  • Broken links — a link on another page points to a URL that no longer exists.
  • Changed URL structure — the site reorganized its content but did not set up redirects from the old URLs.
  • Permalink or routing misconfiguration — common in WordPress or CMS platforms where pretty URLs require server-side routing support.
  • Case sensitivity — web servers on Linux are case-sensitive. /Blog/Post and /blog/post are different paths.

How to Fix It

For Visitors

  1. Check the URL — look for typos, extra slashes, or wrong capitalization.
  2. Go to the homepage — navigate to the root domain and search for the content from there.
  3. Use the site's search function — many sites have a search bar to help you find moved content.
  4. Try the Wayback Machine — check web.archive.org to see if the page was cached in the past.
  5. Check external links — if you followed a link, report it to the site owner as a broken link.

For Site Owners

  1. Set up 301 redirects — if you moved or renamed content, redirect the old URL to the new one using a permanent redirect.
  2. Check for broken links — use the Broken Link Checker to find and fix dead links on your site.
  3. Fix permalink settings — in WordPress: Settings → Permalinks → save (no changes needed, just save to flush rewrite rules).
  4. Configure a custom 404 page — provide helpful navigation rather than a blank error page, so users can find what they need.
  5. Monitor 404s in server logs — regularly audit your access logs to find patterns in 404 traffic and fix the underlying issues.

Fixing 404 in nginx

# Add a redirect for a moved page:
location /old-path {
    return 301 /new-path;
}

Fixing 404 in Apache (.htaccess)

Redirect 301 /old-path /new-path

Frequently Asked Questions

Is a 404 error the same as the server being down?

No. A 404 means the server is working and responding, but the specific resource you asked for does not exist. If the server itself were down, you would see a connection error like ERR_CONNECTION_REFUSED or a 502/503 error, not a 404.

Should I use 404 or 410 for deleted content?

A 410 Gone status code is more accurate for intentionally deleted content that will not return. Search engines remove 410 pages from their index faster than 404 pages. For most cases, 404 is fine, but 410 is preferred when the content is permanently gone.

Does Google penalize sites for 404 pages?

404 responses themselves are not a ranking penalty. However, having many broken internal links or external links pointing to 404 pages wastes crawl budget and erodes link equity. Use 301 redirects where possible.

Related Errors

  • 502 Bad Gateway — server is up but upstream is failing.
  • 503 Service Unavailable — server is temporarily unable to handle any requests.
  • ERR_CONNECTION_REFUSED — server is not reachable at all.
