504 Gateway Timeout

Last updated: March 8, 2026

A 504 error means the gateway or proxy waited for an upstream server response but the upstream was too slow or did not respond at all.

You might see this error as:

  • HTTP 504
  • 504 Gateway Timeout
  • Error 504
  • 504 error
  • Gateway timeout
  • 504 Gateway Time-out nginx
  • 504 Cloudflare timeout
  • upstream timed out

Where the Failure Happens

What Does This Error Mean?

HTTP 504 occurs in a multi-server architecture where a gateway (nginx, Cloudflare, AWS ALB, a load balancer) forwards your request to a backend server (Node.js, PHP-FPM, Django, Rails). If the backend does not respond within the gateway's configured timeout, the gateway gives up and returns 504 to the browser.

The gateway itself is working — 504 specifically tells you the upstream server is the problem.

Common Causes

  • Application server overloaded — PHP-FPM, Gunicorn, or Node.js worker pool is saturated.
  • Slow database query — a long-running database query holding up the response.
  • External API call blocking — application waiting for a slow or unresponsive third-party API.
  • Application server crashed — PHP-FPM or a Node.js process died and is not accepting connections.
  • Timeout mismatch — gateway timeout shorter than the time the application legitimately needs.
  • Network issue between gateway and backend — internal network congestion or misconfigured firewall.
  • Memory exhaustion — server running out of RAM and thrashing.

How to Fix It

For Visitors

Refresh the page after a short wait. If the problem persists, contact the site owner — this cannot be fixed from the client side.

For Server Owners

1. Check Application Server Status

Verify your backend process is running:

systemctl status php8.2-fpm
systemctl status gunicorn
pm2 status

2. Check Application Logs

Look for errors, slow queries, or out-of-memory messages in your application logs.

3. Increase Gateway Timeout

In nginx, increase the proxy timeout if your application legitimately needs more time:

proxy_read_timeout 120s;
proxy_connect_timeout 30s;
proxy_send_timeout 30s;

For PHP-FPM, also check request_terminate_timeout in your pool configuration.

4. Optimize Slow Database Queries

Add database query logging to identify slow queries. Add indexes, optimize joins, or add caching for expensive queries.

5. Scale Application Workers

If your worker pool is consistently saturated, increase the number of PHP-FPM children, Gunicorn workers, or Node.js instances.

Frequently Asked Questions

504 vs. 502 — how do I tell which is the problem?

504 means the upstream server is too slow (no response within timeout). 502 means the upstream server responded but the response was invalid or malformed. If your backend is completely down, you typically see 502. If it is running but very slow, you see 504.

Why does Cloudflare show a 504 with its own page?

Cloudflare acts as a reverse proxy. When Cloudflare forwards your request to your origin server and gets no response within its timeout window, it shows its own 504 page. The fix is on your origin server, not Cloudflare.

Related Errors

  • 502 Bad Gateway — invalid response from upstream.
  • 503 Service Unavailable — server temporarily unable to handle requests.
  • 500 Internal Server Error — generic server crash.
  • ERR_TIMED_OUT — browser-side timeout waiting for the server.
