413 Payload Too Large

Last updated: March 8, 2026

The request body exceeds the server's size limit

You might see this error as:

  • HTTP 413
  • 413 Payload Too Large
  • 413 error
  • 413 Request Entity Too Large
  • Request body too large
  • File upload too large
  • nginx 413
  • client_max_body_size

What Does This Error Mean?

A 413 Payload Too Large response indicates that the request entity (body) is larger than the server is willing or able to process. Servers impose size limits to prevent denial-of-service attacks and resource exhaustion. This commonly occurs when uploading large files, sending large JSON payloads, or when server limits are configured too low for the application's needs.

Common Causes

  • File upload exceeds server limit — The uploaded file is larger than the maximum body size configured on the web server. Nginx defaults to 1MB, and many application frameworks have similar low defaults.
  • Large JSON or form data payload — The request body contains a large JSON document or form data that exceeds the server's configured maximum request body size.
  • Reverse proxy body size limit — A reverse proxy (Nginx, HAProxy) in front of the application server has a lower body size limit than the application itself, rejecting the request before it reaches the backend.
  • Base64 encoded data inflation — Binary data encoded as Base64 in JSON payloads is approximately 33% larger than the original data, which can push the request body over server limits.

How to Fix It

1. Increase the server body size limit

Adjust the maximum allowed body size in your web server or reverse proxy configuration.

# Nginx: increase to 50MB
client_max_body_size 50M;

# Apache: increase to 50MB
LimitRequestBody 52428800

# Node.js Express
app.use(express.json({ limit: '50mb' }));

2. Implement chunked uploads

For large file uploads, implement chunked or multipart upload logic that splits the file into smaller pieces and uploads them separately.

3. Compress the request body

Use Content-Encoding: gzip to compress the request body before sending. Ensure the server supports decompressing incoming request bodies.

# Send gzip-compressed request body
curl -X POST -H 'Content-Encoding: gzip' --data-binary @payload.gz https://api.example.com/upload

Frequently Asked Questions

What is the default upload limit in Nginx?

Nginx defaults to 1MB (client_max_body_size 1m). This is intentionally conservative and must be increased for applications that handle file uploads or large payloads.

Can a CDN cause 413 errors?

Yes. CDNs like Cloudflare impose their own request body size limits (e.g., 100MB on Cloudflare Free plan). These limits apply even if your origin server allows larger uploads.

Is 413 the same as 'Request Entity Too Large'?

Yes. The status was originally named '413 Request Entity Too Large' but was renamed to '413 Payload Too Large' in RFC 7231. Both names refer to the same error.
