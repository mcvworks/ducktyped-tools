508 Loop Detected

Last updated: March 8, 2026

The server detected an infinite loop while processing the request

You might see this error as:

  • HTTP 508
  • 508 Loop Detected
  • 508 error
  • Infinite loop
  • WebDAV loop detected

What Does This Error Mean?

A 508 Loop Detected response indicates that the server terminated an operation because it encountered an infinite loop while processing a request with 'Depth: infinity'. This status code is defined in the WebDAV extension and occurs when recursive operations like PROPFIND or COPY encounter a binding loop where a collection contains itself directly or indirectly.

Common Causes

  • WebDAV binding loop — A WebDAV collection (directory) contains a binding (reference) that points back to itself or to a parent collection, creating an infinite loop during recursive operations.
  • Symbolic link loop on the file system — The server's underlying file system has symbolic links that create circular references, causing recursive WebDAV operations to loop indefinitely.
  • Recursive copy or move operation — A COPY or MOVE operation with Depth: infinity encounters a directory structure that references itself, causing the server to detect an infinite recursion.

How to Fix It

1. Remove circular references

Identify and remove symbolic links or WebDAV bindings that create circular references in the directory structure.

2. Limit operation depth

Instead of using Depth: infinity, specify a finite depth for recursive operations to prevent loops from being an issue.

# Use finite depth for PROPFIND
curl -X PROPFIND -H 'Depth: 1' https://example.com/webdav/collection

3. Check symbolic links on the server

Audit the file system for symbolic link loops. Use tools to detect circular references before running recursive operations.

# Find symbolic link loops on Linux
find /path/to/webdav -type l -follow 2>&1 | grep 'loop'

Frequently Asked Questions

Is 508 only used with WebDAV?

It was defined for WebDAV but the concept applies to any server that detects infinite loops in recursive processing. Some APIs use it for detected circular dependencies.

How does the server detect the loop?

The server tracks visited resources during recursive operations. If it encounters a resource it has already visited in the current recursion path, it detects a loop and returns 508.
