417 Expectation Failed

Last updated: March 8, 2026

The server cannot meet the requirements of the Expect header

You might see this error as:

  • HTTP 417
  • 417 Expectation Failed
  • 417 error
  • Expect header failed
  • Expect: 100-continue failed

What Does This Error Mean?

A 417 Expectation Failed response indicates that the server cannot meet the expectation specified in the Expect header of the request. The most common Expect header value is '100-continue', which asks the server to confirm it will accept the request body before the client sends it. Some servers and proxies do not support this mechanism and respond with 417.

Common Causes

  • Server does not support Expect: 100-continue — The server or an intermediary proxy does not implement the 100-continue mechanism, and rejects the Expect header outright with a 417 response.
  • HTTP library auto-adding Expect header — Some HTTP libraries (like libcurl) automatically add 'Expect: 100-continue' for POST requests with large bodies. Servers that do not support this respond with 417.
  • Proxy or load balancer interference — An intermediary proxy or load balancer strips or rejects the Expect header, preventing the 100-continue negotiation from completing.

How to Fix It

1. Remove the Expect header

Explicitly remove the Expect header from your request. In curl, use an empty Expect header to prevent the automatic 100-continue behavior.

# Disable Expect header in curl
curl -X POST -H 'Expect:' -d @large-file.json https://api.example.com/upload

2. Configure your HTTP library

Most HTTP libraries allow you to disable the automatic Expect: 100-continue behavior. Check your library's documentation for the relevant setting.

3. Enable 100-continue support on the server

If you control the server, ensure it properly handles the Expect: 100-continue header by sending a 100 Continue response before the client sends the body.

Frequently Asked Questions

What is the Expect: 100-continue mechanism?

It allows a client to check if the server will accept a request before sending a large body. The client sends headers with Expect: 100-continue, waits for a 100 response, then sends the body. This avoids wasting bandwidth on rejected requests.

Why does curl add Expect: 100-continue automatically?

curl adds this header for POST requests larger than 1024 bytes as an optimization. If the server would reject the request (e.g., 401), the client avoids sending the large body unnecessarily.
