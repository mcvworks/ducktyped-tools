421 Misdirected Request

Last updated: March 8, 2026

The request was directed to a server that cannot produce a response

You might see this error as:

  • HTTP 421
  • 421 Misdirected Request
  • 421 error
  • Misdirected request
  • Wrong server

What Does This Error Mean?

A 421 Misdirected Request response indicates that the request was directed at a server that is not able to produce a response for the requested URI. This typically occurs with HTTP/2 connection coalescing, where the client reuses an existing connection to a server that shares a TLS certificate but is not authoritative for the requested domain. The client should retry the request on a new connection.

Common Causes

  • HTTP/2 connection coalescing mismatch — The client is reusing an HTTP/2 connection to a server that shares a TLS certificate with another domain, but the server cannot serve content for the requested hostname.
  • Wildcard or multi-domain certificate issues — A TLS certificate covers multiple domains (SAN or wildcard), and the client assumes any server presenting this certificate can serve all covered domains.
  • CDN or load balancer misconfiguration — A CDN or load balancer is presenting a shared certificate but not all edge servers are configured to handle all domains covered by the certificate.
  • Virtual host configuration mismatch — The server has a TLS certificate for multiple domains but only has virtual host configurations for some of them, causing it to reject requests for unconfigured domains.

How to Fix It

1. Retry on a new connection

When a client receives a 421, it should open a new TCP/TLS connection specifically for the target domain and retry the request, bypassing connection coalescing.

2. Configure all virtual hosts on the server

Ensure the server has proper virtual host configurations for all domains covered by its TLS certificate so it can serve requests for any of them.

3. Use separate certificates per domain

If the server should not handle requests for certain domains on its certificate, use separate TLS certificates for each domain to prevent connection coalescing.

Frequently Asked Questions

What is HTTP/2 connection coalescing?

HTTP/2 allows clients to reuse a single TCP connection for multiple domains if they resolve to the same IP and share a TLS certificate. This optimization can cause 421 errors when the server cannot serve all domains on the certificate.

Is 421 a client-side or server-side issue?

It is usually a server configuration issue. The server presents a certificate covering domains it cannot serve. The client correctly detects this when the server returns 421 and retries on a new connection.
