428 Precondition Required

Last updated: March 8, 2026

The server requires the request to be conditional

You might see this error as:

  • HTTP 428
  • 428 Precondition Required
  • 428 error
  • Precondition required
  • If-Match required

What Does This Error Mean?

A 428 Precondition Required response indicates that the server requires the request to include conditional headers like If-Match or If-Unmodified-Since. This is used to prevent the 'lost update' problem, where a client overwrites changes made by another client. The server enforces conditional requests to ensure clients have the latest version before making modifications.

Common Causes

  • Missing If-Match header on update — The server requires an If-Match header containing the resource's current ETag when making PUT or PATCH requests, but the client did not include one.
  • Missing If-Unmodified-Since header — The server requires a timestamp-based precondition to verify the resource has not been modified since the client last retrieved it.
  • API requires optimistic concurrency control — The API is designed to enforce optimistic concurrency by requiring all modification requests to include precondition headers, preventing silent overwrites.

How to Fix It

1. Fetch the resource first and include the ETag

GET the resource to obtain its current ETag, then include it as an If-Match header in your modification request.

# 1. GET the resource and note the ETag
curl -I https://api.example.com/resource/123
# ETag: "abc123"

# 2. Include If-Match in your update
curl -X PUT \
  -H 'If-Match: "abc123"' \
  -H 'Content-Type: application/json' \
  -d '{"name": "updated"}' \
  https://api.example.com/resource/123

2. Use If-Unmodified-Since with Last-Modified

If the server uses timestamp-based preconditions, include the Last-Modified value from a GET response as the If-Unmodified-Since header in your update request.

3. Check API documentation for required headers

Review the API documentation to determine which precondition headers are required for modification endpoints and how to obtain the necessary values.

Frequently Asked Questions

What is the difference between 412 and 428?

428 means the server requires precondition headers but the client did not include them. 412 means the client included precondition headers but they did not match the current resource state.

Why do servers require conditional requests?

To prevent the 'lost update' problem. Without preconditions, two clients could read a resource, both modify it, and the second write would silently overwrite the first client's changes.
