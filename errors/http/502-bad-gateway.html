502 Bad Gateway

Last updated: March 8, 2026

A 502 error means a gateway or proxy server received an invalid response from the backend server it was trying to reach. Here is what causes it and how to fix it.

You might see this error as:

  • HTTP 502
  • 502 Bad Gateway
  • Error 502
  • 502 error
  • 502 Bad Gateway nginx
  • 502 Bad Gateway Cloudflare
  • Bad gateway error
  • Server Error 502
  • 502 proxy error
  • upstream prematurely closed connection

Where the Failure Happens

What Does 502 Bad Gateway Mean?

The HTTP 502 Bad Gateway status code is returned by a gateway or reverse proxy (such as nginx, Apache's mod_proxy, Cloudflare, or a load balancer) when the upstream server it is forwarding requests to returns an invalid or empty response.

The gateway itself is operational — it received your request and tried to forward it. The problem is with the backend: the application server crashed, timed out, or sent a malformed response.

Common architectures where this occurs:

  • nginx (reverse proxy) → PHP-FPM (PHP application)
  • nginx (reverse proxy) → Node.js / Python / Ruby application
  • Cloudflare CDN → your origin server
  • Load balancer → backend application instances

Common Causes

  • Application server crashed — PHP-FPM, Gunicorn, Node.js, or another backend process is down.
  • Application server overloaded — the backend is alive but not responding within the configured timeout.
  • Upstream timeout — the gateway timed out waiting for the backend to respond.
  • Misconfigured upstream in nginx/Apache — the proxy is pointing to the wrong IP, port, or socket.
  • Network issue between gateway and backend — firewall rules, routing issues, or a private network failure.
  • Memory or resource exhaustion on the backend — the backend server ran out of memory or file descriptors.
  • Deployment errors — a recent code deploy caused the application to fail to start.

How to Fix It

For Visitors

As a visitor, the issue is on the server's end. Try:

  1. Wait a few minutes and refresh the page — transient overload often resolves itself.
  2. Try a different browser or device to rule out local issues.
  3. Check if the site is down for everyone using the HTTP Latency Checker.

For Site Owners

1. Check the Application Server

Verify your backend application process is running:

# Check PHP-FPM
sudo systemctl status php8.1-fpm

# Check Node.js (if using PM2)
pm2 status

# Check Gunicorn/uWSGI
sudo systemctl status gunicorn

2. Check nginx Error Logs

sudo tail -f /var/log/nginx/error.log

Look for "upstream" errors — they will show the exact cause (connection refused, timeout, etc.).

3. Verify Upstream Configuration in nginx

location / {
    proxy_pass http://127.0.0.1:3000;  # Make sure port is correct
    proxy_read_timeout 60s;
    proxy_connect_timeout 10s;
}

4. Restart the Application Server

sudo systemctl restart php8.1-fpm
# or
sudo systemctl restart gunicorn

5. Check Server Resources

Check memory, CPU, and disk usage. An OOM (Out of Memory) event can kill backend processes:

free -h
df -h
top

6. Increase Upstream Timeout

If the backend is slow to respond (e.g., a heavy computation), increase the timeout in nginx:

proxy_read_timeout 120s;
proxy_connect_timeout 30s;

Frequently Asked Questions

What is the difference between 502 and 503?

A 502 Bad Gateway means the gateway received an invalid response from the upstream — the upstream is responding, but with garbage or nothing usable. A 503 Service Unavailable means the server itself cannot handle requests, typically due to maintenance mode or being completely overloaded with no capacity left.

Does Cloudflare return 502?

Yes. When Cloudflare cannot reach your origin server or your origin returns an error, Cloudflare returns a 502. Check your origin server's health and ensure Cloudflare's IP ranges are not blocked by your firewall.

Can a 502 error be caused by DNS?

Indirectly. If your nginx upstream uses a hostname (rather than an IP) that resolves to an incorrect address, requests will be proxied to the wrong server. Use the DNS Lookup tool to verify resolution.
