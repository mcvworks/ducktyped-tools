414 URI Too Long

Last updated: March 8, 2026

The request URL is longer than the server is willing to process

You might see this error as:

  • HTTP 414
  • 414 URI Too Long
  • 414 error
  • 414 Request-URI Too Large
  • URL too long
  • Query string too long

What Does This Error Mean?

A 414 URI Too Long response indicates that the request target (URL) is longer than the server is willing to interpret. This typically occurs when query strings become excessively long, often due to form data being sent via GET instead of POST, or when applications encode large amounts of state in URL parameters. Most servers limit URLs to 8KB-16KB.

Common Causes

  • Excessive query string parameters — The URL contains too many query parameters, often from forms using GET method or applications encoding complex state in the URL.
  • Form data sent via GET instead of POST — A form with many fields is using the GET method, which appends all form data to the URL as query parameters, easily exceeding URL length limits.
  • Redirect loop with accumulating parameters — A redirect loop is appending parameters to the URL on each redirect, causing the URL to grow indefinitely until it exceeds server limits.
  • Base64 data in URL — Large encoded data (such as Base64-encoded images or tokens) is included directly in the URL path or query string.

How to Fix It

1. Use POST instead of GET for large data

Switch from GET to POST for requests that include large amounts of data. POST transmits data in the request body, which has much higher limits.

<!-- Change form method from GET to POST -->
<form method="POST" action="/search">
  <!-- form fields -->
</form>

2. Increase server URL length limit

If you control the server, increase the maximum allowed URL length. Be cautious about setting it too high, as very long URLs can be used in attacks.

# Nginx: increase to 32KB
large_client_header_buffers 4 32k;

# Apache: increase to 16KB
LimitRequestLine 16384

3. Use request body or headers for data

Move large data payloads from URL parameters to the request body or custom headers. For API endpoints, accept filter criteria in a POST body instead of query parameters.

Frequently Asked Questions

What is the maximum URL length?

There is no official maximum in the HTTP specification. In practice, most browsers support URLs up to 2,048-8,192 characters. Servers like Nginx default to 8KB and Apache to 8,190 bytes.

Can bookmarks cause 414 errors?

If a bookmark contains an extremely long URL with many query parameters, it could trigger a 414 error when opened. This is rare but possible with dynamically generated URLs.
