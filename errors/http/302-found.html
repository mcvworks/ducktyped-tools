302 Found

Last updated: March 8, 2026

The requested resource temporarily resides at a different URL

You might see this error as:

  • HTTP 302
  • 302 redirect
  • 302 Found
  • 302 Moved Temporarily
  • Temporary redirect
  • 302 status code

What Does This Error Mean?

A 302 Found response tells the client that the requested resource temporarily resides at a different URI. Unlike a 301, the client should continue to use the original URL for future requests because the redirect is not permanent. Historically, some clients changed POST requests to GET when following a 302, which led to the creation of 307.

Common Causes

  • Temporary content relocation — The resource has been temporarily moved during maintenance, A/B testing, or a staged rollout, and the original URL should remain the canonical reference.
  • Authentication redirect — The server is redirecting unauthenticated users to a login page before granting access to the originally requested resource.
  • Geographic or device-based routing — The server is temporarily directing users to a localized or device-specific version of the page based on their location or user agent.
  • Incorrect redirect type configured — A 302 was used when a 301 was intended. This is a common misconfiguration that can prevent search engines from properly indexing the destination URL.

How to Fix It

1. Determine if the redirect should be permanent

If the redirect is not truly temporary, change it to a 301. Using 302 for permanent moves prevents search engines from transferring ranking signals to the new URL.

2. Use 307 for method-preserving temporary redirects

If you need to guarantee that POST and other non-GET methods are preserved during the redirect, use 307 instead of 302. The 302 status historically allowed method changes.

3. Check redirect loops

Ensure that the target URL does not redirect back to the original URL, creating an infinite redirect loop. Use a redirect checker to trace the full chain.

curl -Ls -o /dev/null -w '%{url_effective}\n%{redirect_url}\n' https://example.com

Frequently Asked Questions

Does a 302 redirect pass SEO value?

Not reliably. Search engines treat 302 as temporary and generally keep the original URL in their index. For permanent URL changes, use a 301 redirect instead.

Why does my browser change POST to GET after a 302?

This is a historical behavior where some clients convert POST requests to GET when following a 302. To guarantee the method is preserved, use a 307 Temporary Redirect instead.
