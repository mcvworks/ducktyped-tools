408 Request Timeout

Last updated: March 8, 2026

A 408 error means the server closed the connection because the client did not finish sending its request in time. The server was waiting and eventually gave up.

You might see this error as:

  • HTTP 408
  • 408 Request Timeout
  • 408 error
  • Request timeout
  • Server timeout
  • Connection timeout

What Does This Error Mean?

HTTP 408 is sent by the server when the client opened a connection but did not send a complete request within the server's timeout window. Web servers keep connections open for a limited time to save resources — if the client takes too long, the server sends 408 and closes the connection.

Note the direction: 408 is the server timing out while waiting for the client, not the other way around. ERR_TIMED_OUT is when the browser gives up waiting for the server.

Common Causes

  • Slow internet upload speed — large file uploads taking longer than the server's timeout allows.
  • Network interruption mid-request — the client started sending but the connection dropped.
  • Server timeout set too low — aggressive timeout configuration cutting off legitimate slow requests.
  • Client-side processing delay — client-side code taking too long to assemble the full request.
  • Keep-alive connection reuse — reusing a stale keep-alive connection that the server already timed out.
  • Load balancer timeout mismatch — load balancer forwarding a request to a backend that already closed the connection.

How to Fix It

For Users

1. Retry the Request

Refresh the page or resubmit the form. A transient network blip is often the cause.

2. Check Your Upload Speed

If uploading files, run a speed test. A slow upload connection may not be able to transfer the file before the server times out. Try with a smaller file first.

3. Check Network Stability

Switch to a wired connection if on Wi-Fi. Unstable connections cause partial requests that trigger 408.

For Server Owners

4. Increase Client Timeout Settings

In nginx, adjust client_header_timeout and client_body_timeout:

client_header_timeout 30s;
client_body_timeout 60s;

In Apache, use Timeout directive:

Timeout 120

5. Review Load Balancer Timeout Configuration

Ensure load balancer timeouts (e.g., AWS ALB idle timeout) are at least as long as your backend server's request timeout.

Frequently Asked Questions

408 vs. 504 — what is the difference?

A 504 Gateway Timeout occurs when a gateway/proxy times out waiting for an upstream server — that is a server-to-server timeout. A 408 occurs when the server times out waiting for a client to finish sending its request.

Do browsers automatically retry on 408?

Yes, according to RFC 9110. Browsers may automatically retry idempotent requests (GET, HEAD) on a 408. Non-idempotent requests like POST are typically not automatically retried.

Related Errors

  • 504 Gateway Timeout — gateway waiting for upstream server.
  • ERR_TIMED_OUT — browser waiting for server response.
  • 400 Bad Request — malformed request that could not be processed.
