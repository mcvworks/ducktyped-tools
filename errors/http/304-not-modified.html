304 Not Modified

Last updated: March 8, 2026

The resource has not been modified since the last request

You might see this error as:

  • HTTP 304
  • 304 Not Modified
  • 304 status code
  • Browser cache 304
  • If-Modified-Since 304

What Does This Error Mean?

A 304 Not Modified response indicates that the cached version of the requested resource is still valid and can be reused. The server sends this when the client includes conditional headers like If-Modified-Since or If-None-Match, and the resource has not changed. This saves bandwidth by avoiding retransmission of unchanged content.

Common Causes

  • Valid browser cache — The browser has a cached copy of the resource and sent a conditional request. The server confirmed the cached version is still current by responding with 304.
  • ETag match — The client sent an If-None-Match header containing the ETag from a previous response, and the server determined the resource has not changed.
  • Last-Modified date unchanged — The client sent an If-Modified-Since header, and the resource has not been modified since the timestamp provided.

How to Fix It

1. Force a fresh request

If you need the latest version of a resource, bypass the cache by doing a hard refresh (Ctrl+Shift+R) or adding a cache-busting query parameter to the URL.

# Force reload with curl (no cache)
curl -H 'Cache-Control: no-cache' https://example.com/resource

2. Configure cache headers properly

If your server is returning 304 when content has changed, check that your ETag generation and Last-Modified timestamps are updating correctly when content changes.

3. Disable caching for dynamic content

For resources that change frequently, set appropriate cache headers to prevent stale content from being served.

# Nginx: disable caching for dynamic endpoints
location /api/ {
    add_header Cache-Control "no-store, no-cache, must-revalidate";
}

Frequently Asked Questions

Is a 304 response an error?

No. A 304 is a successful response that tells the client its cached copy is still valid. It is an optimization that reduces bandwidth usage and improves page load times.

Does a 304 response have a body?

No. A 304 response must not contain a message body. The client uses its cached copy of the resource instead.

How do I prevent 304 responses during development?

Open browser DevTools and check 'Disable cache' in the Network tab, or use Ctrl+Shift+R for hard refresh. You can also set Cache-Control: no-store headers on your development server.
