416 Range Not Satisfiable

Last updated: March 8, 2026

The requested byte range cannot be fulfilled by the server

You might see this error as:

  • HTTP 416
  • 416 Range Not Satisfiable
  • 416 error
  • Requested range not satisfiable
  • Range header error

What Does This Error Mean?

A 416 Range Not Satisfiable response indicates that the Range header in the request specifies a byte range that cannot be satisfied for the target resource. This typically happens when the requested range exceeds the size of the resource, or the range format is invalid. The response includes a Content-Range header indicating the actual size of the resource.

Common Causes

  • Range exceeds resource size — The Range header requests bytes beyond the end of the file. For example, requesting bytes 1000-2000 of a file that is only 500 bytes long.
  • Stale resume position — A download resume attempt specifies a byte offset from a previous partial download, but the file on the server has been replaced with a smaller version.
  • Invalid range format — The Range header is malformed or specifies an invalid range, such as a start position greater than the end position.
  • Server does not support range requests — The server does not support partial content delivery but the client is sending Range headers, often due to automatic resume logic in download managers.

How to Fix It

1. Remove the Range header and download the full resource

If the range request is not essential, remove the Range header to download the complete resource. This is the simplest fix for one-off downloads.

# Download without range header
curl -o file.zip https://example.com/file.zip

# Instead of
curl -H 'Range: bytes=1000-' -o file.zip https://example.com/file.zip

2. Check the resource size before requesting a range

Send a HEAD request first to get the Content-Length and confirm the resource supports range requests (Accept-Ranges: bytes), then construct a valid range.

curl -I https://example.com/file.zip

3. Restart the download from the beginning

If you are resuming a failed download and get 416, the file on the server may have changed. Delete the partial download and start fresh.

Frequently Asked Questions

What are range requests used for?

Range requests allow downloading specific portions of a file, enabling features like download resume, video seeking, and parallel chunk downloads. They are essential for media streaming.

How do I check if a server supports range requests?

Send a HEAD request and look for the 'Accept-Ranges: bytes' header in the response. If present, the server supports byte-range requests.
