406 Not Acceptable

Last updated: March 8, 2026

The server cannot produce a response matching the client's Accept headers

You might see this error as:

  • HTTP 406
  • 406 Not Acceptable
  • 406 error
  • Not acceptable
  • Accept header mismatch

What Does This Error Mean?

A 406 Not Acceptable response indicates that the server cannot produce a response matching the list of acceptable values defined in the request's Accept, Accept-Language, Accept-Encoding, or Accept-Charset headers. The server's available representations of the resource do not match what the client is willing to accept. This is part of HTTP content negotiation.

Common Causes

  • Mismatched Accept header — The client is requesting a content type (e.g., application/xml) that the server does not support for the requested resource. The server can only respond with formats not listed in the Accept header.
  • API version negotiation failure — The client is requesting a specific API version through Accept headers (e.g., application/vnd.api+json;version=3) that the server does not support.
  • Strict content negotiation configuration — The server is configured with strict content negotiation and refuses to send a response in a format the client did not explicitly request, rather than falling back to a default.
  • Language or encoding mismatch — The Accept-Language or Accept-Encoding headers specify languages or encodings that the server cannot provide for the requested resource.

How to Fix It

1. Broaden the Accept header

Include more acceptable content types in your Accept header, or use a wildcard to accept any format the server can provide.

# Accept any content type
curl -H 'Accept: */*' https://api.example.com/resource

# Accept JSON or XML
curl -H 'Accept: application/json, application/xml' https://api.example.com/resource

2. Check the API documentation

Review the API documentation to determine which content types are supported and ensure your Accept header matches one of the available formats.

3. Remove restrictive Accept headers

If your HTTP client or framework is adding restrictive Accept headers automatically, configure it to send broader accept values or remove custom Accept headers.

4. Configure server to provide a default format

On the server side, consider returning a default representation (like JSON) instead of 406 when content negotiation fails, as many clients expect a response regardless of Accept headers.

Frequently Asked Questions

Is 406 common in normal web browsing?

No. Browsers send broad Accept headers that match most server configurations. This error is more common in API requests where clients specify narrow content type requirements.

Should APIs return 406 or just default to JSON?

It depends on the API design. Strict APIs return 406 to enforce proper content negotiation. Pragmatic APIs default to JSON and ignore the Accept header when no match is found.
