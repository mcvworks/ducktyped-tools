411 Length Required

Last updated: March 8, 2026

The server requires a Content-Length header in the request

You might see this error as:

  • HTTP 411
  • 411 Length Required
  • 411 error
  • Content-Length required
  • Length required error

What Does This Error Mean?

A 411 Length Required response indicates that the server refuses to accept the request because it requires a Content-Length header. Some servers need to know the exact size of the request body before processing it, particularly for resource allocation or security reasons. This commonly occurs with POST and PUT requests that have a body but no Content-Length header.

Common Causes

  • Missing Content-Length header — The request includes a body but does not specify the Content-Length header. The server requires this header to know the expected size of the incoming data.
  • Chunked transfer encoding not supported — The client is using chunked transfer encoding (Transfer-Encoding: chunked) but the server does not support it and requires a fixed Content-Length instead.
  • Proxy stripping headers — An intermediary proxy is removing the Content-Length header from the request before forwarding it to the origin server.

How to Fix It

1. Add Content-Length header to the request

Calculate the size of the request body in bytes and include it as the Content-Length header value. Most HTTP libraries do this automatically.

# curl automatically adds Content-Length for -d
curl -X POST -d '{"key":"value"}' -H 'Content-Type: application/json' https://api.example.com/endpoint

2. Avoid chunked transfer encoding

If the server does not support chunked encoding, buffer the entire request body and send it with a Content-Length header instead of streaming it in chunks.

3. Check HTTP client library settings

Ensure your HTTP client library is not stripping or omitting the Content-Length header. Some libraries omit it when using streaming or async request bodies.

Frequently Asked Questions

Why do some servers require Content-Length?

Servers may require Content-Length to allocate memory, enforce upload size limits, or prevent slow-loris attacks. Without it, the server cannot know when the request body ends without reading to EOF.

Does GET require Content-Length?

No. GET requests typically do not have a body, so Content-Length is not needed. This error almost exclusively affects POST, PUT, and PATCH requests.
