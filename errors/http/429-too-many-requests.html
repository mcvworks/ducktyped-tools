429 Too Many Requests

Last updated: March 8, 2026

A 429 error means you have hit the server's rate limit. The server is telling you to slow down — you have sent too many requests in a given time window.

You might see this error as:

  • HTTP 429
  • 429 Too Many Requests
  • 429 error
  • Rate limited
  • Rate limit exceeded
  • Too many requests
  • Retry-After header
  • API rate limit
  • 429 throttled

What Does This Error Mean?

HTTP 429 is returned when a server-side rate limiter determines that a client is making requests too frequently. Rate limiting protects servers from abuse, prevents individual clients from monopolizing resources, and enforces API usage tiers.

The response often includes:

  • Retry-After — seconds to wait, or a date/time to retry after.
  • X-RateLimit-Limit — total requests allowed in the window.
  • X-RateLimit-Remaining — requests remaining in the current window.
  • X-RateLimit-Reset — Unix timestamp when the window resets.

Common Causes

  • Too many API calls in a short period — exceeding the requests-per-minute or requests-per-hour limit.
  • Polling without backoff — repeatedly checking a resource without waiting between attempts.
  • Multiple concurrent requests — firing many parallel requests at once.
  • Shared IP rate limiting — if you share an IP with others (NAT, VPN), their requests count toward your limit.
  • Automated tools or scrapers — scripts making requests faster than humans would.
  • Bug causing retry loops — client code retrying failed requests without a backoff delay.

How to Fix It

1. Respect the Retry-After Header

Always check for and honor the Retry-After header in 429 responses before retrying.

2. Implement Exponential Backoff

If no Retry-After is provided, use exponential backoff with jitter:

const delay = Math.pow(2, attemptNumber) * 1000 + Math.random() * 1000;
await new Promise(resolve => setTimeout(resolve, delay));

3. Cache Responses

Cache API responses where the data does not need to be real-time. This reduces redundant requests and helps stay within rate limits.

4. Batch Requests

If the API supports batch operations, combine multiple requests into one instead of making individual calls for each item.

5. Upgrade Your API Tier

If your usage legitimately exceeds the free or basic tier limits, consider upgrading to a higher tier with a larger rate limit quota.

For Server Owners — Implementing Rate Limiting

In nginx, use the limit_req_zone and limit_req directives. In Express, use packages like express-rate-limit. Always include Retry-After in your 429 responses.

Frequently Asked Questions

Is 429 the same as 503 Service Unavailable?

No. 503 means the server cannot handle any requests right now — it is overloaded or in maintenance. 429 is targeted at a specific client — the server is fine, but you personally are sending too many requests.

Can 429 be caused by a single browser tab?

Yes. JavaScript applications that make frequent API calls — especially real-time polling or rapid user interactions — can trigger 429 from a single browser session.
