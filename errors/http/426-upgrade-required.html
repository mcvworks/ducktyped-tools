426 Upgrade Required

Last updated: March 8, 2026

The server requires the client to upgrade to a different protocol

You might see this error as:

  • HTTP 426
  • 426 Upgrade Required
  • 426 error
  • Upgrade required
  • Protocol upgrade needed
  • WebSocket upgrade

What Does This Error Mean?

A 426 Upgrade Required response indicates that the server refuses to process the request using the current protocol and requires the client to upgrade to a different protocol specified in the Upgrade header. This is commonly used to enforce HTTPS, require WebSocket connections, or transition to newer HTTP versions.

Common Causes

  • HTTP to HTTPS upgrade required — The server requires a secure connection and is responding with 426 to indicate the client must switch to HTTPS. This is less common than 301 redirects for HTTPS enforcement.
  • WebSocket upgrade expected — The endpoint expects a WebSocket connection but received a regular HTTP request. WebSocket connections start as HTTP requests with an Upgrade: websocket header.
  • Protocol version too old — The server requires a newer version of the HTTP protocol than the client is using, such as requiring HTTP/2 or HTTP/3.

How to Fix It

1. Use the protocol specified in the Upgrade header

Check the Upgrade header in the 426 response to see which protocol the server requires, and reconnect using that protocol.

# Check which protocol is required
curl -I http://example.com/ws-endpoint
# Look for: Upgrade: websocket, TLS/1.3, h2c

2. Switch to HTTPS

If the server requires HTTPS, change your URL scheme from http:// to https:// and retry the request.

3. Use a WebSocket client for WebSocket endpoints

If the endpoint requires WebSocket, use a WebSocket client library instead of a regular HTTP client.

// JavaScript WebSocket connection
const ws = new WebSocket('wss://example.com/ws-endpoint');

Frequently Asked Questions

Is 426 commonly used for HTTP to HTTPS redirects?

No. Most servers use 301 or 307 redirects for HTTP to HTTPS enforcement. The 426 status is technically more correct but much less commonly used in practice.

What protocols can be specified in the Upgrade header?

Common values include TLS/1.0 (for HTTPS upgrade), websocket (for WebSocket), h2c (for HTTP/2 cleartext), and HTTP/2.0. The server specifies which protocol it requires.
