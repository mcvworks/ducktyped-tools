403 Forbidden

Last updated: March 8, 2026

A 403 error means the server refuses to serve the requested resource. Unlike a 401, this is not about missing authentication — the server knows who you are but will not allow access.

You might see this error as:

  • HTTP 403
  • 403 Forbidden
  • Error 403
  • 403 error
  • Access denied
  • 403 Forbidden nginx
  • 403 Forbidden Apache
  • You don't have permission
  • 403 vs 401

What Does This Error Mean?

HTTP 403 is an authorization error. The server understood your request and may have verified your identity, but access to the resource is not permitted. The server will not reveal whether the resource exists — it just says "no."

This is useful for security: a site can use 403 to deny access to sensitive paths without confirming those paths exist. Some servers return 404 in place of 403 to avoid leaking information about protected resources.

Common Causes

  • Incorrect file permissions — file or directory not readable by the web server process (e.g., wrong chmod on Linux).
  • Missing index file — directory listing is disabled and no index.html or index.php exists.
  • .htaccess restrictions — Apache deny rules or password protection in .htaccess.
  • IP blocking — your IP address is on a block list or the server only allows specific IP ranges.
  • Web Application Firewall (WAF) — a WAF rule flagged your request as suspicious.
  • Geo-restriction — the site blocks visitors from certain countries or regions.
  • User role restriction — your account lacks the permission level required for the action.
  • CORS policy — cross-origin requests blocked by the server's CORS configuration.

How to Fix It

For Visitors

1. Log In or Upgrade Your Account

If the page requires an account or a specific subscription level, ensure you are logged in with the correct account.

2. Try from a Different Network

If your IP is blocked, connecting from a different network (or VPN) may resolve the issue. Some sites use geo-blocking.

3. Contact the Site Owner

If you should have access and do not, contact support. Your account may have been restricted, or there may be a misconfiguration.

For Server Owners

4. Check File Permissions

On Linux, files should typically be 644 and directories 755. Ensure the web server user can read them:

chmod 644 /var/www/html/index.html
chmod 755 /var/www/html/

5. Add an Index File

If directory listing is disabled (as it should be), ensure an index file (index.html, index.php) exists in each accessible directory.

6. Review .htaccess and nginx Config

Check for Deny from all or deny rules that may be too broad. Ensure configuration changes were not accidentally deployed.

Frequently Asked Questions

Does 403 mean the resource exists?

Not necessarily. Servers can return 403 for both existing and non-existing resources to avoid revealing whether protected paths exist. Some servers explicitly use 404 for all denied requests.

Can a CDN or proxy cause 403 errors?

Yes. Cloudflare and other CDN/WAF services have rules that can block requests based on patterns in headers, query strings, or request bodies. Check your CDN's security dashboard for blocked requests.

Is 403 ever intentionally used as a response to bots?

Yes. Many sites return 403 to scrapers, crawlers not in robots.txt, or requests with suspicious User-Agent strings. If you are building a web scraper, ensure you respect robots.txt and rate limits.

Related Errors

  • 401 Unauthorized — authentication required, not authorization.
  • 404 Not Found — resource does not exist.
  • 429 Too Many Requests — rate limit exceeded.
  • ERR_BLOCKED_BY_CLIENT — client-side block by browser extension.
