423 Locked

Last updated: March 8, 2026

The resource is locked and cannot be modified

You might see this error as:

  • HTTP 423
  • 423 Locked
  • 423 error
  • Resource locked
  • WebDAV locked

What Does This Error Mean?

A 423 Locked response indicates that the target resource is currently locked and the requested operation cannot be performed. This status code is defined in the WebDAV (Web Distributed Authoring and Versioning) extension to HTTP. Resources are locked to prevent concurrent modifications, similar to file locking in operating systems.

Common Causes

  • WebDAV resource lock — Another user or process has acquired an exclusive lock on the resource through WebDAV, preventing other clients from modifying it.
  • Stale lock not released — A previous lock was not properly released due to a client crash, network interruption, or programming error, leaving the resource in a permanently locked state.
  • Application-level resource locking — The application implements its own resource locking mechanism (beyond WebDAV) and returns 423 when a resource is being edited by another user.
  • Lock timeout not expired — A lock was placed on the resource with a timeout that has not yet expired. The resource will remain locked until the timeout passes or the lock is explicitly released.

How to Fix It

1. Wait for the lock to be released

If another user has the resource locked, wait for them to finish their modifications and release the lock. Most locks have a timeout after which they expire automatically.

2. Unlock the resource via WebDAV

If you have the lock token, send an UNLOCK request to release the lock on the resource.

# WebDAV UNLOCK request
curl -X UNLOCK -H 'Lock-Token: <opaquelocktoken:...>' https://example.com/resource

3. Contact the administrator to force unlock

If a stale lock cannot be released normally, a server administrator may need to manually remove the lock from the server's lock database.

Frequently Asked Questions

Is 423 only used with WebDAV?

It was defined for WebDAV but some APIs use it to indicate application-level resource locking. However, using 409 Conflict or 429 Too Many Requests may be more appropriate for non-WebDAV scenarios.

How long do WebDAV locks last?

Lock duration is set when the lock is created and can range from seconds to infinity. Most servers set a maximum lock timeout (often 10-30 minutes) after which the lock expires automatically.
