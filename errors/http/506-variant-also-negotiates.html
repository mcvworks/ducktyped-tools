506 Variant Also Negotiates

Last updated: March 8, 2026

The server has a circular reference in content negotiation

You might see this error as:

  • HTTP 506
  • 506 Variant Also Negotiates
  • 506 error
  • Content negotiation error

What Does This Error Mean?

A 506 Variant Also Negotiates response indicates that the server has an internal configuration error during transparent content negotiation. A chosen variant resource is configured to engage in content negotiation itself, creating a circular reference that the server cannot resolve. This is a rare error caused by misconfigured content negotiation on the server.

Common Causes

  • Circular content negotiation reference — A variant resource selected during content negotiation is itself configured to perform content negotiation, creating an infinite loop that the server detects and refuses.
  • Misconfigured type-map files — Apache type-map files or equivalent configuration point to variant resources that also have type-map configurations, creating a circular dependency.
  • Incorrect Alternates header configuration — The server's transparent content negotiation configuration includes variant URIs that reference themselves or each other in the Alternates header.

How to Fix It

1. Review content negotiation configuration

Check the server's content negotiation configuration for circular references. Ensure that variant resources do not themselves perform content negotiation.

2. Fix type-map files

If using Apache with type-map files, ensure variant URIs point to final resources and not to other type-map files or negotiated resources.

# Apache type-map file (correct)
URI: page

URI: page.en.html
Content-Type: text/html
Content-Language: en

URI: page.fr.html
Content-Type: text/html
Content-Language: fr

3. Use server-driven negotiation instead

If transparent content negotiation is causing issues, switch to server-driven negotiation where the server chooses the variant based on Accept headers without client-side negotiation.

Frequently Asked Questions

Is 506 a common error?

No. It is very rare because transparent content negotiation (RFC 2295) is rarely used. Most servers use server-driven content negotiation, which does not produce this error.

What is transparent content negotiation?

It is a mechanism where the server sends a list of available variants to the client, and the client chooses the best one. It is defined in RFC 2295 but is rarely implemented in practice.
