500 Internal Server Error

Last updated: March 8, 2026

A 500 error means the server crashed or encountered an unhandled exception while processing your request. The fault is always on the server side.

You might see this error as:

  • HTTP 500
  • 500 Internal Server Error
  • Error 500
  • 500 error
  • Internal server error
  • Server error 500
  • 500 error nginx
  • 500 error Apache
  • 500 error PHP
  • Something went wrong

What Does This Error Mean?

HTTP 500 is a generic server-side error indicating something went wrong internally that the server did not anticipate. The server could not complete the request because of an unexpected condition — a bug in the application code, a failed dependency, or a misconfiguration.

The 500 response intentionally hides the specific error message from the client to prevent leaking sensitive internal details. The actual cause is recorded in the server's error logs.

Common Causes

  • Unhandled exception — application code threw an error that was not caught.
  • PHP fatal error — syntax error, undefined function call, or memory limit exceeded.
  • Database connection failure — the app cannot connect to its database.
  • Corrupted .htaccess — invalid Apache configuration in a .htaccess file.
  • File permission error — the server process cannot read a required file or write to a required directory.
  • Memory exhaustion — the application exceeded PHP's memory_limit or the server's RAM.
  • Missing dependencies — a library, module, or configuration file the application needs is absent.
  • Infinite loop or timeout — server-side code running too long and hitting the max execution time.

How to Fix It

1. Check Server Error Logs

The specific error is almost always in the server logs:

  • Apache: /var/log/apache2/error.log or /var/log/httpd/error_log
  • nginx: /var/log/nginx/error.log
  • PHP: Check php.ini for the error_log path
  • Application: Check your app's logging configuration (Laravel, Django, Rails, etc.)

2. Enable Detailed Error Output (Development Only)

Temporarily enable detailed errors to see them in the browser. Never do this in production:

  • PHP: set display_errors = On in php.ini
  • Node.js: use a development error handler middleware

3. Check for Corrupted .htaccess

Rename your .htaccess file temporarily to test if it is the cause. An invalid directive in .htaccess causes a 500 error on every request in that directory.

4. Check Database Connectivity

Verify your database server is running, credentials are correct, and the connection limit has not been exceeded.

5. Increase PHP Memory Limit

If logs show "Allowed memory size exhausted," increase the limit in php.ini:

memory_limit = 256M

Frequently Asked Questions

Does a 500 error mean I was hacked?

Not typically. Most 500 errors are caused by bugs or misconfigurations. However, if you recently experienced unusual traffic or suspect a breach, check logs for suspicious requests alongside the errors.

Can a 500 error affect my SEO?

Temporary 500 errors are not a major SEO concern — search engines retry these pages. Persistent 500 errors on important pages can cause Googlebot to temporarily stop crawling them and may affect rankings.

Is there anything a visitor can do to fix a 500 error?

Usually no. Visitors can try reloading the page (it may have been a transient error) or waiting and trying again. But the fix must come from the server owner.

Related Errors

  • 502 Bad Gateway — invalid response from upstream server.
  • 503 Service Unavailable — server temporarily unavailable.
  • 504 Gateway Timeout — upstream server did not respond in time.
  • 501 Not Implemented — server does not support the requested method.
