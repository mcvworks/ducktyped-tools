308 Permanent Redirect

Last updated: March 8, 2026

The resource has permanently moved, preserving the request method

You might see this error as:

  • HTTP 308
  • 308 Permanent Redirect
  • 308 status code
  • 308 vs 301
  • Permanent redirect POST

What Does This Error Mean?

A 308 Permanent Redirect indicates that the resource has been permanently moved to a new URI and the client must not change the request method when following the redirect. It is the permanent counterpart to 307, just as 301 is the permanent counterpart to 302. This is primarily used for APIs where POST and PUT requests must retain their method after redirect.

Common Causes

  • Permanent API endpoint migration — An API endpoint has been permanently relocated and the server needs to ensure that all request methods (POST, PUT, DELETE) are preserved when clients follow the redirect.
  • Domain migration for API services — The service has moved to a new domain and uses 308 instead of 301 to guarantee that non-GET requests from API clients retain their original method.
  • URL restructuring with method safety — The URL scheme has been permanently changed and the server requires that POST form submissions and API calls are not downgraded to GET requests.

How to Fix It

1. Update client URLs to the new location

Since 308 indicates a permanent move, update all references to point to the new URL provided in the Location header. This eliminates the redirect overhead.

2. Verify client support for 308

Some older HTTP clients may not recognize 308. If you need to support legacy clients, consider using 301 for GET requests and 308 only for endpoints that accept other methods.

# Test if your client follows 308 correctly
curl -X POST -d 'test=data' -L -v https://example.com/old-api

3. Configure the redirect on your server

If you are setting up a permanent redirect for API endpoints, use 308 instead of 301 to prevent clients from changing the request method.

# Nginx
location /old-api/ {
    return 308 https://example.com/new-api$request_uri;
}

Frequently Asked Questions

When should I use 308 instead of 301?

Use 308 when you need to permanently redirect requests while ensuring the HTTP method is preserved. This is critical for API endpoints that accept POST, PUT, or DELETE. For simple page redirects, 301 is usually sufficient.

Do search engines understand 308?

Major search engines treat 308 similarly to 301 for SEO purposes, transferring link equity to the new URL. However, 301 is more widely used and tested for SEO contexts.
