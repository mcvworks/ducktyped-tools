418 I'm a Teapot

Last updated: March 8, 2026

The server refuses to brew coffee because it is a teapot

You might see this error as:

  • HTTP 418
  • 418 I'm a Teapot
  • 418 error
  • I'm a teapot
  • HTCPCP
  • RFC 2324
  • Teapot status code

What Does This Error Mean?

A 418 I'm a Teapot response is an April Fools' joke defined in RFC 2324 (Hyper Text Coffee Pot Control Protocol). It indicates that the server refuses to brew coffee because it is, permanently, a teapot. While not a real HTTP status code, it has been implemented by many servers and frameworks as an easter egg and is sometimes used to silently reject unwanted requests like bots or scrapers.

Common Causes

  • Easter egg response — The server has implemented the 418 status code as a joke or easter egg, often triggered by specific endpoints like /coffee or /brew.
  • Bot or scraper rejection — Some servers use 418 as a non-standard way to reject automated requests, bots, or scrapers without using a standard error code that might trigger retry logic.
  • Rate limiting or abuse prevention — The server is using 418 as an unconventional rate limiting response to indicate that the client should stop making requests.

How to Fix It

1. Check if the URL is correct

Verify you are not hitting a joke endpoint. Some servers have /coffee, /teapot, or similar paths that intentionally return 418.

2. Contact the server operator

If a legitimate API is returning 418, the server operator may be using it as a custom error code. Check the API documentation or contact support.

3. Review your request pattern

If you suspect the server is using 418 to block your requests, review your request rate and user-agent string. Ensure you are not being flagged as a bot.

Frequently Asked Questions

Is 418 a real HTTP status code?

It was defined as a joke in RFC 2324 (April 1, 1998) for the Hyper Text Coffee Pot Control Protocol. It is not part of the official HTTP specification but has been widely implemented as an easter egg.

Do real websites return 418?

Yes. Google returns 418 at google.com/teapot. Many frameworks include 418 support. Some servers use it humorously or as a non-standard rejection code for bots.

Should I use 418 in my API?

No. For production APIs, use standard HTTP status codes. Using 418 can confuse monitoring tools and clients. Use 403 or 429 for blocking or rate limiting instead.
