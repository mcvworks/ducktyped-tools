405 Method Not Allowed

Last updated: March 8, 2026

A 405 error means the HTTP method you used is known to the server but not permitted for the requested resource. Check the Allow response header to see what methods are accepted.

You might see this error as:

  • HTTP 405
  • 405 Method Not Allowed
  • 405 error
  • Method not allowed
  • 405 POST not allowed
  • 405 nginx

What Does This Error Mean?

HTTP 405 is returned when a server knows an HTTP method (GET, POST, PUT, DELETE, PATCH, etc.) but has explicitly not allowed it for the endpoint you requested. The server must include an Allow header listing the permitted methods.

For example: sending a DELETE /articles/123 to a read-only API that only supports GET and POST would return 405.

Common Causes

  • Submitting a form with the wrong method — HTML forms default to GET; some forms need POST.
  • Using the wrong HTTP verb in an API call — using POST when PUT is required, or vice versa.
  • Read-only endpoint — attempting to write to a GET-only resource.
  • Missing route handler — your application has a route defined for GET but not for POST on the same URL.
  • Firewall or WAF blocking the method — some WAFs block DELETE, PUT, or PATCH at the network layer.
  • Static file server — a static file server only supports GET and HEAD; sending POST returns 405.

How to Fix It

1. Check the Allow Header

The 405 response should include: Allow: GET, POST (or similar). Use one of the listed methods for your request.

2. Verify Your HTTP Method

Confirm you are using the correct method for the operation:

  • GET — retrieve data
  • POST — create a new resource
  • PUT — replace a resource entirely
  • PATCH — partially update a resource
  • DELETE — remove a resource

3. Add the Missing Route Handler (Server Owners)

If you control the API, add a handler for the required method:

# Express.js
app.put('/resource/:id', handler);   // add PUT handler
app.delete('/resource/:id', handler); // add DELETE handler

4. Check WAF Rules

If your application accepts these methods but still returns 405, check whether a WAF or security middleware is blocking the method at the proxy layer.

Frequently Asked Questions

405 vs. 403 — what's the difference?

403 Forbidden means the server refuses to serve the resource regardless of method. 405 is more specific — the resource exists and is accessible, but not via the method you used. You can try a different method for 405.

Related Errors

  • 501 Not Implemented — server doesn't support the method globally.
  • 403 Forbidden — access denied entirely.
  • 400 Bad Request — malformed request.
