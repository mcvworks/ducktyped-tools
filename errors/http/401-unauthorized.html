401 Unauthorized

Last updated: March 8, 2026

A 401 error means the server requires authentication and the request did not include valid credentials. You must log in or provide a valid token to access the resource.

You might see this error as:

  • HTTP 401
  • 401 Unauthorized
  • Error 401
  • 401 error
  • Authentication required
  • WWW-Authenticate
  • 401 vs 403
  • Unauthorized access

What Does This Error Mean?

HTTP 401 signals that the request lacks valid authentication credentials. Despite the name "Unauthorized," it is really an unauthenticated error — the server does not know who you are. When responding with 401, the server typically includes a WWW-Authenticate header indicating the authentication method required (e.g., Bearer, Basic).

Common Causes

  • Not logged in — accessing a protected resource without a session or token.
  • Session expired — your login session or JWT token has timed out.
  • Wrong credentials — incorrect username, password, or API key.
  • Expired API token — OAuth access tokens expire and need to be refreshed.
  • Missing Authorization header — API request sent without the required Authorization: Bearer <token> header.
  • Revoked credentials — API key or token has been revoked or rotated.
  • Incorrect authentication scheme — using Basic auth where Bearer is expected, or vice versa.

How to Fix It

For Web Users

1. Log In Again

Your session may have expired. Return to the login page and sign in with your credentials.

2. Clear Cookies and Cache

Corrupt session cookies can prevent authentication from working correctly. Clear cookies for the site and log in again.

3. Check for Password Changes

If a password was recently changed, all existing sessions are typically invalidated. Log in with the new credentials.

For Developers and API Consumers

4. Include the Authorization Header

For Bearer token authentication:

Authorization: Bearer your_access_token_here

For Basic authentication:

Authorization: Basic base64(username:password)

5. Refresh Expired Tokens

OAuth 2.0 access tokens expire. Implement token refresh logic using your refresh token before the access token expires.

6. Verify Your API Key

Confirm the API key is correct, has not been revoked, and has the required permissions for the endpoint.

Frequently Asked Questions

Why is it called "Unauthorized" if it is about authentication?

This is a historical naming quirk in the HTTP specification. The spec authors originally used "Unauthorized" to mean "unauthenticated" — you have not proven your identity. The term "authorization" is used loosely in HTTP 401 to mean "prove who you are." HTTP 403 is the true authorization error.

Can 401 be caused by a server misconfiguration?

Yes. A reverse proxy like nginx may be configured to require HTTP Basic auth for a route, and if credentials are not passed through, all requests return 401 — even for users who are authenticated at the application level.

Should APIs return 401 or 403 for expired tokens?

401 is the correct code for expired or missing tokens, since the authentication itself has failed. 403 should be returned when the token is valid but the user lacks permission to perform the action.

Related Errors

  • 403 Forbidden — authenticated but not authorized.
  • 429 Too Many Requests — rate limit exceeded for API calls.
  • 400 Bad Request — malformed request, possibly malformed auth header.
