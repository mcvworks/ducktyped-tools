424 Failed Dependency

Last updated: March 8, 2026

The request failed because it depended on another request that also failed

You might see this error as:

  • HTTP 424
  • 424 Failed Dependency
  • 424 error
  • Failed dependency
  • WebDAV dependency failed

What Does This Error Mean?

A 424 Failed Dependency response indicates that the request could not be performed because it depended on another operation that failed. This status code is defined in the WebDAV extension and typically occurs during batch operations where multiple related resources are being modified in a single request. If one operation in the batch fails, dependent operations return 424.

Common Causes

  • Dependent WebDAV operation failed — A batch WebDAV operation (like COPY or MOVE with depth) failed on one resource, causing dependent operations on related resources to fail with 424.
  • Transaction rollback — The server is processing multiple related operations as a transaction. When one operation fails, all dependent operations are rolled back and return 424.
  • Prerequisite resource operation failed — The request depends on a previous operation (like creating a parent directory before creating a file) that failed, causing this request to fail as well.

How to Fix It

1. Fix the root cause operation

Identify which operation in the batch originally failed (it will have a different status code, not 424) and resolve that issue first. The dependent operations should then succeed.

2. Retry the entire batch operation

If the original failure was transient (like a temporary lock conflict), retry the entire batch operation. Individual retries of 424 responses will fail again if the dependency is not met.

3. Break operations into smaller batches

Reduce the scope of batch operations to minimize cascading failures. Process resources individually or in smaller groups to isolate failures.

Frequently Asked Questions

Is 424 only used with WebDAV?

It was defined for WebDAV but some modern APIs use it to indicate cascading failures in batch or transactional operations. The concept of dependent request failure applies broadly.

How do I find the original error in a batch operation?

Look at the multi-status (207) response body for the operation that returned a status code other than 424. That is the root cause. All 424 responses are secondary failures.
