Python: No Module Named pip

Last updated: July 2, 2026

The failure 'ModuleNotFoundError: No module named pip' (or '/usr/bin/python3: No module named pip') — this interpreter has no pip installed at all.

You might see this error as:

  • No module named pip
  • ModuleNotFoundError: No module named pip
  • /usr/bin/python3: No module named pip
  • ensurepip

What Does This Error Mean?

pip is a package that lives inside a specific interpreter's environment — and some interpreters legitimately do not have it: Debian/Ubuntu split it into the separate python3-pip package, embedded/minimal Pythons omit it, and a venv created with --without-pip stays empty. The other flavor is mismatch rather than absence: pip exists in one interpreter while your command runs another. Running pip as 'python3 -m pip' pins it to the interpreter you name and dissolves half of these cases.

Common Causes

  • Debian/Ubuntu without python3-pip — The distro intentionally ships python3 without pip; it arrives via 'apt install python3-pip'.
  • A venv created without pip — python3 -m venv --without-pip, or venv creation that failed halfway (missing python3-venv produces exactly this).
  • Multiple interpreters, pip in the other one — pyenv/conda/system Pythons side by side — 'pip' on PATH belongs to one; 'python3' runs another.
  • Embedded or minimal distributions — The Windows embeddable zip, some IoT builds, and stripped containers exclude pip by design.

How to Fix It

1. Bootstrap pip with ensurepip

The standard library carries a pip installer for exactly this situation.

python3 -m ensurepip --upgrade
python3 -m pip --version

2. On Debian/Ubuntu, install the packages

python3-pip for pip, python3-venv so venvs come with pip included.

sudo apt update && sudo apt install -y python3-pip python3-venv
python3 -m pip --version

3. Recreate broken venvs

Faster and cleaner than repairing one.

rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
python -m pip --version

4. Always call pip through the interpreter

'python3 -m pip' guarantees pip and python agree; a bare 'pip' obeys PATH and can point anywhere.

python3 -m pip install requests
# which interpreter is this pip tied to?
pip --version    # prints the python path it belongs to

Frequently Asked Questions

Why doesn't Ubuntu ship pip with Python?

Debian policy separates the interpreter from the installer so the distro's own Python tooling stays under apt's control (the same philosophy that later became externally-managed-environment). One apt install adds pip; venvs you create then carry their own.

ensurepip says it is disabled — what now?

Debian/Ubuntu disable ensurepip in the system interpreter and direct you to apt ('ensurepip is disabled in Debian/Ubuntu for the system python'). Use 'apt install python3-pip', or work inside a venv where ensurepip runs normally.

pip works but installs packages my python cannot see — related?

Same root cause, opposite symptom: pip belongs to interpreter A, your script runs interpreter B. Compare 'pip --version' (shows its python) with 'which python3'. Then use 'python3 -m pip' — or activate the venv you actually meant.
