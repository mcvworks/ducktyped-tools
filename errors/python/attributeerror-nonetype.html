AttributeError: 'NoneType' Object Has No Attribute

Last updated: July 2, 2026

The most common Python traceback — a variable is None where code expected a real object, usually because some earlier call returned None.

You might see this error as:

  • AttributeError: 'NoneType' object has no attribute
  • nonetype object has no attribute
  • nonetype has no attribute get
  • python none attribute error

What Does This Error Mean?

Something evaluated to None, and the code then did none_thing.attribute. The traceback line shows where the None was USED — the bug is where it was PRODUCED, one or more steps earlier. Python is full of functions that return None on 'not found' rather than raising: dict.get, re.match without a hit, find() on XML, ORM .first(), functions with a missing return. The craft is tracing the None to its source and deciding there whether to raise, default, or branch.

Common Causes

  • A lookup that found nothing — dict.get(key), re.match(...), soup.find(...), queryset.first() — all return None on a miss, and the very next attribute access explodes.
  • A function missing a return — A code path (often an else or exception branch) that falls off the end returns None implicitly; callers get None only for certain inputs — the intermittent flavor.
  • In-place methods used as expressions — list.sort(), list.append(), random.shuffle() return None by design; 'data = data.sort()' assigns None and detonates later.
  • Optional values crossing layers unchecked — None from a config default, an API's null, or an unset field travels deep into code that assumed it could not be missing.

How to Fix It

1. Find the producer, not just the crash line

Work upward from the traceback: which expression produced the variable that is None? Print or debug one step earlier.

user = get_user(user_id)
print(repr(user))         # None? the bug is inside/into get_user
profile = user.profile    # <- crash line, not bug line

2. Guard at the boundary where None is meaningful

Handle the miss where it happens — raise a clear error or take the alternate path.

user = get_user(user_id)
if user is None:
    raise LookupError(f'no user with id {user_id!r}')
# or branch:
name = user.name if user else 'anonymous'

3. Fix the None-returning pattern itself

Watch the two classics: implicit returns and in-place methods.

# implicit None:
def pick(items):
    if items:
        return items[0]
    return None   # make it explicit — or raise

# in-place method:
data.sort()               # right
# data = data.sort()      # wrong: assigns None
ordered = sorted(data)    # expression form when you want a new list

4. Let type checkers catch it before runtime

Annotate optionals and run mypy/pyright — they flag attribute access on possibly-None values at edit time.

def get_user(user_id: int) -> "User | None": ...

# mypy error: Item "None" of "User | None" has no attribute "profile"
pip install mypy && mypy src/

Frequently Asked Questions

What is NoneType exactly?

The type of the single value None. The message "'NoneType' object has no attribute 'x'" is Python saying: this variable is None, and None has no attributes — a wrong-value error dressed as an attribute error.

Why is the traceback pointing at a line that looks correct?

Because that line only USED the None. The producer is earlier — sometimes another file entirely (config loading, an API client). repr()-print the operands of the crashing expression; whichever is None, trace where it was assigned.

Is there a safe-navigation operator like ?. in Python?

No — deliberately. The idiomatic forms are the conditional expression (x.y if x else default), try/except AttributeError for duck-typed cases, and getattr(x, 'y', default). Type annotations plus a checker give the compile-time version of the safety.
