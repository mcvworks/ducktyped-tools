Python error: externally-managed-environment

Last updated: September 24, 2026

pip is protecting a Python installation managed by your operating system or package manager. Choose a virtual environment for project libraries or pipx for command-line applications.

You might see this error as:

  • error: externally-managed-environment
  • externally managed environment pip
  • This environment is externally managed
  • pep 668
  • pip break-system-packages

What Does This Error Mean?

This error means the Python interpreter is marked EXTERNALLY-MANAGED and pip is running outside a virtual environment. The marker asks Python installers to leave that environment under its package manager’s control. It is not a permissions error, so adding sudo does not solve the underlying problem. See the externally managed environments specification.

Common Causes

  • The project is using the system Python — A bare pip or pip3 command can target a different interpreter from the one your project uses. Check the interpreter and the installation path first.
  • The virtual environment was never selected — An editor, new terminal, scheduled job, or container step may use the system interpreter even if a virtual environment exists.
  • A command-line application is being installed as a system library — A tool such as HTTPie usually fits pipx, which gives each application its own environment.
  • A distribution-based container uses a managed interpreter — A container does not automatically bypass this policy. Build the application’s environment explicitly.

How to Fix It

1. Check which Python and pip are running

Run these commands in the same terminal or container where the install fails. The executable path identifies Python; the pip output identifies its installation directory. For a venv, sys.prefix differs from sys.base_prefix. A shell prompt containing “.venv” alone is not proof.

python3 -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)"
python3 -m pip --version

2. Create a virtual environment for project dependencies

From your project directory, create a new .venv if you do not already have one. Use its Python directly so shell activation is optional. This Unix/macOS example installs requests; if the project supplies requirements.txt, use the last command instead. Configure your editor or job to use the same interpreter.

python3 -m venv .venv
.venv/bin/python -m pip --version
.venv/bin/python -m pip install requests

# For a project that has requirements.txt:
.venv/bin/python -m pip install -r requirements.txt

3. Install venv support if creation fails

If Debian or Ubuntu reports that ensurepip is unavailable, install venv support for the interpreter you selected. For the distribution’s default Python, use the command below, then retry creating the environment. A separately installed Python version may need its matching venv package. Other operating systems use their own Python packaging instructions.

sudo apt update
sudo apt install python3-venv
python3 -m venv .venv

4. Use pipx for a command-line application

Install pipx through your package manager: sudo apt install pipx on supported Debian/Ubuntu releases or brew install pipx on macOS. Run ensurepath and open a new terminal if the installed command is not found. pipx is for applications; install libraries your code imports into the project venv. See the pipx installation guide.

pipx ensurepath
pipx install httpie
http --version

5. Give Docker its own application environment

This example assumes requirements.txt and app.py exist in the build context. It copies dependencies before installing them and sets PATH for later build steps and the running container; activating a venv in one RUN step would not persist into the next. Pin application dependencies and choose a base image appropriate for your project.

FROM ubuntu:24.04
RUN apt-get update \
    && apt-get install -y --no-install-recommends python3-venv ca-certificates \
    && rm -rf /var/lib/apt/lists/*
RUN python3 -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
WORKDIR /app
COPY requirements.txt .
RUN python -m pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]

6. Use the system package manager for system packages

If the software is intended for the system interpreter, use its package manager and the package name it provides. On Debian/Ubuntu, for example, requests may be installed as sudo apt install python3-requests. Do not remove the EXTERNALLY-MANAGED marker to make pip ignore the policy. The --break-system-packages option explicitly permits pip to modify a managed installation; it does not isolate dependencies or resolve conflicts.

Frequently Asked Questions

Why does pip install --user still fail?

A user installation can still shadow libraries used by the managed interpreter. The externally managed policy also covers this case outside a virtual environment. Use a project venv for libraries or pipx for an application.

Do I have to activate the virtual environment?

No. Calling .venv/bin/python directly on Unix or macOS selects that environment. On Windows, use .venv\Scripts\python.exe. Activation is a convenience that changes which commands your shell finds.

Why do I still get the error after creating a venv?

Check the interpreter used by the failing command. A new shell, editor, sudo command, or container step may still select system Python. Run the venv’s Python with -m pip and configure the application to use that same interpreter.

Should I use --break-system-packages?

That option permits modifying an externally managed installation. It does not prevent package conflicts. For ordinary project work, a venv or pipx avoids changing the managed environment.
