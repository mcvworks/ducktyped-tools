Python IndentationError

Last updated: July 2, 2026

Crashes like 'IndentationError: unexpected indent', 'expected an indented block', and 'unindent does not match any outer indentation level' — whitespace that Python cannot parse as structure.

You might see this error as:

  • IndentationError: unexpected indent
  • IndentationError: expected an indented block
  • unindent does not match any outer indentation level
  • TabError: inconsistent use of tabs and spaces in indentation

What Does This Error Mean?

Python uses indentation as syntax, so inconsistent leading whitespace is a parse error, not a style issue. The three messages point at three shapes: 'unexpected indent' — a line is deeper than its context allows; 'expected an indented block' — a colon promised a body that is not there (or not indented); 'unindent does not match any outer indentation level' — a dedent lands between existing levels, the signature of mixed tabs and spaces. TabError is the explicit mixed-whitespace diagnosis. Copy-pasted code (from web pages, PDFs, chats) is the leading source.

Common Causes

  • Mixed tabs and spaces — Visually identical lines with different whitespace — an editor inserting tabs into a spaces file, or paste from a source that used the other convention.
  • Copy-paste artifacts — Web pages and PDFs smuggle non-breaking spaces (U+00A0) and other invisible characters into the indentation, which Python does not count as indent.
  • Empty block after a colon — A def/if/for line whose body was deleted or never written — Python requires at least a pass.
  • Merge/edit damage — Conflict resolution or bulk find-replace shifting some lines' indentation out of alignment with their block.

How to Fix It

1. Make the invisible visible

Turn on whitespace rendering in the editor, or inspect the raw bytes of the offending line.

cat -A file.py | sed -n '41,43p'    # tabs show as ^I, line ends as $
python3 -c "print(repr(open('file.py').readlines()[41]))"

2. Normalize the whole file to spaces

Convert tabs and reindent in one pass — PEP 8 says 4 spaces.

expand -t 4 file.py > fixed.py && mv fixed.py file.py
# or auto-format, which settles it permanently:
pip install black && black file.py

3. Fill empty blocks

Any promised body needs at least a placeholder.

def todo_later():
    pass   # or: raise NotImplementedError

if condition:
    ...    # Ellipsis works too

4. Set the editor so it cannot happen again

Spaces-only indentation, 4 wide, plus an .editorconfig so every contributor's editor agrees.

# .editorconfig
[*.py]
indent_style = space
indent_size = 4

Frequently Asked Questions

What is TabError specifically?

A subclass of IndentationError raised when a single block mixes tabs and spaces ambiguously ('inconsistent use of tabs and spaces in indentation'). Python 3 refuses to guess how wide a tab is. Normalize to spaces and it disappears.

The line looks perfectly aligned — why does Python disagree?

Alignment is visual; Python counts characters. A tab can render as the same width as 4 spaces while being a different indent level, and a non-breaking space looks identical to a space while not counting as indentation at all. repr() of the line settles every such argument.

Tabs or spaces — does Python care which I choose?

Either works if perfectly consistent, but PEP 8 and the entire tooling ecosystem (black, most formatters) standardize on 4 spaces. Choosing spaces plus an auto-formatter makes this whole error class extinct in a codebase.
