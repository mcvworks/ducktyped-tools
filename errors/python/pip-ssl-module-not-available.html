pip: TLS/SSL Module Not Available

Last updated: July 2, 2026

The failure 'pip is configured with locations that require TLS/SSL, however the ssl module in Python is not available' — this Python was built without OpenSSL support.

You might see this error as:

  • pip is configured with locations that require TLS/SSL, however the ssl module in Python is not available
  • No module named '_ssl'
  • pyenv ssl module missing
  • python ssl module not available

What Does This Error Mean?

Python's ssl module binds to OpenSSL at build time. If the OpenSSL development headers were missing when the interpreter was compiled — the classic pyenv-on-a-fresh-machine mistake — the resulting Python has no ssl module at all, and pip (which talks HTTPS to PyPI) cannot function. The fix is never inside pip: the interpreter itself must be rebuilt with the SSL libraries present, or you switch to an interpreter that has them.

Common Causes

  • pyenv/source build without OpenSSL headers — pyenv install compiles CPython; without libssl-dev (Debian) or openssl@3 (Homebrew) present, the build finishes but quietly skips the ssl module.
  • Minimal container images — Hand-rolled Python builds in slim images missing the ssl shared libraries, or copied interpreters whose linked OpenSSL is absent.
  • Broken conda/virtualenv linkage — Conda environments after certain updates, or venvs whose base interpreter moved, can lose the _ssl extension linkage.
  • Very old Python vs modern OpenSSL — Building an EOL Python (3.7-) against OpenSSL 3 fails or produces a crippled ssl module — old interpreters need old OpenSSL or patches.

How to Fix It

1. Confirm the diagnosis

Import ssl directly — the error message settles it.

python3 -c "import ssl; print(ssl.OPENSSL_VERSION)"
# ModuleNotFoundError: No module named '_ssl'  -> rebuild needed

2. Install the build dependencies, then rebuild

Get the headers first, then recompile the same version with pyenv.

# Debian/Ubuntu:
sudo apt install -y libssl-dev libbz2-dev libreadline-dev libsqlite3-dev \
  libffi-dev zlib1g-dev liblzma-dev
# macOS:
brew install openssl@3 readline sqlite3 xz zlib

pyenv uninstall 3.12.4
pyenv install 3.12.4
python3 -c 'import ssl; print(ssl.OPENSSL_VERSION)'

3. Point older builds at Homebrew's OpenSSL if needed

When the build does not find brew's keg-only OpenSSL automatically.

export LDFLAGS="-L$(brew --prefix openssl@3)/lib"
export CPPFLAGS="-I$(brew --prefix openssl@3)/include"
PYTHON_CONFIGURE_OPTS="--with-openssl=$(brew --prefix openssl@3)" pyenv install 3.12.4

4. Or use an interpreter that ships working SSL

Distro python3, python.org installers, and the official Docker images all come with ssl working — a valid alternative to compiling.

sudo apt install python3 python3-venv
# or in Docker:
FROM python:3.12-slim

Frequently Asked Questions

Why did the Python build succeed if a core module is missing?

CPython treats many extension modules as optional at build time: missing headers mean the module is skipped with only a summary warning in the build log ('The necessary bits to build these optional modules were not found: _ssl ...'). It bites later, when something imports ssl — usually pip, immediately.

Can I pip-install the ssl module instead of rebuilding?

No — ssl is part of the interpreter, compiled against OpenSSL during the build. Nothing on PyPI can add it afterwards (and pip cannot reach PyPI anyway without it). Rebuild with headers present, or switch interpreters.

Same error inside a conda environment — same fix?

Conda ships its own OpenSSL; the linkage occasionally breaks after partial updates. 'conda install openssl' (or recreating the environment) usually repairs it — no compiling involved, since conda distributes prebuilt interpreters.
