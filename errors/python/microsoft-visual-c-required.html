error: Microsoft Visual C++ 14.0 or Greater Is Required

Last updated: July 2, 2026

The pip build failure 'error: Microsoft Visual C++ 14.0 or greater is required. Get it with Microsoft C++ Build Tools' — a package needs compiling and Windows has no compiler.

You might see this error as:

  • error: Microsoft Visual C++ 14.0 or greater is required
  • Microsoft C++ Build Tools
  • building wheel failed windows
  • error: command cl.exe failed

What Does This Error Mean?

The package being installed contains C/C++ extensions, PyPI had no prebuilt wheel matching your exact Python version/architecture, so pip fell back to compiling from source — and Windows ships no compiler. You have two directions: avoid the compile (usually better — get a wheel by upgrading pip, choosing compatible versions, or a different package build) or enable it (install the Microsoft C++ Build Tools, several gigabytes). The avoid-first strategy resolves most cases in minutes.

Common Causes

  • No wheel for your Python version — Brand-new Python releases lag wheel coverage for a few weeks; running 3.13 the day it ships forces source builds of half the ecosystem.
  • Old pip that cannot see modern wheels — Older pip versions do not recognize newer wheel tags (manylinux/abi3 conventions) and skip perfectly good prebuilt wheels.
  • Package genuinely without Windows wheels — Some scientific and niche packages publish source-only releases, or dropped Windows binaries for certain versions.
  • 32-bit Python on a 64-bit machine — Accidentally installed x86 Python finds few wheels; everything tries to compile.

How to Fix It

1. Upgrade pip and retry first

The cheapest fix — newer pip finds wheels older pip cannot.

python -m pip install --upgrade pip setuptools wheel
python -m pip install package-name

2. Check wheel availability and pick versions that have them

The package's PyPI 'Download files' page lists wheels per Python version — pin to a version with a wheel for yours, or use the Python version the package supports.

pip install package-name==2.1.0   # last version with cp312 wheels, e.g.
pip debug --verbose | findstr cp    # your interpreter's wheel tags

3. Or install the compiler properly

The error's link is correct: 'Build Tools for Visual Studio' with the 'Desktop development with C++' workload — not the Visual Studio IDE itself.

winget install Microsoft.VisualStudio.2022.BuildTools
# in the installer select: Desktop development with C++
# then reopen the terminal and retry pip install

4. Consider conda for heavy scientific stacks

conda distributes everything prebuilt — on Windows it sidesteps this entire error class for numpy/scipy-adjacent ecosystems.

conda install package-name

Frequently Asked Questions

Why does pip suddenly want a compiler for a pure 'pip install'?

PyPI serves either prebuilt wheels or source distributions. When no wheel matches your Python/OS/architecture, pip compiles the source — which needs MSVC on Windows. The wheel lookup is the invisible step; everything about this error is really about why no wheel matched.

Which exact Microsoft download do I need?

'Build Tools for Visual Studio' (a standalone ~7GB toolchain), selecting the 'Desktop development with C++' workload. You do not need the Visual Studio IDE. '14.0 or greater' in the message covers every current version — 2022 Build Tools satisfy it.

Is this the Windows version of node-gyp errors?

Precisely — same story, different ecosystem: native extensions, missing toolchain, prebuilt binaries as the escape hatch. The strategies transfer both ways: prefer wheel/prebuild coverage, keep the package manager current, install the platform toolchain only when compilation is truly required.
