python: command not found

Last updated: July 2, 2026

Shell errors 'python: command not found' or Windows opening the Microsoft Store — the python command is missing from PATH, or only python3 exists.

You might see this error as:

  • python: command not found
  • 'python' is not recognized as an internal or external command
  • Python was not found; run without arguments to install from the Microsoft Store
  • zsh: command not found: python
  • bash: python: command not found

What Does This Error Mean?

Modern Linux distributions ship only a python3 command (the python name was retired with Python 2), macOS depends on developer tools or Homebrew, and Windows ships a fake 'python' App Execution Alias that opens the Microsoft Store when nothing real is installed. So this error means one of: Python is genuinely not installed, it is installed under a different name (python3, py), or it is installed but not on the PATH your shell searches.

Common Causes

  • Only python3 exists — Ubuntu, Debian, Fedora, and most modern Linux systems install python3 with no python alias. Scripts and tutorials written as 'python ...' fail out of the box.
  • Windows App Execution Alias hijack — Typing python on a fresh Windows box triggers a Store stub ('Python was not found; run without arguments to install from the Microsoft Store...') — the alias shadows real installs too, if installed later without PATH.
  • Installed, but not on PATH — Windows installer run without the 'Add python.exe to PATH' checkbox; pyenv shims not initialized in the shell profile; a venv not activated.
  • Genuinely not installed — Minimal containers, fresh macOS without developer tools, slim CI images.

How to Fix It

1. Try the names that actually exist

Diagnose in ten seconds — one of these usually answers.

python3 --version
py --version        # Windows launcher
which python3 || command -v python3
# Windows: where python

2. Linux: use python3, or install the alias package

Either adapt the habit or make 'python' mean python3 system-wide.

sudo apt install python3 python3-venv python3-pip
# optional 'python' alias on Debian/Ubuntu:
sudo apt install python-is-python3

3. Windows: disable the Store alias and fix PATH

Settings → Apps → Advanced app settings → App execution aliases → turn OFF both 'python' entries. Then install from python.org with 'Add python.exe to PATH' checked, or use the py launcher which needs no PATH edits.

py --version
py -3.12 script.py   # pick a specific installed version

4. macOS: install via Homebrew or the CLT

Homebrew gives current Python as python3.

brew install python
python3 --version
# make sure brew's bin is on PATH (Apple Silicon):
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile

Frequently Asked Questions

Why did 'python' stop existing on Linux?

During the Python 2→3 transition, 'python' meant Python 2 on most systems. When Python 2 was removed (EOL January 2020), distros dropped the name rather than silently changing what it pointed to. python3 is the stable, unambiguous name; python-is-python3 exists for compatibility.

pip is also 'not found' — same fix?

Same family: use pip3, or better, invoke it through the interpreter — 'python3 -m pip install ...' always matches pip to the python you ran, which avoids the classic multiple-Pythons confusion where pip installs into a different interpreter than the one running your code.

The command works in one terminal but not another — how?

Different PATH per shell: your profile (.bashrc/.zshrc) initializes pyenv or adds directories, and the other context (cron, IDE terminal, CI step) never runs that profile. Print PATH in both and diff; then initialize the tool in the profile the failing context actually loads, or use absolute paths.
