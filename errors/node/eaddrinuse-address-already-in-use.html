Node.js EADDRINUSE — Address Already in Use

Last updated: July 2, 2026

The crash 'Error: listen EADDRINUSE: address already in use :::3000' — another process (often a previous instance of the same app) already listens on the port.

You might see this error as:

  • Error: listen EADDRINUSE: address already in use :::3000
  • EADDRINUSE
  • listen eaddrinuse
  • port 3000 already in use node
  • address already in use node

What Does This Error Mean?

Your server called listen() on a port that already has a listener. Nine times out of ten, the squatter is a previous run of the same application: a dev server that never died when its terminal closed, a nodemon/pm2 child orphaned by a crashed parent, or a debugger-paused process still holding the socket. The rest are genuine conflicts — two apps configured for the same port, or a system service on it. The fix is always: identify the holder, then either kill it or move one of them.

Common Causes

  • A previous instance is still running — Closed the terminal without stopping the server, a crashed watcher left its child alive, or a background/debug session was forgotten. The old process keeps the port until it exits.
  • Watcher restart races — nodemon and similar restart the app before the old listener fully closed — intermittent EADDRINUSE on save, that heals on the next restart.
  • Two services configured for the same port — Your API and someone's create-react-app both defaulting to 3000, or a docker-compose stack publishing a port the host app also uses.
  • Missing graceful shutdown — Apps that never close their server on SIGTERM/SIGINT leave listeners around in process managers and container restarts.

How to Fix It

1. Find and kill the process on the port

One command names it; kill by PID rather than pkill node (which nukes every Node process, including your editor's tooling).

lsof -i :3000 -sTCP:LISTEN
kill <PID>          # graceful
kill -9 <PID>       # if it ignores SIGTERM
# Windows:
# netstat -ano | findstr :3000
# taskkill /PID <pid> /F

2. Make the port configurable and fail informatively

Read PORT from the environment and print a useful message on conflict.

const port = process.env.PORT || 3000;
const server = app.listen(port)
  .on('error', (err) => {
    if (err.code === 'EADDRINUSE') {
      console.error(`Port ${port} in use. lsof -i :${port} to find the holder.`);
      process.exit(1);
    }
    throw err;
  });

3. Add graceful shutdown

Close the server on termination signals so restarts and container stops release the port promptly.

function shutdown() {
  server.close(() => process.exit(0));
  setTimeout(() => process.exit(1), 10_000).unref(); // failsafe
}
process.on('SIGTERM', shutdown);
process.on('SIGINT', shutdown);

4. Tame watcher races

Give nodemon a signal and a small delay so the old process exits before the new one binds.

// nodemon.json
{
  "signal": "SIGTERM",
  "delay": "300"
}

Frequently Asked Questions

What does the ::: in 'address already in use :::3000' mean?

':::3000' is the IPv6 any-address ([::]) plus port. Node binds dual-stack by default, so the conflict may be with a process holding either the IPv6 or IPv4 side. lsof shows both.

Nothing shows on the port but bind still fails — how?

Check as root/admin (another user's process is invisible to plain lsof), and check both protocol families ('lsof -i :3000' covers them; 'ss -tlnp | grep 3000' as a second opinion). On Windows, excluded port ranges reserved by Hyper-V can also block binds — 'netsh int ipv4 show excludedportrange protocol=tcp'.

Is EADDRINUSE the same as EACCES on listen?

No: EADDRINUSE means someone has the port; EACCES means you lack permission — on Linux typically binding a port below 1024 as non-root. For the latter, use a high port behind a proxy, or grant the binary cap_net_bind_service.
