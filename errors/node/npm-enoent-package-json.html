npm ERR! ENOENT — Could Not Read package.json

Last updated: July 2, 2026

The failure 'npm ERR! code ENOENT ... Could not read package.json' — npm ran in a directory that has no package.json to read.

You might see this error as:

  • npm ERR! code ENOENT
  • Could not read package.json
  • npm ERR! enoent This is related to npm not being able to find a file
  • no such file or directory open package.json

What Does This Error Mean?

Almost every npm command starts by reading package.json from the current directory. ENOENT ('Error NO ENTry' — the POSIX code for a missing file) here means that file is not where npm ran. The bug is nearly always about location, not the file: a terminal sitting one directory too high, a CI step missing its working-directory setting, a Dockerfile whose WORKDIR does not match where files were copied, or a monorepo command aimed at the root when it needed a workspace (or vice versa).

Common Causes

  • Wrong current directory — Running npm from the repo root when the app lives in a subfolder (or from home after opening a fresh terminal).
  • The project was never initialized — Brand-new folder — 'npm install something' before 'npm init' has nothing to record the dependency in.
  • CI/Docker path mismatches — A pipeline step without working-directory, or a Dockerfile that COPYs into one path and runs npm in another.
  • Monorepo confusion — Commands meant for a workspace run at the root (or the reverse), or the workspaces config does not include the package's path.

How to Fix It

1. Look before you run

Two commands settle where you are and what is there.

pwd
ls package.json || find . -maxdepth 3 -name package.json -not -path '*/node_modules/*'
cd path/to/app && npm install

2. Initialize when starting fresh

Create the manifest first.

npm init -y
npm install express

3. Pin working directories in CI and Docker

Make the path explicit instead of inherited.

# GitHub Actions:
- run: npm ci
  working-directory: apps/web

# Dockerfile:
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .

4. Address workspaces explicitly

Run per-workspace commands from the root with the -w flag.

npm install lodash -w apps/web
npm run build -w packages/ui
npm run test --workspaces

Frequently Asked Questions

What does ENOENT mean in general?

It is the POSIX errno for 'no such file or directory', and npm surfaces it for any missing file — package.json here, but also missing scripts or paths inside packages. The path in the error message tells you exactly which file npm wanted.

npm WARN saying 'no such file or directory, open .../package.json' during install of a dependency — same thing?

Related but different: that is a broken or partially-installed dependency missing its own package.json inside node_modules. 'rm -rf node_modules && npm ci' rebuilds the tree cleanly.

Why do npm scripts work at the repo root in some projects without a root package.json?

They don't — projects where root-level npm commands work have a root package.json (often private, with workspaces). If your monorepo lacks one, either add it to define the workspaces, or run npm inside each package directory.

Related Errors

  • npm ELIFECYCLE — script failures once package.json is found.
  • Cannot Find Module — runtime resolution failures.
  • npm EPERM — permission errors during installs.
