JavaScript Heap Out of Memory

Last updated: July 2, 2026

The crash 'FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory' — the Node process hit V8's heap ceiling and aborted.

You might see this error as:

  • FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory
  • javascript heap out of memory
  • max-old-space-size
  • FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed
  • node out of memory build

What Does This Error Mean?

V8 caps its managed heap; when garbage collection can no longer free enough space under that cap, Node aborts with this fatal error. The cap depends on Node version and available RAM (commonly ~2-4GB by default). Three genuinely different situations produce it: a legitimate big workload (large builds, huge data transforms) that needs a higher ceiling; code that buffers something enormous into memory that should be streamed; and a leak, where memory grows without bound and any ceiling only delays the crash. Raising the limit is the right fix only for the first.

Common Causes

  • Big toolchain workloads — webpack/Next.js/Angular production builds, big TypeScript projects, and test suites routinely exceed default heap on large codebases — the classic CI failure.
  • Buffering instead of streaming — Reading multi-gigabyte files with readFile, building giant arrays/strings, or loading full query results at once — memory scales with input size until it cannot.
  • A memory leak — Caches without eviction, listeners added per-request and never removed, closures pinning large objects — heap grows steadily across hours regardless of load.
  • Container limits below the heap ceiling — In Docker/K8s, the kernel OOM-killer may kill the process before V8's limit is reached (exit code 137, no JS error) — the sibling failure worth distinguishing.

How to Fix It

1. Raise the heap ceiling for legitimate big jobs

NODE_OPTIONS reaches child processes too (build tools spawn workers), which plain CLI flags may miss.

NODE_OPTIONS=--max-old-space-size=4096 npm run build
# package.json variant:
"build": "cross-env NODE_OPTIONS=--max-old-space-size=4096 next build"

2. Stream what you currently buffer

Process large inputs incrementally so memory is bounded by chunk size, not file size.

const fs = require('fs');
const readline = require('readline');

const rl = readline.createInterface({
  input: fs.createReadStream('huge.ndjson'),
});
for await (const line of rl) {
  handle(JSON.parse(line));   // constant memory
}

3. Diagnose a leak before raising anything

Two heap snapshots some minutes apart, compared in Chrome DevTools, show what is accumulating and what retains it.

node --inspect server.js
# Chrome -> chrome://inspect -> take Heap Snapshot twice -> 'Comparison' view
# quick trend check without DevTools:
node -e 'setInterval(()=>console.log(process.memoryUsage().heapUsed/1e6|0,"MB"),5000)'

4. Align container memory with the heap limit

Give the container headroom above max-old-space-size (V8 uses memory outside the JS heap too — buffers, code, stacks).

# heap 4GB -> container ~5GB
docker run -m 5g -e NODE_OPTIONS=--max-old-space-size=4096 myapp

Frequently Asked Questions

What is the default heap limit?

It varies by Node version and system RAM — modern Node picks a fraction of available memory, commonly landing between 2GB and 4GB on typical machines. 'node -e "console.log(require('v8').getHeapStatistics().heap_size_limit/1e9)"' prints yours.

Will raising --max-old-space-size fix a leak?

No — it schedules the same crash later. If memory grows steadily under constant load, it is a leak: snapshot, find the growth, fix the retention. Raise the limit only when a bounded workload legitimately needs more than the default.

My container died with exit code 137 but no heap error — same problem?

That is the kernel OOM-killer, not V8: total process memory exceeded the container limit before the JS heap hit its own ceiling. Same investigation tools, but the fix balances container memory against max-old-space-size (container needs headroom above the heap).
