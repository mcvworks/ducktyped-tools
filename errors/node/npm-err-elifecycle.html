npm ERR! code ELIFECYCLE

Last updated: July 2, 2026

The npm failure 'npm ERR! code ELIFECYCLE, npm ERR! errno 1' — the package.json script npm ran exited with a non-zero code. npm is the messenger, not the culprit.

You might see this error as:

  • npm ERR! code ELIFECYCLE
  • npm ERR! errno 1
  • elifecycle npm
  • npm run build exit code 1
  • npm ERR! Exit status 1

What Does This Error Mean?

ELIFECYCLE means a lifecycle script — npm start, npm test, npm run build, or a postinstall hook — exited with a failure code, and npm is reporting that fact. The actual problem is printed by your script, above npm's ERR! wall. Treating the npm block as the error is the classic mistake; the debugging move is always to scroll up (or run the underlying command directly) and read what the tool inside the script said.

Common Causes

  • The script's own command failed — Tests failed, the bundler errored, the server crashed at boot — any non-zero exit from the command becomes ELIFECYCLE in npm's wrapper.
  • Environment differences in CI — Missing environment variables, devDependencies omitted by NODE_ENV=production installs, or a different Node version than local — the script fails only where the environment differs.
  • postinstall hooks failing — A dependency's postinstall (often node-gyp compiling, or a download step blocked by a proxy) fails, surfacing as ELIFECYCLE during npm install.
  • Port or resource conflicts at startup — npm start dying instantly with EADDRINUSE or a missing config file — the script never got going.

How to Fix It

1. Run the underlying command directly

Bypassing npm's wrapper gives you the tool's plain output and often a better exit message.

grep -A2 '"scripts"' package.json
# if "build": "webpack --mode production":
npx webpack --mode production

2. Read above the npm ERR! block

The real stack trace/compiler error is printed by the failing tool just before npm's summary. In CI logs, search upward from 'ELIFECYCLE' to the first non-npm error line.

3. Align the environment with local

Check the three usual suspects: Node version, env vars, devDependencies presence.

node --version            # match with "engines" / local
npm ci                     # NOT --omit=dev if the build needs devDeps
printenv | sort | head     # compare required vars against .env.example

4. For install-time failures, identify the hook

See which package's postinstall died, then fix its real requirement (usually a build toolchain).

npm install --foreground-scripts   # stream hook output live
npm install --ignore-scripts       # confirm the tree installs without hooks

Frequently Asked Questions

What does errno 1 actually mean?

Just 'the script exited with status 1' — the generic failure code. It carries no information about why; only the script's own output does. errno 137 is more specific: the process was killed (usually OOM), and 130 means interrupted by Ctrl-C.

Why does 'npm run build' fail in CI but work locally?

Environment drift: CI installs with production flags (missing devDependencies the build needs), runs a different Node major, or lacks env vars your local .env provides. Reproduce locally with 'rm -rf node_modules && NODE_ENV=production npm ci && npm run build' — it usually fails the same way.

Does clearing the npm cache fix ELIFECYCLE?

Almost never — cache corruption is rare and produces integrity errors, not lifecycle ones. Reserve 'npm cache clean --force' for when npm explicitly reports cache problems, and spend the time reading the script's real error instead.
