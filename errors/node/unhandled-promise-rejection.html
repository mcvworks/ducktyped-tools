Node.js Unhandled Promise Rejection

Last updated: July 2, 2026

The crash 'Error [ERR_UNHANDLED_REJECTION]: This error originated either by throwing inside of an async function without a catch block...' — a rejected promise had no handler, and Node 15+ exits.

You might see this error as:

  • UnhandledPromiseRejectionWarning
  • ERR_UNHANDLED_REJECTION
  • unhandled promise rejection
  • This error originated either by throwing inside of an async function

What Does This Error Mean?

Since Node 15, a promise rejection with no .catch() (and no rejection handler installed) crashes the process — previously it only printed a warning. The error means some async path in your code can fail without anyone listening: a floating promise called without await, an async function invoked from a callback, or a rejection thrown after the caller stopped waiting. The stack trace names the original rejection; the work is finding the call site that dropped the promise.

Common Causes

  • A promise called without await or .catch() — someAsyncFn(); as a statement — errors inside it have nowhere to go. Common in event handlers, timers, and 'fire and forget' calls that were not supposed to be.
  • async callbacks passed where none is expected — forEach(async ...), an async function as an EventEmitter listener, or setTimeout(async ...) — the caller ignores the returned promise, so rejections are orphaned.
  • Errors thrown outside the awaited window — A rejection that happens after the code that would catch it already resolved (e.g. multiple concurrent promises where only the first is awaited).
  • Upgrade from Node 14 or earlier — Code that 'worked' for years — with warnings nobody read — starts crashing on modern Node because the default became throw.

How to Fix It

1. Handle rejections at every call site

await inside try/catch for sequential code; explicit .catch for intentional fire-and-forget.

// sequential:
try {
  await sendEmail(user);
} catch (err) {
  log.error({ err }, 'email failed');
}

// intentional fire-and-forget:
sendAnalytics(event).catch(err => log.warn({ err }, 'analytics failed'));

2. Collect concurrent work safely

Promise.allSettled never rejects; use it when partial failure is acceptable, and Promise.all + try/catch when it is not.

const results = await Promise.allSettled(jobs.map(run));
for (const r of results) {
  if (r.status === 'rejected') log.error({ err: r.reason }, 'job failed');
}

3. Add a last-resort process handler — for logging, not for ignoring

Log rich context, then exit: after an unhandled rejection the process state is suspect, and supervisors restart it cleanly.

process.on('unhandledRejection', (reason) => {
  log.fatal({ err: reason }, 'unhandled rejection');
  process.exit(1);   // let systemd/pm2/k8s restart us
});

4. Prevent the class with lint rules

typescript-eslint's no-floating-promises flags every dropped promise at review time.

// .eslintrc
{
  "rules": {
    "@typescript-eslint/no-floating-promises": "error",
    "@typescript-eslint/no-misused-promises": "error"
  }
}

Frequently Asked Questions

Why did Node start crashing instead of warning?

Silently swallowed rejections hid real failures — half-completed writes, lost jobs — and the warning was ignored in practice. Crashing makes the bug undeniable and lets a supervisor restart from a clean state. You can revert with --unhandled-rejections=warn, but that re-hides the bugs.

unhandledRejection vs uncaughtException — what is the difference?

unhandledRejection fires for promise rejections nobody handled; uncaughtException for synchronous throws that escaped everything. Both mean the app lost control of an error path; both handlers should log and exit rather than attempt to continue.

Is exiting on every unhandled rejection too harsh for a web server?

The alternative is running with unknown corrupted state. The robust pattern is: per-request error handling catches expected failures (so they never reach the process handler), and the process handler is strictly for bugs — where restart-on-crash plus a fix is safer than limping on.
