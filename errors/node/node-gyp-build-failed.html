node-gyp Build Failed

Last updated: July 2, 2026

Install failures full of 'gyp ERR! build error' and 'gyp ERR! stack' — a package with native C/C++ code could not compile on your machine.

You might see this error as:

  • gyp ERR! build error
  • gyp ERR! stack Error
  • node-gyp rebuild failed
  • gyp ERR! find Python
  • node-pre-gyp install failed
  • NODE_MODULE_VERSION mismatch

What Does This Error Mean?

Some npm packages (bcrypt, sqlite3, canvas, sharp's fallbacks, serialport...) contain native addons that must be compiled during install when no prebuilt binary matches your OS/architecture/Node version. node-gyp orchestrates that compile and needs a working toolchain: a C/C++ compiler, Python, and the Node headers. gyp ERR! means some part of that chain failed — the useful line is never the gyp ERR! stack itself but the compiler or configure error a screen above it.

Common Causes

  • No compiler toolchain installed — Fresh machines and slim Docker images lack make/gcc/clang. Linux needs build-essential (or equivalents), macOS the Xcode Command Line Tools, Windows the Visual Studio Build Tools.
  • Python problems — node-gyp drives the build with Python 3. Missing Python — or Python 3.12+ with an old node-gyp that still imports the removed distutils module — kills the configure step.
  • No prebuilt binary for your platform/Node combo — Packages usually ship prebuilds for common combos; a brand-new Node major, Alpine (musl), or ARM can miss the matrix and force a source build that then needs the toolchain.
  • Version skew after Node upgrades — node_modules compiled against an older Node ABI, then the runtime changed — errors like NODE_MODULE_VERSION mismatch call for a rebuild rather than a toolchain fix.

How to Fix It

1. Install the toolchain for your OS

The one-time fix for most machines.

# Debian/Ubuntu:
sudo apt install -y build-essential python3
# Alpine (Dockerfiles):
apk add --no-cache python3 make g++
# macOS:
xcode-select --install
# Windows (admin PowerShell):
# install 'Visual Studio Build Tools' with the C++ workload

2. Fix Python/node-gyp pairing

Update node-gyp (bundled with npm) and, on Python 3.12+, ensure setuptools is present for older chains.

python3 --version
npm install -g node-gyp@latest
# if an old chain complains about distutils on Python 3.12+:
python3 -m pip install setuptools

3. Rebuild after Node version changes

For NODE_MODULE_VERSION mismatches, recompile the tree against the current runtime.

npm rebuild
# or the reliable big hammer:
rm -rf node_modules && npm ci

4. Prefer packages with prebuilds where possible

Swapping bcrypt for bcryptjs (pure JS), or better-sqlite3/sharp (excellent prebuild coverage) for older equivalents, removes the compile requirement entirely — valuable in CI and slim containers.

Frequently Asked Questions

Where is the actual error in the wall of gyp output?

Scroll above the 'gyp ERR!' block: the real failure is the compiler line (missing header 'xyz.h', 'g++: not found') or the configure line ('Could not find any Python installation'). The gyp ERR! stack is just the messenger.

Why does it work on my machine but fail in Docker?

Your machine has prebuilt binaries cached or a full toolchain; the slim/alpine image has neither. Add the toolchain packages to the build stage, or use a multi-stage Dockerfile that installs deps in a builder image and copies node_modules to the runtime image (matching libc!).

What is NODE_MODULE_VERSION and why did it mismatch?

It is Node's native ABI number, bumped each major release. A compiled addon carries the number it was built against; running it on a different Node major fails the check. 'npm rebuild' (or a clean install) recompiles against the runtime you actually use.
