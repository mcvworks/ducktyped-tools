Temporary failure in name resolution

Last updated: July 1, 2026

A Linux system error meaning the resolver could not translate a hostname into an IP address — usually because no DNS server is configured or reachable.

You might see this error as:

  • Temporary failure in name resolution
  • ping: temporary failure in name resolution
  • socket.gaierror: [Errno -3]
  • EAI_AGAIN linux
  • apt temporary failure resolving
  • Temporary failure in name resolution WSL

What Does This Error Mean?

This message comes from the C library resolver (getaddrinfo) on Linux when a hostname lookup fails at the system level. You will see it from ping, apt, curl, and Python (socket.gaierror: [Errno -3]). Unlike NXDOMAIN — where a DNS server answered 'this name does not exist' — this error usually means the system never got a usable answer at all: there is no nameserver configured, the configured nameserver is unreachable, or the local resolver daemon is down.

Common Causes

  • Empty or missing /etc/resolv.conf — The resolver reads nameserver addresses from /etc/resolv.conf. If the file is empty, missing, or contains no valid 'nameserver' line, every lookup fails immediately.
  • systemd-resolved is stopped or broken — On most modern distributions /etc/resolv.conf is a symlink to a stub file managed by systemd-resolved (127.0.0.53). If the service is stopped or crashed, the stub answers nothing and all name resolution fails.
  • No network connectivity — If the machine has no route to the network (interface down, DHCP failed, VPN dropped), the configured DNS server is unreachable even though the configuration is correct.
  • WSL2 regenerated or broke resolv.conf — WSL2 auto-generates /etc/resolv.conf pointing at the Windows host. VPN clients and some corporate setups break this bridge, leaving Linux-side lookups failing while Windows resolves fine.

How to Fix It

1. Check that resolv.conf contains a nameserver

Inspect the file first — most cases are visible immediately. If there is no nameserver line, add a public resolver as a quick test.

cat /etc/resolv.conf
# quick test entry:
echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf
ping -c1 example.com

2. Restart systemd-resolved

If resolv.conf points at 127.0.0.53, the stub resolver must be running. Restart it and check its status and upstream servers.

sudo systemctl restart systemd-resolved
resolvectl status
resolvectl query example.com

3. Verify basic connectivity to the DNS server

Confirm the machine can actually reach the configured resolver. If ping to the resolver IP fails, the problem is the network path, not DNS itself.

ip route show
ping -c2 1.1.1.1
dig @1.1.1.1 example.com

4. Fix WSL2 DNS permanently

In WSL2, disable auto-generation and set your own nameserver so VPN software cannot break it on every restart.

# /etc/wsl.conf
[network]
generateResolvConf = false

# then recreate /etc/resolv.conf:
sudo rm /etc/resolv.conf
echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf
# restart WSL from Windows: wsl --shutdown

Frequently Asked Questions

What does Python's socket.gaierror: [Errno -3] mean?

Errno -3 (EAI_AGAIN) is the same underlying failure: getaddrinfo could not resolve the hostname because no DNS server answered. Fix the system resolver configuration; the Python code itself is usually fine.

How is this different from 'Name or service not known'?

'Name or service not known' (EAI_NONAME) means a DNS server answered and said the name does not exist — like NXDOMAIN. 'Temporary failure in name resolution' (EAI_AGAIN) means no usable answer arrived at all, pointing to resolver or connectivity problems rather than a wrong hostname.

Why does this happen after every reboot?

Something is rewriting /etc/resolv.conf at boot — typically NetworkManager, dhclient, or WSL2's auto-generation. Fix the source (NetworkManager DNS settings, or wsl.conf) instead of editing resolv.conf by hand each time.

Related Errors

  • DNS Server Not Responding — the configured DNS server is unreachable.
  • No servers could be reached — dig/nslookup cannot contact any resolver.
  • Could not resolve host — the same failure as reported by curl and git.
