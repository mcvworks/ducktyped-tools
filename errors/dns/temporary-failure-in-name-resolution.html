Temporary failure in name resolution

Last updated: September 23, 2026

A temporary hostname lookup failure on Linux. Check the affected application, network, resolver, VPN, WSL, or container before changing DNS settings.

You might see this error as:

  • Temporary failure in name resolution
  • ping: temporary failure in name resolution
  • socket.gaierror: [Errno -3]
  • EAI_AGAIN linux
  • apt temporary failure resolving
  • Temporary failure in name resolution WSL

What Does This Error Mean?

Linux applications can report this message when getaddrinfo returns EAI_AGAIN, a temporary name-resolution failure. It can reflect a timeout or a temporary failure reported by a DNS server; it does not prove that no server replied or that the domain is missing. Python may expose it as socket.gaierror, and package managers may report a temporary failure resolving a repository host. See the getaddrinfo error definitions.

Common Causes

  • The configured resolver cannot complete the lookup — A DNS timeout, temporary upstream failure, or unavailable local resolver can interrupt resolution even when other parts of the network still work.
  • The network or VPN changed — DHCP, a disconnected VPN, or an incorrect route can leave the machine using an unreachable resolver. Private names may require the DNS servers supplied by the VPN.
  • Resolver configuration is inconsistent — A stale symlink, incorrect upstream address, or failed service can break the lookup path. First identify whether NetworkManager, systemd-resolved, WSL, or another component manages it.
  • The failure is inside a different runtime — A container or WSL distribution can have different resolver settings from the host. Test from the environment where the application actually fails.

How to Fix It

1. Check whether one hostname or every hostname fails

Run these on the affected Linux system, then replace example.com with the hostname from your error. If public names work but one name fails, investigate that name and its DNS zone. If everything fails, continue with the network and resolver checks. A missing getent utility is not itself a DNS failure.

getent ahosts example.com
getent ahosts example.org
ip route show

2. Inspect the resolver configuration before editing it

Check whether the file is a symlink and which nameservers it lists. A loopback nameserver can be a legitimate local resolver. Make lasting corrections in the component that owns the configuration, such as NetworkManager, DHCP, or your VPN. Blindly replacing the file can lose private DNS settings and will often be overwritten later.

ls -l /etc/resolv.conf
cat /etc/resolv.conf

3. Check systemd-resolved if this system uses it

Use status and a query to inspect the service and its upstream configuration. If the service is not installed or this system uses a different resolver, skip this step. Restart only a failed service that is part of your configured lookup path; a restart cannot repair an unreachable upstream DNS server. The resolvectl manual explains the query and status commands.

systemctl status systemd-resolved --no-pager
resolvectl status
resolvectl query example.com

# Only if this configured service has failed:
sudo systemctl restart systemd-resolved

4. Compare a DNS query through the current and another resolver

If dig is available and your network permits public DNS queries, compare these results for a public name. If only the second succeeds, investigate your configured resolver or the path to it. If both fail, inspect routing, firewall, and DNS policy. A failed ping is inconclusive because ICMP may be blocked. Keep private hostnames on the organization’s resolver.

dig example.com
dig @1.1.1.1 example.com

5. For WSL, check Windows resolution and DNS tunneling

Compare the same hostname in Windows and WSL. Modern supported WSL setups offer DNS tunneling to improve VPN compatibility; check its configuration before applying older workarounds that replace resolv.conf. Microsoft notes that generateResolvConf must not be disabled for tunneling to work. Follow the WSL DNS troubleshooting guidance. After an intentional WSL configuration change, save your work before running wsl --shutdown in Windows: it stops running WSL sessions.

6. Reproduce the failure inside the application or container

If the host resolves correctly, repeat the test inside the failing container. Replace my-app with its name; minimal images may not include getent. Check the container network and resolver before changing the host’s DNS. Docker has its own DNS behavior. For intermittent application errors, use bounded retries and record the affected hostname and time; avoid an endless retry loop.

docker exec my-app cat /etc/resolv.conf
docker exec my-app getent ahosts example.com

Frequently Asked Questions

What does Python’s socket.gaierror: [Errno -3] mean?

On common Linux systems it corresponds to EAI_AGAIN, a temporary failure in the hostname lookup. Test from the same machine or container as Python. It does not by itself identify a typo, a broken DNS server, or a problem in the Python code.

Is EAI_AGAIN the same as a nonexistent domain?

No. EAI_AGAIN indicates a temporary lookup failure. EAI_NONAME means a name or service was not known, and can arise for reasons beyond an NXDOMAIN response. Inspect the actual hostname and resolver response instead of treating those errors as interchangeable.

Does a failed ping prove that DNS or the network is down?

No. ICMP traffic may be blocked while DNS and HTTPS still work. Use a hostname lookup or a DNS query to test resolution, and inspect the route and resolver configuration separately.

Why does an online DNS tool work while my application fails?

An online tool queries from another server and network. Its success does not verify your local resolver, VPN, container DNS, or private hostname access. Reproduce the lookup where your application runs.

Related Errors

  • DNS Server Not Responding — the configured DNS server is unreachable.
  • No servers could be reached — dig/nslookup cannot contact any resolver.
  • Could not resolve host — the same failure as reported by curl and git.
