DNS NOTIMP

Last updated: July 1, 2026

DNS response code 4 (Not Implemented) — the server understood the query but does not support the requested operation or query type.

You might see this error as:

  • NOTIMP
  • RCODE 4
  • Not Implemented DNS
  • DNS NOTIMP
  • query type not implemented
  • dig ANY NOTIMP

What Does This Error Mean?

NOTIMP (RCODE 4) is the DNS server saying 'I do not support that kind of request'. Unlike SERVFAIL (something broke) or REFUSED (policy says no), NOTIMP is about capability. In modern networks it most often appears for ANY queries — which RFC 8482 explicitly allows servers to decline — or when a firewall, load balancer, or ancient DNS implementation sits in the path and does not implement the query type, opcode, or EDNS options the client used.

Common Causes

  • ANY queries are deprecated — Since RFC 8482, large providers (Cloudflare was first) intentionally answer ANY queries with NOTIMP or a minimal HINFO record, because ANY was heavily abused for DDoS amplification.
  • A middlebox is intercepting DNS — Firewalls and 'DNS inspection' features sometimes implement only plain A/AAAA lookups. Queries for newer types (HTTPS/SVCB, CAA) or with EDNS options get NOTIMP from the middlebox, not the real server.
  • Outdated DNS server software — Very old BIND versions, consumer router resolvers, and minimal embedded DNS implementations return NOTIMP for record types or opcodes added after they were written.
  • Dynamic updates sent to a server that does not accept them — An UPDATE opcode (RFC 2136) sent to a server with updates disabled — or to a resolver instead of an authoritative server — can be answered with NOTIMP.

How to Fix It

1. Query specific record types instead of ANY

Ask for exactly what you need — ANY was never guaranteed to return everything anyway (it only reflects what a resolver happens to have cached).

dig example.com A
dig example.com AAAA
dig example.com MX
dig example.com TXT

2. Identify who is actually answering

Compare answers from your configured resolver and a public one. If the public resolver supports the query but your path returns NOTIMP, a middlebox or local resolver is the culprit.

dig example.com HTTPS            # via configured resolver
dig @1.1.1.1 example.com HTTPS   # direct to public resolver

3. Update or bypass the limited DNS implementation

Upgrade old DNS software, or point clients at a modern resolver. For firewalls, disable DNS inspection/ALG features that rewrite queries they do not understand.

Frequently Asked Questions

What is the difference between NOTIMP and REFUSED?

NOTIMP means the server cannot process that type of request at all (missing capability). REFUSED means it could, but policy forbids it — for example recursion requested by an unauthorized client. Capability vs policy.

Why does 'dig ANY' return almost nothing these days?

ANY responses were huge and made perfect DDoS amplification payloads. RFC 8482 lets servers answer ANY with a synthetic minimal response or NOTIMP, and all major providers do. Query individual record types instead.

Is NOTIMP ever the client's fault?

Rarely — only if the client sends a genuinely exotic opcode or a malformed extension. In practice, treat NOTIMP as a signal about the server (or middlebox) capability, and route the query to a more capable resolver.

Related Errors

  • DNS REFUSED — policy-based rejection.
  • DNS FORMERR — the server could not parse the query.
  • DNS SERVFAIL — internal server failure.
