DNS_PROBE_FINISHED_BAD_SECURE_CONFIG

Last updated: March 8, 2026

DNSSEC validation failure prevented DNS resolution

You might see this error as:

  • DNS_PROBE_FINISHED_BAD_SECURE_CONFIG
  • DNS bad secure config
  • Secure DNS configuration error

What Does This Error Mean?

DNS_PROBE_FINISHED_BAD_SECURE_CONFIG occurs when the browser's DNS resolver cannot validate DNSSEC signatures for the requested domain. DNSSEC adds cryptographic signatures to DNS records so resolvers can verify that responses have not been tampered with. When the signature chain is broken, expired, or misconfigured, the resolver rejects the response and the browser displays this error.

Common Causes

  • Expired DNSSEC signatures — The RRSIG records for the domain have passed their expiration date. DNSSEC signatures have a validity period, and if the zone is not re-signed before expiration, all validating resolvers will reject the records.
  • Incorrect DS record at the registrar — The Delegation Signer (DS) record published in the parent zone does not match the DNSKEY in the child zone. This breaks the chain of trust from the root zone down to the domain.
  • Zone re-signed with a new key without updating DS — The domain operator generated new DNSSEC keys and re-signed the zone but did not update the DS record at the registrar, causing a mismatch in the trust chain.
  • Clock skew on the client system — DNSSEC validation checks signature timestamps. If the client system clock is significantly wrong, valid signatures may appear expired or not yet valid, causing validation failures.
  • DNS resolver does not support DNSSEC properly — Some network-provided DNS resolvers partially support DNSSEC but handle edge cases incorrectly, returning SERVFAIL for zones with valid but complex DNSSEC configurations.

How to Fix It

1. Switch to a DNSSEC-aware public resolver

Configure your system to use Google Public DNS or Cloudflare DNS, which have robust DNSSEC validation. This rules out resolver-specific bugs.

# Set DNS servers
# Google: 8.8.8.8, 8.8.4.4
# Cloudflare: 1.1.1.1, 1.0.0.1

2. Verify your system clock

Ensure your computer's date and time are correct. DNSSEC signatures include validity windows, and an incorrect clock will cause legitimate signatures to fail validation.

3. Contact the domain administrator

If you manage the domain, check that the DS record at your registrar matches your current DNSKEY. Use a DNSSEC debugger like dnsviz.net to trace the chain of trust and identify the break.

4. Flush DNS cache and retry

Stale cached DNSSEC records can cause validation failures after a zone is re-signed. Flush the system DNS cache and retry.

# Windows
ipconfig /flushdns

# macOS
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder

# Linux
sudo systemd-resolve --flush-caches

Frequently Asked Questions

What is DNSSEC and why does it cause errors?

DNSSEC is a security extension for DNS that uses cryptographic signatures to verify that DNS responses are authentic and unmodified. When signatures are misconfigured or expired, validating resolvers refuse to return the DNS records, which prevents the browser from resolving the domain.

Can I disable DNSSEC validation to bypass this error?

Switching to a non-validating DNS resolver would bypass the error, but this removes the security benefit of DNSSEC. It is better to fix the underlying DNSSEC configuration or contact the domain administrator.

Is this error on my end or the website's end?

In most cases this is a server-side DNSSEC misconfiguration. However, if your system clock is wrong or your local DNS resolver has bugs, the issue can be on your end. Try a different DNS resolver to narrow it down.
