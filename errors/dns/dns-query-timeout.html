DNS Query Timeout

Last updated: March 8, 2026

DNS query timed out before receiving a response

You might see this error as:

  • DNS query timeout
  • DNS request timed out
  • DNS server not responding timeout

What Does This Error Mean?

A DNS query timeout occurs when the DNS resolver sends a query to a DNS server but does not receive a response within the configured timeout period. The resolver typically retries with different servers or after a delay, but if all attempts time out, DNS resolution fails completely. This is different from SERVFAIL, where the server responds with an error — a timeout means no response was received at all.

Common Causes

  • DNS server is offline — The DNS server configured on the system is not running or has crashed. Queries sent to it receive no response because there is no process listening on port 53.
  • Network path to DNS server is blocked — A firewall, router ACL, or network security appliance is dropping DNS packets (UDP/TCP port 53) between the client and the DNS server, preventing queries from reaching the server.
  • UDP packet loss on the network — DNS primarily uses UDP, which has no built-in reliability. High packet loss on the network path can cause DNS queries or responses to be dropped silently.
  • DNS server overloaded — The DNS server is under heavy load, such as during a DDoS attack or a traffic spike, and cannot process queries fast enough, causing them to queue and eventually time out.
  • Incorrect DNS server address configured — The system is configured with a DNS server IP address that does not host a DNS service, so queries are sent to a host that has no DNS server running.

How to Fix It

1. Verify DNS server reachability

Check whether the DNS server is reachable and responding to queries.

# Test DNS server with nslookup
nslookup google.com 8.8.8.8

# Test with dig and explicit timeout
dig @8.8.8.8 google.com +timeout=5

# Check if port 53 is reachable
nc -zvu 8.8.8.8 53

2. Switch to a reliable public DNS server

If your current DNS server is unreliable, switch to a well-maintained public DNS service with global anycast infrastructure.

# Google DNS: 8.8.8.8 / 8.8.4.4
# Cloudflare DNS: 1.1.1.1 / 1.0.0.1
# Quad9: 9.9.9.9 / 149.112.112.112

3. Check for packet loss on the network

Run a packet loss test to the DNS server to determine if network issues are causing query drops.

# Test packet loss to DNS server
ping -c 100 8.8.8.8

# Windows
ping -n 100 8.8.8.8

4. Check firewall and security software

Review firewall rules to ensure DNS traffic (UDP and TCP on port 53) is allowed outbound. Security software sometimes blocks DNS traffic, especially after updates or policy changes.

Frequently Asked Questions

How long does a DNS query wait before timing out?

Default timeout varies by resolver. Most operating system resolvers wait 5 seconds per attempt and retry 2-3 times, for a total of 10-15 seconds. Browsers may have shorter internal timeouts.

Why do DNS queries use UDP instead of TCP?

DNS uses UDP for most queries because it is faster — there is no connection setup overhead. However, DNS falls back to TCP for responses larger than 512 bytes (or the EDNS0 buffer size) and for zone transfers. If UDP is blocked, DNS-over-TCP on port 53 may still work.

Can DNS query timeouts be caused by DNS-over-HTTPS or DNS-over-TLS issues?

Yes. If your system or browser is configured to use DoH or DoT and the encrypted DNS server is unreachable or has certificate issues, queries will time out. Check whether encrypted DNS is configured and try disabling it temporarily to test.
