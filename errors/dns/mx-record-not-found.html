MX Record Not Found

Last updated: July 3, 2026

This error means a sending mail server looked up a domain's MX (Mail Exchanger) records to find out where to deliver email — and found none. Without an MX record telling senders which host accepts mail, delivery fails and the message bounces. Note that the website can work perfectly while this happens: web traffic and email use different DNS records.

You might see this error as:

  • no MX record found for domain
  • Host or domain name not found. Name service error for name=example.com type=MX
  • queryMx ENODATA example.com
  • Recipient address rejected: Domain not found
  • 550 5.1.2 ... unable to route to recipient domain
  • DNS type 'MX' lookup responded with no data

What Does This Error Mean?

When a mail server has a message for user@example.com, it asks DNS for the MX records of example.com. Each MX record names a mail host and a priority; the sender tries the lowest-priority number first. If DNS returns no MX records, the sender has nowhere to deliver the message.

There is one nuance. RFC 5321 defines an implicit MX rule: if a domain has no MX record but does have an A or AAAA record, a sender may deliver to that address instead. In practice many providers do not honor this, so a missing MX record almost always results in a bounce. The reliable answer is to publish an explicit MX record.

Common Causes

  • No MX record was ever configured — the domain has web DNS set up but no mail records.
  • The MX target has no A/AAAA record — the MX record exists but points to a hostname that does not resolve, which fails the same way.
  • MX points to a CNAME — an MX record must reference a hostname with an address record, not a CNAME; this is invalid and breaks delivery.
  • DNS not yet propagated — a newly added MX record has not reached all resolvers.
  • Typo or wrong domain — mail sent to a mistyped or expired domain, which returns NXDOMAIN rather than an MX answer.
  • A CNAME at the domain apex — putting a CNAME on the root domain suppresses other records, including MX.

How to Fix It

1. Check the Current MX Records

First confirm what DNS actually returns. Query from several resolvers with the DNS Lookup tool, or from a terminal:

dig MX example.com +short
# or
nslookup -type=mx example.com

If this returns nothing, no MX record is published and you need to add one.

2. Add an MX Record at Your DNS Host

In your DNS provider's dashboard, add an MX record pointing to your mail host with a priority. A zone-file view of a self-hosted setup looks like this:

; name          TTL   class type priority  target
example.com.     3600  IN    MX   10        mail.example.com.
mail.example.com. 3600 IN    A              203.0.113.10

If you use a hosted email provider, enter their exact values instead — for example, Google Workspace uses a single MX host:

example.com.     3600  IN    MX   1         ASPMX.L.GOOGLE.COM.

3. Make Sure the MX Target Resolves

The hostname your MX record points to must have its own A or AAAA record and must not be a CNAME. Look up the target directly to confirm it returns an IP address.

4. Wait for Propagation, Then Verify

MX changes can take minutes to hours to reach every resolver. Re-check from multiple locations until the record is consistent, then send a test message. You can confirm the receiving server is reachable with the SMTP Checker.

  • WHOIS Lookup — rule out an expired or unregistered domain behind the failure.

Frequently Asked Questions

What is an MX record?

An MX (Mail Exchanger) record is a DNS record naming the host that receives email for a domain, along with a priority. Lower priority numbers are preferred, letting you list backup mail servers.

Does a domain really need an MX record to receive email?

Almost always. RFC 5321 permits a fallback to the domain's A/AAAA record when no MX exists, but many senders ignore that, so mail is likely to bounce. Publish an explicit MX record to receive email reliably.

Why does mail bounce when the website loads fine?

The website is served from the domain's A/AAAA record; email uses the separate MX record. One can be configured without the other, so the site works while mail has nowhere to go.

Can an MX record point to an IP address?

No. An MX record must point to a hostname that resolves via an A or AAAA record. Pointing it at an IP address or a CNAME is invalid.

Related Errors

  • NXDOMAIN — the recipient domain does not exist at all, so no MX lookup is possible.
  • SMTP 550 — the bounce code a sender often returns when the recipient domain cannot be routed.
  • SERVFAIL — the MX lookup failed due to a resolver or DNSSEC error rather than a missing record.
