Troubleshooting / DNS / getaddrinfo ENOTFOUND

getaddrinfo ENOTFOUND

Last updated: July 1, 2026

A Node.js error thrown when a hostname cannot be resolved to an IP address — the DNS lookup returned no result for the name your code tried to connect to.

You might see this error as:

  • getaddrinfo ENOTFOUND
  • Error: getaddrinfo ENOTFOUND
  • getaddrinfo ENOTFOUND undefined
  • getaddrinfo ENOTFOUND localhost
  • FetchError: getaddrinfo ENOTFOUND
  • axios ENOTFOUND

What Does This Error Mean?

Node.js calls the operating system's getaddrinfo function to turn a hostname into an IP address before opening a connection. ENOTFOUND means that lookup came back empty: the name does not exist in DNS (or in /etc/hosts) from this machine's point of view. The error is almost always about *which name* the code tried to resolve — very often a typo, an unset environment variable, or a hostname that only exists inside another network (like a Docker or Kubernetes internal name).

Common Causes

  • The hostname is wrong or does not exist — A typo in the URL or connection string, or a domain that was never registered or has been deleted. The lookup correctly reports there is no such name.
  • An environment variable is unset — Errors like 'getaddrinfo ENOTFOUND undefined' mean the code built a hostname from a variable that was undefined — the literal string 'undefined' was looked up in DNS.
  • The name only resolves in a different environment — Docker Compose service names (db, redis) and Kubernetes service names resolve only inside that network. Code running on the host, or in a different network, cannot resolve them.
  • Local DNS or hosts-file entry is missing — If the app previously relied on an /etc/hosts entry or an internal DNS zone (VPN, office network), running it elsewhere makes the same hostname unresolvable.

How to Fix It

1. Log and verify the exact hostname

Print the hostname the code actually uses (not the one you think it uses), then test it with dig or an online DNS lookup. This catches typos and undefined variables immediately.

console.log('connecting to:', process.env.DB_HOST);
# on the same machine:
dig +short your-hostname.example.com

2. Check environment variables are loaded

If the hostname comes from .env, confirm the file is loaded (dotenv configured, correct working directory, variable spelled the same in code and file).

node -e "require('dotenv').config(); console.log(process.env.DB_HOST)"

3. Use the right name for the network you are in

Inside Docker Compose, connect using the service name. From the host machine, use localhost with the published port instead — the service name does not exist in host DNS.

# inside the compose network:
DATABASE_URL=postgres://user:pass@db:5432/app
# from the host (port published as 5432):
DATABASE_URL=postgres://user:pass@localhost:5432/app

4. Add a hosts entry or fix DNS for internal names

For names served by an internal DNS zone, connect to the VPN, or add a temporary /etc/hosts entry while testing.

echo "10.0.0.15 internal-api.company.local" | sudo tee -a /etc/hosts

Frequently Asked Questions

What is the difference between ENOTFOUND and ECONNREFUSED?

ENOTFOUND fails before any connection attempt — the hostname could not be resolved to an IP. ECONNREFUSED means DNS worked and Node reached the target machine, but nothing was listening on that port. They point to completely different problems.

Why do I get 'getaddrinfo ENOTFOUND localhost'?

Some minimal containers and misconfigured systems are missing the localhost entry in /etc/hosts. Add '127.0.0.1 localhost' to the hosts file, or connect to 127.0.0.1 directly.

Does Node.js cache DNS results?

Not by default — every lookup calls the OS resolver. If you fixed DNS and still see the error, the stale result is being cached by the operating system or an HTTP agent in your code, not by Node's resolver.
