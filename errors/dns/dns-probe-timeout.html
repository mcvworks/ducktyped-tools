DNS_PROBE_TIMEOUT

Last updated: March 8, 2026

DNS probe timed out while testing connectivity

You might see this error as:

  • DNS_PROBE_TIMEOUT
  • DNS timeout
  • DNS query timed out
  • DNS lookup timed out

What Does This Error Mean?

DNS_PROBE_TIMEOUT occurs when Chrome's internal DNS probe mechanism fails to receive a response within its timeout window. After detecting a DNS resolution failure, Chrome sends probe queries to verify DNS connectivity, and if these probes also time out, the browser concludes that DNS resolution is not functioning. This typically points to network-level issues blocking DNS traffic or an unresponsive DNS server.

Common Causes

  • Firewall blocking DNS traffic — A local firewall, corporate firewall, or network appliance is blocking outbound DNS queries on port 53 (UDP/TCP), preventing both the original lookup and Chrome's diagnostic probes from reaching any DNS server.
  • DNS server is down or unreachable — The configured DNS server is offline, overloaded, or unreachable from the client network. All queries sent to it receive no response, causing timeouts.
  • Network congestion or packet loss — Heavy network congestion or high packet loss on the path between the client and the DNS server is causing DNS queries to be dropped before they reach the server or responses to be lost in transit.
  • ISP DNS infrastructure issues — The internet service provider's DNS infrastructure is experiencing an outage or degraded performance, affecting all customers using the default DNS servers.
  • VPN tunnel DNS leak prevention — A VPN client is configured to prevent DNS leaks by blocking all DNS traffic outside the VPN tunnel, but the tunnel itself is down or not routing DNS correctly.

How to Fix It

1. Test DNS server reachability

Verify that you can reach your configured DNS server. If the DNS server is unreachable, switch to a different one.

# Test if DNS server responds
nslookup google.com 8.8.8.8

# Check current DNS configuration
# Windows
ipconfig /all | findstr "DNS"

# Linux/macOS
cat /etc/resolv.conf

2. Switch to a public DNS server

Replace your current DNS server with a reliable public DNS provider. This bypasses issues with ISP DNS servers or misconfigured local DNS.

# Use Google DNS: 8.8.8.8 / 8.8.4.4
# Or Cloudflare: 1.1.1.1 / 1.0.0.1

3. Check firewall rules

Ensure your firewall allows outbound UDP and TCP traffic on port 53. Some security software or corporate firewalls may block DNS traffic, especially after a policy update.

4. Restart network services

Restart your network adapter and DNS client service to clear any stuck states.

# Windows
ipconfig /release
ipconfig /renew
ipconfig /flushdns

# Linux
sudo systemctl restart NetworkManager
sudo systemd-resolve --flush-caches

Frequently Asked Questions

How long does Chrome wait before timing out DNS probes?

Chrome's DNS probe timeout is typically a few seconds. If both the original DNS query and the follow-up probe queries receive no response within this window, Chrome reports the timeout error.

Can a slow internet connection cause DNS probe timeouts?

A slow connection alone usually does not cause DNS timeouts, but a connection with high packet loss can. DNS queries are small packets, so bandwidth is not the issue — reliability of packet delivery is.

Is this different from DNS_PROBE_FINISHED_NO_INTERNET?

Yes. DNS_PROBE_TIMEOUT means the probe queries received no response at all. DNS_PROBE_FINISHED_NO_INTERNET means the probes completed but confirmed that there is no internet connectivity.

Related Errors

  • DNS_PROBE_FINISHED_NO_INTERNET — DNS probe confirmed no internet access
  • DNS Server Not Responding — DNS server is not responding to queries
  • DNS_PROBE_STARTED — Chrome has initiated a DNS probe
