Relay Access Denied

Last updated: March 8, 2026

Mail server rejected the message because relay is not permitted

You might see this error as:

  • Relay access denied
  • 554 Relay access denied
  • Relaying denied
  • SMTP relay not allowed
  • This server does not relay

What Does This Error Mean?

Relay Access Denied occurs when an SMTP server refuses to forward an email because the sender is not authorized to use the server as a relay. Mail servers are configured to accept mail only for their own domains or from authenticated users. When a server receives mail destined for a domain it does not host from an unauthenticated sender, it rejects the message to prevent being used as an open relay, which would enable spam distribution.

Common Causes

  • Missing SMTP authentication — The email client is not authenticating with the SMTP server before attempting to send. Modern SMTP servers require authentication (SMTP AUTH) to relay mail for non-local domains.
  • Incorrect SMTP server for the sending domain — The email client is configured to use an SMTP server that does not recognize the sender's domain. Each email provider typically requires you to use their specific SMTP server.
  • IP address not in the relay allow list — The SMTP server is configured to allow relaying only from specific IP addresses or networks, and the sender's IP is not in the permitted list.
  • Sending to an external domain through a local server — The email is addressed to a recipient outside the server's local domains, and the server is correctly configured to refuse relaying for unauthenticated senders.

How to Fix It

1. Enable SMTP authentication

Configure your email client to authenticate with the SMTP server using a username and password. Ensure the authentication method matches what the server supports.

# Common SMTP settings requiring authentication
# Port 587 (STARTTLS) — recommended
# Port 465 (SSL/TLS)
# Authentication: Login or PLAIN

2. Verify SMTP server settings

Ensure you are using the correct SMTP server for your email provider. Using the wrong server will result in relay denials because the server does not recognize your account.

3. Check relay permissions on the server

If you manage the mail server, review the relay configuration to ensure legitimate senders are permitted. For Postfix, check mynetworks and smtpd_relay_restrictions.

# Postfix relay configuration
smtpd_relay_restrictions =
  permit_mynetworks,
  permit_sasl_authenticated,
  reject_unauth_destination

4. Use the correct sending port

Ensure your client is connecting on port 587 (submission) with STARTTLS rather than port 25 (relay). Port 587 is designed for authenticated mail submission.

Frequently Asked Questions

What is an open relay and why do servers prevent it?

An open relay is a mail server that forwards email from any sender to any recipient without authentication. Spammers exploit open relays to send bulk email. Modern mail servers are configured to reject unauthorized relay attempts to prevent abuse.

Why did this suddenly stop working?

Your mail server may have been updated to require authentication, your IP address may have changed and is no longer in the relay allow list, or your email client settings may have been reset to not include authentication credentials.

Can I fix this without server access?

Yes. The most common fix is to enable SMTP authentication in your email client settings. Ensure you have the correct username, password, server address, and port configured.
