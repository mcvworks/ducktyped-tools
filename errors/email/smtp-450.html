SMTP 450 — Mailbox Temporarily Unavailable

Last updated: March 8, 2026

SMTP 450 means the recipient's mailbox is temporarily unavailable. This is a soft bounce — your mail server will retry delivery automatically.

You might see this error as:

  • SMTP 450
  • 450 Mailbox unavailable
  • 450 Requested mail action not taken
  • 450 mailbox busy
  • Greylisting 450

What Does This Error Mean?

The full SMTP 450 response is typically: "450 Requested mail action not taken: mailbox unavailable (e.g., mailbox busy or temporarily blocked for policy reasons)."

As a 4xx code, this is a transient failure. The message is not rejected permanently — it is queued and will be retried. This is in contrast to the permanent 5xx equivalent, SMTP 550.

Common Causes

  • Mailbox over quota — recipient's inbox is full.
  • Mailbox locked — the mailbox is currently being accessed and locked by another process.
  • Greylisting — the receiving server temporarily rejects first-time senders as an anti-spam measure. Retry typically succeeds.
  • Temporary anti-spam policy — the receiving server has temporarily blocked your sending IP due to suspicious activity.
  • Server maintenance — the receiving mail server is temporarily in a degraded state.

📡 Them or you? Before changing anything, check live Microsoft 365 status or Google Workspace status on DTMonitor — during a provider incident this error shows up on perfectly healthy setups, and the fix is to wait.

How to Handle It

1. Wait for Automatic Retry

A correctly configured sending MTA will retry automatically. For greylisting, the second delivery attempt (after a few minutes) almost always succeeds.

2. Verify the Mailbox is Not Permanently Full

If 450 errors for the same recipient persist over several days, contact the recipient. Their inbox may be consistently over quota and they need to clear space.

3. Check Your IP Reputation

If you are receiving 450 errors across many recipients, your sending IP may be on a temporary throttle or blocklist. Use the Blacklist Checker to inspect your IP reputation.

4. Verify MX Records

Confirm the destination's MX records are correctly configured using the DNS Lookup tool.

Frequently Asked Questions

How does greylisting work?

Greylisting temporarily rejects email from unknown sender/IP combinations with a 450 code. Legitimate mail servers retry delivery after a few minutes, which succeeds. Spam bots often do not retry, so greylisting filters spam without permanently rejecting legitimate email.

When does a 450 become a hard bounce?

If the sending server cannot deliver the message within its configured retry window (typically 4–5 days), it sends a non-delivery report (NDR) to the original sender. The bounce message will indicate the 450 was the cause of the failed delivery.
