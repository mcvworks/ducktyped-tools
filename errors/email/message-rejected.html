Message Rejected

Last updated: March 8, 2026

Email message was rejected by the receiving server

You might see this error as:

  • Message rejected
  • 550 Message rejected
  • Email rejected by server
  • Spam filter rejected

What Does This Error Mean?

Message Rejected is a general SMTP rejection indicating that the receiving mail server refused to accept the email. Unlike recipient-specific errors, message rejection typically relates to the content, format, or characteristics of the email itself. The server evaluated the message and determined it violates one or more policies, such as content filtering rules, attachment restrictions, message size limits, or sender reputation checks.

Common Causes

  • Content flagged by spam filters — The message body, subject line, or headers triggered the receiving server's spam filters. This can happen with certain keywords, excessive links, HTML formatting issues, or a high spam score from content analysis.
  • Sender domain fails authentication checks — The sending domain's SPF, DKIM, or DMARC records do not align with the sending server, causing the receiving server to reject the message as potentially spoofed.
  • Attachment policy violation — The message contains an attachment type that the receiving server does not allow, such as executable files (.exe, .bat, .scr), password-protected archives, or files exceeding the size limit.
  • Sender IP on a blocklist — The IP address of the sending mail server appears on one or more DNS-based blocklists (DNSBLs), causing the receiving server to reject all mail from that IP.
  • Message exceeds size limit — The total message size, including attachments and encoding overhead, exceeds the receiving server's maximum message size policy.

How to Fix It

1. Check sender authentication records

Verify that your domain has valid SPF, DKIM, and DMARC records, and that the sending server is authorized in these records.

# Check SPF record
dig TXT example.com | grep spf

# Check DKIM record
dig TXT selector._domainkey.example.com

# Check DMARC record
dig TXT _dmarc.example.com

2. Review message content

Remove or modify content that may trigger spam filters. Avoid excessive capitalization, multiple exclamation marks, spammy phrases, and large numbers of URLs. Ensure HTML is well-formed.

3. Check sender IP reputation

Verify that your sending IP is not listed on major blocklists. Use a blocklist checker to scan multiple DNSBLs at once.

4. Reduce attachment size or change format

If the message has attachments, ensure they comply with the recipient's server policies. Use cloud storage links for large files and avoid executable file types.

Frequently Asked Questions

Why was my legitimate email rejected as spam?

Spam filters use scoring systems that evaluate many factors. A legitimate email can be rejected if it has formatting similar to spam, comes from a new domain with no reputation, is sent from an IP shared with spammers, or lacks proper authentication records.

Does the sender get a bounce message when a message is rejected?

Usually yes. The sending server receives the rejection during the SMTP transaction and generates a bounce (Non-Delivery Report) back to the sender. The bounce message typically includes the rejection reason from the receiving server.

Can I find out exactly why my message was rejected?

Check the bounce message or SMTP logs for the specific rejection reason. The receiving server usually provides a diagnostic message. Common formats include '550 5.7.1 Message rejected due to content' followed by more details.
