SMTP 502 — Command Not Implemented

Last updated: March 8, 2026

SMTP command is recognized but not implemented on this server

You might see this error as:

  • SMTP 502
  • 502 Command not implemented
  • 502 VRFY not implemented

What Does This Error Mean?

SMTP 502 is a permanent error indicating that the server recognizes the SMTP command but has not implemented it. Unlike SMTP 500 where the command is unrecognized, SMTP 502 means the command is part of the SMTP specification but the server deliberately does not support it. This commonly occurs with optional SMTP extensions that not all servers implement, such as VRFY, EXPN, or certain AUTH mechanisms.

Common Causes

  • Optional SMTP command not supported — The client sent an optional SMTP command like VRFY (verify address), EXPN (expand mailing list), or TURN that the server has chosen not to implement, often for security reasons.
  • AUTH mechanism not supported — The client attempted to use an authentication mechanism (such as AUTH CRAM-MD5 or AUTH NTLM) that the server does not support. The server only implements specific authentication methods.
  • ESMTP extension not available — The client attempted to use an ESMTP extension that was not advertised in the server's EHLO response. Servers only support the extensions they explicitly list.
  • Security policy disables the command — The server administrator has deliberately disabled certain commands for security purposes. VRFY and EXPN are commonly disabled to prevent email address harvesting.

How to Fix It

1. Check server capabilities with EHLO

Send an EHLO command and review the server's response to see which extensions and commands are supported.

# Check supported extensions
telnet mail.example.com 25
EHLO client.example.com

# Server responds with supported extensions:
# 250-PIPELINING
# 250-SIZE 52428800
# 250-AUTH LOGIN PLAIN
# 250-STARTTLS
# 250 8BITMIME

2. Use a supported authentication mechanism

If AUTH returns 502, check which AUTH mechanisms the server advertises and use one of those instead. Most servers support AUTH LOGIN and AUTH PLAIN.

3. Avoid disabled commands

Do not rely on VRFY or EXPN commands in production email workflows. These commands are disabled on most modern mail servers. Use alternative methods to validate addresses.

Frequently Asked Questions

Why do servers disable VRFY and EXPN?

VRFY allows anyone to verify whether an email address exists on the server, and EXPN reveals the members of mailing lists. Both can be exploited by spammers to harvest valid email addresses, so administrators disable them as a security measure.

Is SMTP 502 a temporary or permanent error?

It is a permanent error. The server will never support the command unless the administrator enables it. Your client must use alternative commands or approaches.

How is SMTP 502 different from SMTP 504?

SMTP 502 means the entire command is not implemented. SMTP 504 means the command is implemented but a specific parameter for that command is not supported. For example, AUTH may be implemented (no 502) but a specific AUTH mechanism like GSSAPI may not be (504).
