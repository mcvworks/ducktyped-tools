SMTP 535 — Authentication Failed

Last updated: March 8, 2026

SMTP 535 means the SMTP server rejected your authentication credentials. The username, password, or authentication method was not accepted.

You might see this error as:

  • SMTP 535
  • 535 Authentication failed
  • 535 5.7.8 Username and Password not accepted
  • 535 Incorrect authentication data
  • SMTP auth failed

What Does This Error Mean?

The full response is typically: "535 5.7.8 Username and Password not accepted" or "535 Authentication credentials invalid." This error occurs during the SMTP AUTH command — when your email client or application attempts to authenticate before sending mail.

Common Causes

  • Incorrect password — the password was changed and the SMTP client was not updated.
  • Using account password instead of app password — Gmail, Outlook, Yahoo, and others require an app-specific password when two-factor authentication is enabled.
  • Account locked — too many failed login attempts triggered a temporary lock.
  • Less secure app access disabled — providers like Gmail have deprecated "less secure app" access; OAuth is now required.
  • Wrong username format — some servers require the full email address (user@domain.com), others just the username.
  • SMTP AUTH not enabled — the mail server requires authentication but it is not enabled for your account or IP.
  • Incorrect authentication mechanism — client uses PLAIN but server requires LOGIN, or CRAM-MD5, etc.

How to Fix It

1. Verify Your Credentials

Log into the web interface of your email provider with the same username and password. If that fails, reset your password through the provider.

2. Use an App-Specific Password

If you have 2FA enabled on your email account (strongly recommended), generate an app-specific password:

  • Gmail: Google Account → Security → App passwords
  • Outlook/Microsoft: Account settings → Security → App passwords
  • Yahoo: Account Security → Generate app password

Use this app password in your SMTP client instead of your main account password.

3. Check for Account Lockout

Sign into your email account via the web. If the account is locked, follow the provider's account recovery steps.

4. Check SMTP Settings

Verify your SMTP configuration matches your provider's requirements:

  • Correct hostname (e.g., smtp.gmail.com)
  • Correct port (587 with STARTTLS, or 465 with SSL/TLS)
  • Full email address as username (e.g., user@gmail.com)

Use the SMTP Checker to verify connectivity.

Frequently Asked Questions

Does 535 mean my account was hacked?

Not necessarily. It most commonly means credentials are outdated or misconfigured. However, if you receive unexpected authentication failure alerts, it may indicate failed unauthorized login attempts. Enable 2FA if you haven't already.

What is an app-specific password?

An app-specific password is a unique 16-character password generated by your email provider for use with a specific application. It allows applications to authenticate without your main account password and without 2FA prompts. Each app gets its own password that can be revoked independently.
