SMTP 500 — Syntax Error

Last updated: March 8, 2026

SMTP command not recognized due to syntax error

You might see this error as:

  • SMTP 500
  • 500 Syntax error
  • 500 Unrecognized command
  • 500 Command not recognized

What Does This Error Mean?

SMTP 500 is a permanent error response indicating that the server did not recognize the command sent by the client. The command may be misspelled, improperly formatted, or not supported by the server. This is a protocol-level error meaning the SMTP conversation cannot proceed with the unrecognized command. Unlike content or recipient errors, SMTP 500 indicates a fundamental miscommunication between the client and server about the SMTP protocol itself.

Common Causes

  • Unrecognized SMTP command — The client sent an SMTP command that the server does not support or recognize. This can happen when a client uses extended SMTP (ESMTP) commands with a server that only supports basic SMTP.
  • Malformed command syntax — The command was sent with incorrect syntax, such as missing required parameters, extra spaces, or incorrect line endings (not using CRLF).
  • Client sending HTTP to an SMTP port — A misconfigured application is sending HTTP requests to an SMTP server port, causing the SMTP server to reject the unrecognized data as a syntax error.
  • Protocol version mismatch — The client is attempting to use ESMTP features (like STARTTLS or AUTH) on a server that only supports the basic SMTP command set and does not advertise these extensions.

How to Fix It

1. Verify SMTP command sequence

Ensure your client follows the correct SMTP command sequence: EHLO/HELO, then MAIL FROM, RCPT TO, DATA, and QUIT.

# Correct SMTP command sequence
EHLO client.example.com
MAIL FROM:<sender@example.com>
RCPT TO:<recipient@example.com>
DATA
Subject: Test

Test message body.
.
QUIT

2. Use EHLO instead of HELO

Modern SMTP servers expect the EHLO command which initiates an Extended SMTP session. If the server returns 500 for EHLO, fall back to HELO for basic SMTP.

3. Check for proper line endings

SMTP requires CRLF (\r\n) line endings. If your client sends only LF (\n), some strict servers will reject the commands with a syntax error.

4. Review client configuration

Ensure the email client is configured to use SMTP (not HTTP or another protocol) and is connecting to the correct port (25, 465, or 587).

Frequently Asked Questions

Is SMTP 500 a permanent or temporary error?

SMTP 500 is a permanent error (5xx class). The server will not accept the same command if retried. The client must fix the command syntax or use a different command before retrying.

Can SMTP 500 be caused by the email content?

No. SMTP 500 is specifically about the SMTP command itself, not the email content. Content-related rejections use different error codes like 550 or 554.

Why do I see SMTP 500 when connecting to a new mail server?

The new server may have different capabilities or stricter syntax requirements. Check which SMTP extensions the server supports by examining the response to the EHLO command.
