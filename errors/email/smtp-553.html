SMTP 553 — Mailbox Name Not Allowed

Last updated: March 8, 2026

SMTP 553 means the email address is not valid or the mailbox name violates the receiving server's policies. This is a permanent 5xx error.

You might see this error as:

  • SMTP 553
  • 553 Requested action not taken
  • 553 Mailbox name not allowed
  • 553 Invalid sender

What Does This Error Mean?

The standard response is: "553 Requested action not taken: mailbox name not allowed." This error indicates the email address used in the RCPT TO (recipient) or MAIL FROM (sender) command is unacceptable to the server — either because of invalid format, disallowed characters, or a server policy restriction.

Common Causes

  • Invalid email address format — the address does not conform to RFC 5321 syntax (e.g., missing @, invalid characters, double dots).
  • Relay restriction — some servers return 553 when they refuse to relay mail for a sender domain they do not control.
  • Reserved mailbox names — names like postmaster, abuse may be restricted on some servers.
  • Sender address not authorized — using a FROM address for a domain the server does not accept relaying for.
  • Blocked TLD or domain — the server blocks all mail from certain domains or TLDs.

How to Fix It

1. Verify the Recipient's Address

Double-check the spelling and format of the recipient's email address. Ensure it follows the format local-part@domain.tld with no invalid characters.

2. Check Your Sender Address

If the error references the MAIL FROM address, ensure your sending address is valid and uses a domain you are authorized to send from.

3. Use the Email Validator

Validate the email address format and check that the domain has valid MX records before sending.

4. Check Your Mail Server Configuration

If you are a mail server administrator and users are reporting 553 errors when sending, check your relay restrictions. Ensure authenticated users can send with their own domain addresses.

Frequently Asked Questions

Does 553 mean the email account does not exist?

Not necessarily. If the address does not exist, the server would typically return SMTP 550. A 553 specifically means the mailbox name itself is unacceptable — a different type of rejection than a non-existent account.

Can 553 be caused by using a no-reply address?

Possibly. If you are sending with a noreply@yourdomain.com sender address via a relay server that requires authentication, ensure you are authenticated for that domain. Some servers reject FROM addresses that do not match an authenticated account.
