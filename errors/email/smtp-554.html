SMTP 554 — Transaction Failed

Last updated: March 8, 2026

SMTP 554 is a permanent rejection of the entire email transaction. It is commonly triggered by spam filters, content policies, or sender reputation issues. Here is what causes it and how to fix it.

You might see this error as:

  • SMTP 554
  • 554 Transaction failed
  • 554 Message rejected
  • 554 5.7.1 Blocked
  • 554 Denied
  • 554 Email rejected

What Does SMTP 554 Mean?

The SMTP response code 554 means the mail server permanently refused to process the email transaction. Unlike code 550 (which targets a specific mailbox), 554 rejects the entire session — often before the message content is even evaluated.

A typical 554 response looks like:

554 5.7.1 Service unavailable; Client host [1.2.3.4] blocked
554 5.7.1 Message rejected as spam by Content Filtering
554 Transaction failed. Spam message rejected
554 5.7.0 Reject, id=00012-09 — SPAM

The exact text depends on the receiving server's software and policy configuration.

Common Causes

  • Sending IP blacklisted — your mail server's IP appears on a DNS-based block list (DNSBL) such as Spamhaus, Barracuda, or SORBS.
  • SPF hard fail — your sending IP is not in the SPF record and the record uses -all (hard fail).
  • DMARC reject policy — the sender domain has p=reject in its DMARC policy and the message failed authentication.
  • Content spam score too high — the message body, subject line, or attachments triggered the recipient's spam filter.
  • No reverse DNS (PTR record) — many mail servers reject connections from IPs without a PTR record that matches the forward DNS.
  • Missing or invalid HELO/EHLO hostname — the sending server identifies itself incorrectly during the SMTP handshake.
  • Recipient server policy — some organizations reject all mail from certain IP ranges, countries, or mail providers.
  • High bounce rate history — if your domain or IP has a history of bounces or spam complaints, reputation systems will flag future messages.

How to Fix It

1. Check Whether Your IP Is Blacklisted

Use the Blacklist Checker to check your sending IP against major DNSBLs. If listed, follow the delisting instructions for each blacklist. You must resolve the underlying cause (spam activity, open relay, compromised server) before requesting removal.

2. Verify Your SPF Record

Look up your domain's TXT records using the DNS Record Checker. Your SPF record must list all servers authorized to send mail for your domain:

v=spf1 ip4:203.0.113.10 include:_spf.google.com ~all

Avoid using -all (hard fail) until you are certain all legitimate senders are included, as it causes strict rejections.

3. Set Up or Fix DKIM

DKIM signs your outgoing messages so receivers can verify they have not been tampered with. Check that your DKIM selector record exists in DNS:

selector._domainkey.yourdomain.com  TXT  "v=DKIM1; k=rsa; p=..."

If the record is missing or malformed, reconfigure DKIM signing in your mail server software.

4. Check Your PTR (Reverse DNS) Record

Many mail servers require that your sending IP has a PTR record that resolves back to a valid hostname, and that hostname resolves forward to the same IP. Contact your hosting provider or ISP to set a PTR record for your mail server's IP.

# Verify PTR record:
nslookup 1.2.3.4

5. Review Message Content

If the rejection message mentions content filtering, review your email for common spam triggers:

  • Excessive use of capital letters or exclamation marks
  • Spam keyword patterns in the subject line
  • Too many links relative to text content
  • Attachments with suspicious file types
  • HTML-only emails with no plain text part

6. Test SMTP Connectivity

Use the SMTP Checker to verify your mail server connects correctly and the EHLO handshake succeeds.

Frequently Asked Questions

Can I just retry after a 554?

No. A 554 is a permanent (5xx) error — the server will reject the same message again without changes. You must fix the underlying cause (clear the blacklist, fix authentication records, clean up message content) before resending.

Why is my sending IP blacklisted?

IPs get blacklisted for sending spam (whether intentional or from a compromised server), operating as an open relay, or having a high bounce rate. Check your server logs for unauthorized mail activity, secure any open relays, and remove compromised accounts before requesting delisting.

Does 554 mean the recipient server thinks I'm spam?

Usually yes, but not always. Some servers use 554 for any policy rejection, including geographic blocks, IP range bans, or administrative policies unrelated to spam content. The rejection text will usually hint at the specific reason.

Related Errors

  • SMTP 550 — Mailbox Unavailable — recipient address rejected.
  • SMTP 553 Mailbox Name Invalid — sender or recipient address format is unacceptable.
  • SMTP 535 Authentication Failed — sender could not authenticate with the mail server.
  • SMTP 521 — Does Not Accept Mail — destination server refuses all incoming email.
