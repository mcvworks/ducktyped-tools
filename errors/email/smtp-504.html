SMTP 504 — Command Parameter Not Implemented

Last updated: March 8, 2026

SMTP command parameter is not implemented on this server

You might see this error as:

  • SMTP 504
  • 504 Command parameter not implemented
  • 504 Unrecognized authentication type

What Does This Error Mean?

SMTP 504 is a permanent error indicating that the server supports the SMTP command but does not implement the specific parameter or argument used with it. The command itself is valid and implemented, but the particular option or variant requested is not available. This commonly occurs with unsupported AUTH mechanisms, unrecognized MAIL FROM parameters, or SIZE declarations that exceed server limits.

Common Causes

  • Unsupported AUTH mechanism — The client requested an authentication mechanism (such as GSSAPI, DIGEST-MD5, or EXTERNAL) that the server does not implement. The server supports AUTH but not the specific mechanism requested.
  • Unsupported MAIL FROM extension parameter — The client included an ESMTP extension parameter in the MAIL FROM command (such as BODY=BINARYMIME or AUTH=) that the server does not support.
  • Unrecognized EHLO parameter format — The hostname or address literal provided with EHLO uses a format the server does not support, such as an IPv6 address literal on a server that only handles IPv4.
  • SIZE parameter exceeds server maximum — The SIZE parameter in the MAIL FROM command declares a message size larger than what the server is configured to accept.

How to Fix It

1. Use a supported AUTH mechanism

Check which authentication mechanisms the server advertises and use one of those.

# Check supported AUTH mechanisms from EHLO response
# Server responds:
# 250-AUTH LOGIN PLAIN XOAUTH2

# Use a supported mechanism
AUTH LOGIN
AUTH PLAIN

2. Remove unsupported MAIL FROM parameters

If the MAIL FROM command includes extension parameters, remove them and use the basic form to see if the command succeeds.

# Basic MAIL FROM (always supported)
MAIL FROM:<sender@example.com>

# Extended form (may not be supported)
MAIL FROM:<sender@example.com> BODY=8BITMIME SIZE=1048576

3. Check server capabilities before using extensions

Only use ESMTP extension parameters that the server explicitly advertises in its EHLO response. Do not assume any extensions are available.

Frequently Asked Questions

How is SMTP 504 different from SMTP 502?

SMTP 502 means the entire command is not implemented. SMTP 504 means the command is implemented but a specific parameter variant is not. For example, AUTH is available (not 502) but AUTH GSSAPI is not (504).

Can I determine which parameters a server supports?

Yes. Send an EHLO command and examine the response. Each extension line indicates a supported capability and its parameters. For AUTH, the supported mechanisms are listed after 'AUTH' in the EHLO response.

Will retrying the same command with the same parameter work later?

No. SMTP 504 is a permanent error. The parameter is not implemented and will not be accepted on retry. You must use a different, supported parameter.
