SMTP 550 — Mailbox Unavailable

Last updated: March 8, 2026

SMTP error 550 means the receiving mail server rejected your message. The most common reason is that the recipient address does not exist. Here is what causes it and how to diagnose and fix it.

You might see this error as:

  • SMTP 550
  • 550 User unknown
  • 550 5.1.1
  • 550 Requested action not taken
  • 550 Mailbox not found
  • 550 No such user
  • 550 Recipient rejected
  • 550 5.7.1 Relaying denied

Where This Error Occurs

What Does SMTP 550 Mean?

In the SMTP protocol, response codes in the 5xx range indicate permanent failures. 550 specifically means the server refused to deliver the message to the requested address. The full response typically looks like:

550 5.1.1 The email account that you tried to reach does not exist.
550 5.7.1 Message rejected due to sender policy.
550 No such user here

The second set of digits (e.g., 5.1.1 or 5.7.1) is the enhanced status code that provides more specific information about the rejection reason.

Enhanced Status Codes

  • 5.1.1 — the recipient address does not exist on this server.
  • 5.1.2 — bad recipient domain — cannot find the domain in DNS.
  • 5.7.1 — delivery not authorized. Sender policy, relay denial, or authentication failure.
  • 5.7.26 — SPF authentication failed for the sender domain.

Common Causes

  • Non-existent mailbox — the email address has been deleted, misspelled, or never existed.
  • Sender policy rejection — the recipient server's anti-spam policy blocked the message based on the sender's IP or domain reputation.
  • SPF failure — the sending server's IP is not authorized by the sender domain's SPF record.
  • DKIM failure — the message signature is invalid or missing, and the recipient server enforces DKIM.
  • DMARC policy failure — SPF and/or DKIM fails, and the DMARC policy is set to reject.
  • IP blacklisted — the sending IP address is on a DNS blacklist (DNSBL).
  • Relay access denied — you are trying to send mail through a server you are not authorized to use as a relay.

How to Fix It

1. Verify the Recipient Address

Confirm the email address is typed correctly. Use the Email Validator to check whether the domain has valid MX records and whether the address format is valid.

2. Check Your SPF Record

Use the DNS Record Checker to look up the TXT records for your sending domain. Verify your SPF record includes all servers authorized to send email on your behalf:

v=spf1 include:_spf.google.com include:sendgrid.net ~all

The ~all (soft fail) or -all (hard fail) at the end controls how receiving servers handle unauthorized senders.

3. Verify DKIM Configuration

Check that your DKIM TXT record is published in DNS and that your mail server is signing outgoing messages. Use the DNS checker to look up selector._domainkey.yourdomain.com.

4. Check DMARC Policy

Look up _dmarc.yourdomain.com in the DNS checker. A DMARC policy of p=reject means any message that fails both SPF and DKIM alignment will be rejected.

5. Check Blacklists

Use the Blacklist Checker to see if your sending IP is on any DNS-based block lists. If blacklisted, contact the blacklist provider to request delisting after resolving the underlying issue (spam, misconfiguration).

6. Check SMTP Connection

Use the SMTP Checker to verify the recipient domain's mail server is reachable and accepting connections on port 25.

Frequently Asked Questions

Does a 550 bounce mean the email address is fake?

Not always. A 550 with code 5.1.1 usually means the mailbox does not exist. However, some servers return 550 for policy reasons even when the mailbox exists — for example, if your IP is blacklisted or your message failed authentication. Read the extended message text carefully.

Can I retry a message that gets a 550 bounce?

Not immediately. 5xx codes are permanent failures. Retrying without fixing the underlying issue will result in the same rejection. Fix the root cause first, then resend.

What is the difference between a soft bounce and a hard bounce?

A hard bounce (like a 550) is a permanent delivery failure — the message was definitively rejected. A soft bounce is a temporary failure (4xx codes) where the server suggests retrying later. Hard bounces should remove the address from your mailing list.

Related Errors

  • SMTP 554 Transaction Failed — broader rejection, often spam-related.
  • SMTP 553 Mailbox Name Invalid — sender or recipient address is syntactically unacceptable.
  • SMTP 521 — Does Not Accept Mail — destination server refuses all incoming email.
  • Mailbox Unavailable — recipient mailbox cannot receive messages.
