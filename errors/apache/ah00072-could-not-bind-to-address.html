Apache AH00072 — make_sock: Could Not Bind to Address

Last updated: July 2, 2026

The startup failure '(98)Address already in use: AH00072: make_sock: could not bind to address [::]:80' — another process holds Apache's port, or Apache is fighting itself.

You might see this error as:

  • AH00072: make_sock: could not bind to address
  • (98)Address already in use: AH00072
  • AH00451: no listening sockets available, shutting down
  • apache could not bind to address 0.0.0.0:80

What Does This Error Mean?

Apache could not claim the port a Listen directive told it to use, so startup aborts (AH00451: no listening sockets available). Same root causes as any port conflict: nginx or another server on 80/443, a stale Apache still holding the socket, or the same Listen declared twice (ports.conf plus a vhost, or two included files) making Apache collide with itself — the giveaway for that case is the error naming a port that only Apache uses.

Common Causes

  • Another web server owns the port — Nginx, Caddy, a Node app, or a Docker container publishing 80/443 got there first. Only one listener per address:port.
  • Duplicate Listen directives — Listen 80 in ports.conf and again in an included vhost file makes Apache try to bind twice — it then reports a conflict with itself.
  • Stale Apache processes — A crashed restart can leave the old process tree holding the socket, so the new start finds the port taken by its predecessor.
  • IPv6/IPv4 split conflicts — The error naming [::]:80 with 0.0.0.0:80 free (or vice versa) points at another service bound on just one protocol family.

How to Fix It

1. Identify the holder

Name the process on the port before changing anything.

sudo ss -tlnp | grep -E ':80 |:443 '
# if it is nginx: decide which server fronts the box;
# if it is apache/httpd: stale process — see below

2. Check for duplicate Listen directives

Dump the whole effective config and count the Listen lines per port.

# Debian/Ubuntu:
sudo apache2ctl -t -D DUMP_RUN_CFG 2>/dev/null | head
grep -rn '^\s*Listen' /etc/apache2/ | sort
# RHEL: grep -rn '^\s*Listen' /etc/httpd/

3. Clear stale processes and restart

Kill leftovers, then start through systemd so tracking is correct.

ps aux | grep [a]pache2
sudo pkill -f apache2   # or httpd
sudo systemctl start apache2

4. Move Apache if the other service should keep the port

When nginx fronts the machine and proxies to Apache, bind Apache elsewhere.

# /etc/apache2/ports.conf
Listen 127.0.0.1:8080
# and match the vhost:
<VirtualHost 127.0.0.1:8080>

Frequently Asked Questions

The error says the conflict is with Apache itself — how?

A duplicate Listen for the same port makes the second bind fail after the first succeeded — Apache collides with its own earlier directive. Keep Listen lines only in ports.conf (Debian) or httpd.conf (RHEL), never inside vhost files.

How do Apache and nginx share one server?

One of them takes 80/443 and reverse-proxies to the other on a local port. The common pattern is nginx in front (static/TLS) with Apache on 127.0.0.1:8080 for legacy apps — set Listen and the vhost accordingly, and keep mod_remoteip configured so Apache logs real client IPs.

What is AH00451?

'no listening sockets available, shutting down' — the follow-up line meaning every Listen failed. It is the consequence, not a separate problem: fix the AH00072 bind conflicts above it and AH00451 disappears.
