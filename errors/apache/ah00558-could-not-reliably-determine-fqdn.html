Apache AH00558 — Could Not Reliably Determine FQDN

Last updated: July 2, 2026

The startup message 'AH00558: apache2: Could not reliably determine the server's fully qualified domain name' — Apache has no ServerName and is guessing.

You might see this error as:

  • AH00558: apache2: Could not reliably determine the server's fully qualified domain name
  • ah00558
  • apache could not reliably determine fqdn
  • apache servername warning
  • using 127.0.1.1 set the servername directive globally

What Does This Error Mean?

At startup, Apache wants to know its own hostname to build self-referential URLs and default vhost behavior. Without a ServerName directive, it asks the operating system, and when that returns only 127.0.1.1 or an unresolvable name, Apache prints AH00558 and carries on using the IP. It is a warning, not a failure — the server runs — but it pollutes every restart log, breaks tools that treat stderr output as failure, and hints that redirects Apache generates may use an IP instead of your domain.

Common Causes

  • No ServerName directive anywhere — Fresh installs ship without a global ServerName. Apache falls back to reverse-resolving the host's IP, which on typical cloud/container hosts yields nothing useful.
  • Hostname does not resolve — The machine's hostname is not in /etc/hosts or DNS, so Apache's lookup chain lands on 127.0.1.1 (the message names the address it settled for).
  • Containers with random hostnames — Docker containers get generated hostnames that resolve nowhere, so containerized Apache prints AH00558 on every start unless ServerName is set in the image config.

How to Fix It

1. Set a global ServerName

One line in the main config (or a small conf snippet) silences it for good. Use your real domain, or localhost for dev boxes.

# Debian/Ubuntu:
echo 'ServerName example.com' | sudo tee /etc/apache2/conf-available/servername.conf
sudo a2enconf servername
sudo apachectl configtest && sudo systemctl reload apache2

# RHEL-family: add 'ServerName example.com' to /etc/httpd/conf/httpd.conf

2. Or make the hostname resolvable

If you prefer fixing the OS side, map the hostname in /etc/hosts.

hostnamectl   # see the current hostname
echo '127.0.0.1 myserver' | sudo tee -a /etc/hosts

3. Verify the warning is gone

configtest triggers the same code path, so you can confirm without restarting.

sudo apachectl configtest
# want: 'Syntax OK' with no AH00558 line

Frequently Asked Questions

Is AH00558 breaking anything or just noise?

Apache serves traffic fine. The practical costs: log noise on every restart, self-referential redirects possibly using an IP or wrong name (matters with UseCanonicalName On), and health-check scripts that misread the stderr line as an error. Two minutes to fix, so fix it.

Global ServerName vs the one in my VirtualHost — do both matter?

Yes, they do different jobs. The global one identifies the server itself and silences AH00558. The per-VirtualHost ServerName decides which vhost answers which Host header — that one you already need for name-based hosting.

Why does the message name 127.0.1.1?

Debian-family systems map the machine's hostname to 127.0.1.1 in /etc/hosts. When Apache can find nothing better, that is the address its resolution chain produces — the message is telling you which fallback it chose.
