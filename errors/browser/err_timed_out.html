ERR_TIMED_OUT

Last updated: March 8, 2026

This error means Chrome waited too long for the server to respond and gave up. The server is either overloaded, unreachable, or blocked by a firewall.

You might see this error as:

  • net::ERR_TIMED_OUT
  • ERR_TIMED_OUT Chrome
  • This site can't be reached
  • Connection timed out
  • took too long to respond
  • Request timeout

What Does This Error Mean?

ERR_TIMED_OUT occurs when a network request does not complete within Chrome's timeout window. The browser established (or began establishing) a connection but the server did not send a response in time.

This can happen at different stages: the DNS lookup may succeed, the TCP connection may open, but the server simply never sends data back. Unlike ERR_CONNECTION_REFUSED — where the server actively rejects the connection — a timeout means the server silently stopped responding.

Common Causes

  • Server is overloaded — too many simultaneous requests are queuing up, causing slow or no responses.
  • Server is down — the server process has crashed or the machine is offline.
  • Firewall dropping packets — a firewall is silently discarding traffic without sending a rejection.
  • Slow network — high latency or packet loss causing slow response times.
  • Large page or slow response — a page with slow database queries or expensive server-side processing.
  • Geographic distance — connecting to a server on the other side of the world with high round-trip latency.
  • VPN or proxy adding latency — routing traffic through a distant VPN endpoint.
  • Port blocked by ISP — your ISP may block certain ports, causing connections to time out.

📡 Them or you? Before changing anything, check the live cloud & SaaS outage monitor — during a provider incident this error shows up on perfectly healthy setups, and the fix is to wait.

How to Fix It

1. Reload the Page

A temporary server spike may resolve itself. Try reloading with Ctrl+R or F5. If it loads intermittently, the server is under heavy load.

2. Check Your Internet Connection

Ensure you have a working connection by loading another site. Run a speed test to check for high latency or packet loss.

3. Try the Site From Another Network

Switch to mobile data or a different Wi-Fi network. If the site loads on another network, the issue may be with your ISP or router.

4. Check If the Site Is Down for Everyone

Use the HTTP Latency tool to test whether the server is responding. If response times are very high or there is no response, the server itself has a problem.

5. Flush DNS and Clear Browser Cache

Stale DNS entries can sometimes route traffic to a dead server IP. Flush your DNS cache and clear your browser cache, then retry.

6. Disable VPN or Proxy

If you are using a VPN, try disabling it. VPN endpoints can add significant latency or drop connections.

7. Check Firewall Rules (for Server Owners)

Verify your server's firewall allows inbound connections on the relevant port (80 for HTTP, 443 for HTTPS). Check that iptables or cloud security group rules are not dropping packets.

Frequently Asked Questions

How long does Chrome wait before showing ERR_TIMED_OUT?

Chrome's default connection timeout is approximately 30 seconds, though this can vary. For keep-alive connections with no data received, the timeout can be longer. The value is not user-configurable in standard Chrome settings.

ERR_TIMED_OUT vs. 504 Gateway Timeout — what is the difference?

A 504 Gateway Timeout is a server-side HTTP response — a gateway received no response from an upstream server and returned 504 to the browser. ERR_TIMED_OUT is a browser-side timeout — Chrome gave up waiting before any HTTP response arrived.

Can a firewall cause ERR_TIMED_OUT?

Yes. A firewall that drops packets without sending a rejection (TCP RST) causes the connection to silently hang until the browser times out. A firewall that actively rejects connections sends a TCP RST, which produces ERR_CONNECTION_REFUSED instead.

Related Errors

  • 504 Gateway Timeout — gateway timed out waiting for upstream server.
  • 408 Request Timeout — server timed out waiting for client request.
  • ERR_CONNECTION_REFUSED — server actively rejected the connection.
  • ERR_INTERNET_DISCONNECTED — no network connection.
