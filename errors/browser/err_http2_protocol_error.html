ERR_HTTP2_PROTOCOL_ERROR

Last updated: March 8, 2026

HTTP/2 protocol error encountered by the browser

You might see this error as:

  • net::ERR_HTTP2_PROTOCOL_ERROR
  • ERR_HTTP2_PROTOCOL_ERROR Chrome
  • HTTP/2 protocol error
  • ERR_SPDY_PROTOCOL_ERROR
  • This page isn't working

What Does This Error Mean?

ERR_HTTP2_PROTOCOL_ERROR occurs when the browser detects a violation of the HTTP/2 protocol during communication with the server. This can happen when the server sends malformed frames, resets streams unexpectedly, or violates flow control rules defined in the HTTP/2 specification. The error is common with misconfigured reverse proxies, CDNs, or servers that have incomplete HTTP/2 implementations.

Common Causes

  • Malformed HTTP/2 frames from server — The server or an intermediary proxy is sending HTTP/2 frames that violate the protocol specification, such as incorrect frame sizes or invalid header compression.
  • Reverse proxy or CDN misconfiguration — A reverse proxy like Nginx or a CDN is incorrectly translating between HTTP/1.1 and HTTP/2, resulting in protocol violations that the browser cannot process.
  • Response body exceeds Content-Length — The server is sending more data than declared in the Content-Length header, which causes the HTTP/2 stream to be terminated with a protocol error.
  • Server-side HTTP/2 implementation bugs — The web server software has bugs in its HTTP/2 implementation, particularly around stream management, priority handling, or HPACK header compression.
  • Network middlebox interference — Firewalls, antivirus software, or network appliances are modifying HTTP/2 traffic in ways that corrupt the binary framing layer.

How to Fix It

1. Disable HTTP/2 on the server temporarily

If you control the server, disable HTTP/2 to confirm it is the source of the issue. For Nginx, remove the 'http2' parameter from the listen directive and reload the configuration.

# Nginx: change
listen 443 ssl http2;
# to
listen 443 ssl;

2. Update server software

Ensure your web server (Nginx, Apache, Caddy) and any reverse proxy software are running the latest stable versions, as HTTP/2 implementation bugs are frequently fixed in updates.

3. Clear browser state and retry

Close all browser tabs to the affected site, clear the browser's socket pools by navigating to chrome://net-internals/#sockets and clicking 'Flush socket pools', then retry the request.

4. Check proxy and CDN configuration

If using a CDN or reverse proxy, verify that HTTP/2 settings are consistent between the edge and origin. Some CDNs require specific origin configurations to avoid protocol translation issues.

Frequently Asked Questions

Is ERR_HTTP2_PROTOCOL_ERROR a client-side or server-side problem?

It is almost always a server-side or network infrastructure problem. The browser is correctly detecting that the HTTP/2 protocol rules are being violated by the server or an intermediary.

Does this error mean HTTP/2 is broken on my browser?

No. The browser's HTTP/2 implementation is well-tested. This error means the specific server you are connecting to is sending invalid HTTP/2 data. Other HTTP/2 sites will work fine.

Can browser extensions cause this error?

Extensions that modify network requests can occasionally trigger this error by interfering with HTTP/2 streams. Try loading the page in incognito mode with extensions disabled to rule this out.
