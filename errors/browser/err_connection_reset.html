ERR_CONNECTION_RESET

Last updated: March 8, 2026

This error means your browser established a connection to the server but the connection was suddenly closed before any data was transferred. Here is what causes it and how to fix it.

You might see this error as:

  • net::ERR_CONNECTION_RESET
  • ERR_CONNECTION_RESET Chrome
  • This site can't be reached
  • The connection was reset
  • Connection reset by peer
  • ECONNRESET

How the Request Flow Works

What Does This Error Mean?

When your browser connects to a web server, it first performs a TCP handshake to establish the connection. ERR_CONNECTION_RESET occurs when this connection is abruptly terminated after being established — the server (or something between you and the server) sent a TCP RST (reset) packet, forcing the connection closed.

This is different from ERR_CONNECTION_REFUSED (where the server never accepted the connection) or a timeout (where the connection simply went unanswered). A reset is an active termination of an established connection.

Common Causes

  • Firewall or antivirus interference — security software may be inspecting and blocking the connection mid-transfer.
  • VPN or proxy dropping connections — some VPN configurations close connections due to routing or protocol issues.
  • ISP-level filtering — your ISP may be using deep packet inspection (DPI) to block certain traffic.
  • Unstable network connection — packet loss or a flaky Wi-Fi connection can cause connections to reset.
  • Server misconfiguration — the server may be configured to close idle connections too aggressively, or have a load balancer that drops connections.
  • Browser extension conflicts — some extensions intercept and modify traffic in ways that cause resets.
  • TLS/SSL mismatch — a cipher suite or protocol version mismatch can cause a reset during the SSL handshake.
  • Proxy server errors — a misconfigured proxy may establish and then immediately close connections.

How to Fix It

1. Reload the Page

Sometimes the error is transient. Press Ctrl+F5 (or Cmd+Shift+R on Mac) for a hard reload that bypasses the browser cache.

2. Disable VPN or Proxy

If you are using a VPN or proxy, temporarily disable it and try again. Many VPN clients cause connection resets due to routing issues or DNS leaks.

3. Flush DNS Cache and Reset Network Settings

On Windows, open Command Prompt as administrator and run:

ipconfig /flushdns
netsh int ip reset
netsh winsock reset

Restart your computer after running these commands.

4. Disable Firewall or Antivirus Temporarily

Test whether your security software is the cause by temporarily disabling it and trying the site again. If the error disappears, check your security software's HTTPS inspection or traffic filtering settings.

5. Try Incognito Mode or a Different Browser

Open an incognito/private window to disable extensions. If the error does not appear there, a browser extension is likely the cause. Try disabling extensions one by one to identify the culprit.

6. Try a Different Network

Switch to mobile data or a different Wi-Fi network. If the error disappears, your ISP or router may be causing the issue.

7. Check the Server's HTTP Headers

Use the HTTP Latency Checker to verify the server is responding correctly. If it times out or returns an error, the problem may be server-side.

Frequently Asked Questions

Is ERR_CONNECTION_RESET the same as a refused connection?

No. A refused connection (ERR_CONNECTION_REFUSED) means the server never accepted the TCP connection — the port is closed or no service is listening. A reset means the connection was established but then forcibly terminated. They have different causes and require different troubleshooting steps.

Can ERR_CONNECTION_RESET be caused by the website itself?

Yes. If the server has a misconfigured load balancer, aggressive connection timeouts, or a TLS configuration issue, it may reset connections before completing the handshake. If the error occurs consistently on one site but not others, the problem is likely on the server's end.

Does this error mean my connection is being monitored?

Not necessarily, but ISP-level DPI (deep packet inspection) or a firewall that inspects HTTPS traffic can cause this error. If you are on a corporate or school network, IT policies may be blocking the connection.

Related Errors

  • ERR_CONNECTION_REFUSED — the server rejected the connection before it was established.
  • DNS_PROBE_FINISHED_NXDOMAIN — the domain could not be resolved at all.
  • ERR_SSL_PROTOCOL_ERROR — SSL handshake failed after connection was made.
