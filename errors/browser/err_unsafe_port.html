ERR_UNSAFE_PORT

Last updated: March 8, 2026

Connection blocked because the port number is restricted by the browser

You might see this error as:

  • net::ERR_UNSAFE_PORT
  • ERR_UNSAFE_PORT Chrome
  • Unsafe port blocked
  • Port blocked by browser

What Does This Error Mean?

ERR_UNSAFE_PORT occurs when the browser blocks a connection to a port number that is on its restricted ports list. Browsers maintain a blocklist of ports associated with non-HTTP services (such as FTP, SMTP, POP3, and other protocols) to prevent web pages from abusing these services through cross-protocol attacks. Even if a legitimate HTTP server is running on one of these ports, the browser will refuse to connect.

Common Causes

  • Server running on a restricted port — The web server or application is configured to listen on a port that browsers consider unsafe, such as port 25 (SMTP), 110 (POP3), 143 (IMAP), or other service-specific ports.
  • Development server using a blocked port — A local development server was started on a port that happens to be on the browser's restricted list, such as port 6000 (X11), port 6665-6669 (IRC), or port 2049 (NFS).
  • URL pointing to non-standard port — A link or redirect is pointing to a URL with an explicitly specified port that is on the browser's blocklist, even though the server may be serving valid HTTP content.

How to Fix It

1. Change the server port

Configure your server to use a port that is not on the browser's restricted list. Common safe ports for HTTP include 3000, 4000, 5000, 8000, 8080, 8443, and 9000.

2. Override blocked port in Chrome (development only)

For development purposes only, you can launch Chrome with a flag to allow a specific restricted port. Do not use this in production.

# Launch Chrome allowing a specific port
chrome.exe --explicitly-allowed-ports=6000

3. Use a reverse proxy

If you cannot change the backend port, set up a reverse proxy (like Nginx) that listens on a standard port (80 or 443) and forwards requests to the restricted port internally.

# Nginx reverse proxy to restricted port
server {
    listen 8080;
    location / {
        proxy_pass http://localhost:6000;
    }
}

Frequently Asked Questions

Which ports does Chrome block?

Chrome blocks dozens of ports associated with non-HTTP services, including 1 (tcpmux), 7 (echo), 21 (FTP), 22 (SSH), 25 (SMTP), 110 (POP3), 143 (IMAP), 6000 (X11), 6665-6669 (IRC), and many others. The full list is in Chrome's source code.

Why does Chrome block certain ports?

To prevent cross-protocol attacks where a malicious web page tricks the browser into sending HTTP requests to non-HTTP services. For example, a page could try to send commands to an SMTP server to relay spam.

Does this error affect localhost development?

Yes, the port restriction applies to all connections including localhost. If your development server uses a restricted port, change it to a common development port like 3000, 8080, or 5173.
