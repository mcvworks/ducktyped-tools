ERR_ABORTED

Last updated: March 8, 2026

Network request was aborted before completion

You might see this error as:

  • net::ERR_ABORTED
  • ERR_ABORTED 403
  • ERR_ABORTED 404
  • Failed to load resource: net::ERR_ABORTED
  • ERR_ABORTED Chrome

What Does This Error Mean?

ERR_ABORTED occurs when a network request is cancelled before it completes. Unlike connection errors where the network fails, an aborted request means something actively stopped the request. This can be the browser itself (during navigation), the page's JavaScript code, a browser extension, or a Content Security Policy violation. It is one of the most common network errors and often does not indicate a real problem.

Common Causes

  • Page navigation during loading — The user navigated away from the page or clicked a link while resources were still loading. The browser aborts all pending requests for the previous page as part of normal behavior.
  • JavaScript cancelling the request — Client-side JavaScript explicitly cancelled the request using AbortController, XMLHttpRequest.abort(), or by navigating the page programmatically before the request completed.
  • Browser extension blocking the request — An ad blocker, privacy extension, or security extension is intercepting and blocking the network request based on its filter rules.
  • Content Security Policy violation — The page's Content-Security-Policy header blocks the request because the resource's origin is not listed in the allowed sources for its resource type.
  • Duplicate request deduplication — The browser detected that the same resource is being requested multiple times and aborted the duplicate requests as an optimization.

How to Fix It

1. Check browser extensions

Disable browser extensions, especially ad blockers and privacy tools, then reload the page. If the error disappears, re-enable extensions one by one to identify the culprit.

2. Check the browser console for CSP violations

Open DevTools (F12), go to the Console tab, and look for Content Security Policy violation messages. These indicate which resources are being blocked and which CSP directive is responsible.

// In DevTools Console, look for messages like:
// Refused to load the script 'https://...' because it
// violates the following Content Security Policy directive: ...

3. Verify the request is not being cancelled by code

In DevTools Network tab, filter by the errored request and check the Initiator column. If JavaScript is cancelling the request, review the code at that location for AbortController or abort() calls.

4. Wait for page to fully load

If the error occurs during navigation, simply wait for the new page to finish loading. ERR_ABORTED during navigation is expected browser behavior and not a real error.

Frequently Asked Questions

Is ERR_ABORTED always a problem?

No. ERR_ABORTED is normal during page navigation. The browser cancels in-flight requests for the old page. It is only a problem if it prevents a resource from loading on the current page.

Why do I see ERR_ABORTED in the DevTools Network tab?

DevTools records all network activity including cancelled requests. Many ERR_ABORTED entries are harmless, caused by normal navigation or intentional cancellation by the page's JavaScript.

Can server-side issues cause ERR_ABORTED?

Rarely. ERR_ABORTED is almost always caused by client-side actions. If the server resets the connection, you would see ERR_CONNECTION_RESET instead.
