ERR_CONNECTION_TIMED_OUT

Last updated: March 8, 2026

Connection attempt to the server timed out before completing

You might see this error as:

  • net::ERR_CONNECTION_TIMED_OUT
  • ERR_CONNECTION_TIMED_OUT Chrome
  • This site can't be reached
  • took too long to respond
  • Connection timed out
  • ETIMEDOUT

What Does This Error Mean?

ERR_CONNECTION_TIMED_OUT occurs when the browser's attempt to establish a TCP connection with the server does not receive a response within the timeout period (typically 30 seconds). Unlike ERR_CONNECTION_REFUSED where the server actively rejects the connection, a timeout means the connection request received no response at all. This indicates the server is not responding, packets are being dropped, or a firewall is silently blocking the connection.

Common Causes

  • Server is overloaded — The server is under heavy load and cannot accept new TCP connections within the timeout period. Its connection backlog queue is full, causing new connection attempts to be silently dropped.
  • Firewall silently dropping packets — A firewall between the client and server is configured to DROP (not REJECT) packets to the destination port, causing the connection to hang until it times out rather than receiving an immediate refusal.
  • Server is down but IP is routable — The server machine is powered on and its IP is routable, but the web server process is not running or not listening on the expected port.
  • Network congestion or packet loss — Severe network congestion between the client and server is causing SYN packets to be dropped, preventing the TCP three-way handshake from completing.
  • Incorrect port or IP configuration — The DNS records or URL point to the correct server but the wrong port, or the server is listening on a different interface than expected.

📡 Them or you? Before changing anything, check the live cloud & SaaS outage monitor — during a provider incident this error shows up on perfectly healthy setups, and the fix is to wait.

How to Fix It

1. Check if the server is responding

Use an external service or different network to confirm whether the server is responding to anyone. If it is only timing out for you, the issue is with your network path.

# Test connection with timeout
curl -m 10 -v https://example.com

2. Verify firewall rules

Check firewall rules on both the server and client side. Ensure the destination port (typically 80 or 443) is allowed through all firewalls on the network path.

3. Check server resource usage

If you have server access, check CPU, memory, and connection counts. A server at capacity will stop accepting new connections.

# Check connection counts
ss -s
# Check resource usage
top

4. Flush DNS and try alternate DNS

Clear your local DNS cache and try using a different DNS server in case stale DNS records are pointing to an unresponsive IP.

# Windows
ipconfig /flushdns
# Linux
sudo systemd-resolve --flush-caches

Frequently Asked Questions

What is the difference between ERR_CONNECTION_TIMED_OUT and ERR_TIMED_OUT?

ERR_CONNECTION_TIMED_OUT specifically refers to the TCP connection attempt timing out (before any data is exchanged). ERR_TIMED_OUT can refer to the overall request timing out, including waiting for a response after the connection was established.

How long does the browser wait before timing out?

Chrome typically waits about 30 seconds for a TCP connection to be established. This value is built into the browser and cannot be changed by the user.
