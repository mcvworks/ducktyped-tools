ERR_CONTENT_LENGTH_MISMATCH

Last updated: March 8, 2026

Content-Length header does not match the actual response body size

You might see this error as:

  • net::ERR_CONTENT_LENGTH_MISMATCH
  • ERR_CONTENT_LENGTH_MISMATCH
  • Content length mismatch
  • Incomplete response body

What Does This Error Mean?

ERR_CONTENT_LENGTH_MISMATCH occurs when the number of bytes in the response body does not match the value specified in the Content-Length header. The browser expects to receive exactly the number of bytes declared, and terminates the connection when there is a discrepancy. This usually indicates a server-side misconfiguration, particularly with compression, caching, or reverse proxy setups.

Common Causes

  • Compression applied after Content-Length was set — The server or a reverse proxy compresses the response body with gzip or Brotli after the Content-Length header was already calculated for the uncompressed body, creating a mismatch.
  • Reverse proxy modifying the response body — A reverse proxy or CDN is rewriting parts of the response (such as injecting scripts or modifying URLs) without updating the Content-Length header to reflect the new body size.
  • Server sending partial response — The server process terminates or crashes before sending the complete response body, resulting in fewer bytes delivered than the Content-Length header promised.
  • Caching layer serving stale content — A caching layer is serving a cached response body with a Content-Length header from a different version of the content, where the sizes no longer match.

How to Fix It

1. Use chunked transfer encoding instead

Configure the server to use Transfer-Encoding: chunked instead of Content-Length. This avoids the mismatch by not declaring the body size upfront.

# Nginx: disable buffering to use chunked encoding
proxy_buffering off;

2. Fix compression configuration

Ensure that compression is applied before the Content-Length header is set, or remove the Content-Length header when compression is enabled. In Nginx, gzip automatically removes Content-Length when active.

3. Clear proxy and CDN caches

Purge all cached responses from your reverse proxy and CDN to ensure stale Content-Length values from previous response versions are not being served.

4. Check for response body modifications

Audit your reverse proxy configuration for any directives that modify the response body (sub_filter in Nginx, mod_substitute in Apache) and ensure they also update the Content-Length header.

Frequently Asked Questions

Why does ERR_CONTENT_LENGTH_MISMATCH only happen with certain files?

It typically affects files that go through compression or proxy rewriting. Static files served directly may work fine while dynamically generated or proxied responses trigger the error.

Can this error cause partial page loads?

Yes. If the browser receives more data than expected, it truncates the response. If it receives less, the page may appear incomplete or broken before the error is shown.

Is this error related to CORS?

No, this error is purely about the mismatch between the declared and actual response body size. CORS errors are related to cross-origin request permissions and produce different error messages.
