ERR_TOO_MANY_REDIRECTS

Last updated: March 8, 2026

This error means the page entered an infinite redirect loop. The browser followed too many redirects without reaching a final destination and stopped to prevent endless looping.

You might see this error as:

  • ERR_TOO_MANY_REDIRECTS
  • This page isn't working
  • Redirected you too many times
  • Too many redirects
  • Redirect loop
  • Infinite redirect loop

What Does This Error Mean?

An HTTP redirect (status codes 301, 302, 307, 308) sends the browser from one URL to another. This is normal for HTTP-to-HTTPS redirects, trailing slash normalization, or domain canonicalization. However, when redirect rules are misconfigured, they can create a loop — URL A redirects to URL B, which redirects back to URL A, which redirects to URL B, and so on.

Browsers allow a maximum number of redirects (typically 20) before giving up and displaying ERR_TOO_MANY_REDIRECTS. This protects against infinite loops consuming bandwidth and server resources.

Common Causes

  • HTTPS redirect loop — the server redirects HTTP to HTTPS, but the CDN or proxy sends HTTPS requests back as HTTP to the origin, creating a loop.
  • WordPress misconfiguration — the WordPress Address (URL) and Site Address (URL) settings do not match, causing login or page redirect loops.
  • Cloudflare SSL mode mismatch — using Cloudflare's "Flexible" SSL while the origin server also forces HTTPS creates an infinite loop.
  • Browser cookies — stale cookies may contain redirect logic or session data that triggers incorrect redirects.
  • Conflicting .htaccess rules — multiple redirect rules in Apache's .htaccess file that conflict with each other.
  • Plugin conflicts — WordPress or CMS plugins that add redirect logic can conflict with server-level redirects.
  • Load balancer or reverse proxy misconfiguration — redirect rules at the load balancer level that conflict with the origin server's rules.

How to Fix It

1. Clear Browser Cookies for the Site

Stale cookies can cause redirect loops. Clear them specifically for the affected domain:

  • Chrome: Open DevTools → Application tab → Cookies → right-click the domain → Clear
  • Or open an Incognito window to test without cookies

2. Inspect the Redirect Chain

Use the Redirect Checker tool to trace the exact redirect chain. This will show you every hop and reveal where the loop occurs.

3. Fix Cloudflare SSL Mode (Most Common CDN Cause)

If you use Cloudflare and have HTTPS forced on your origin server, set Cloudflare's SSL mode to Full (Strict) rather than "Flexible":

  1. Go to Cloudflare Dashboard → SSL/TLS
  2. Change the SSL mode from Flexible to Full or Full (Strict)

Flexible SSL means Cloudflare connects to your origin over HTTP, but your server redirects that to HTTPS — creating a loop.

4. Fix WordPress URL Settings

If you manage a WordPress site, check and align these settings:

  1. Log in to wp-admin → Settings → General
  2. Ensure WordPress Address (URL) and Site Address (URL) both use the same protocol (both https://)
  3. Or set them directly in wp-config.php:
define('WP_HOME','https://yourdomain.com');
define('WP_SITEURL','https://yourdomain.com');

5. Review .htaccess Rules

Check your Apache .htaccess file for conflicting redirect rules. A common mistake is having both a redirect-to-HTTPS rule and another rule that catches all HTTPS traffic and redirects again:

# Ensure this condition prevents looping:
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

6. Check nginx Configuration

In nginx, look for conflicting return or rewrite directives across server blocks that redirect to each other.

Frequently Asked Questions

Why does this only happen in my browser but not for others?

Cookies are the most common reason. The redirect loop is being triggered by a stale session cookie in your browser. Clear cookies for the site or test in a private/incognito window.

Why does clearing cache not fix it?

Clearing the browser cache removes cached files but not cookies. Redirect loops are almost always caused by redirect rules or cookies, not cached page content. Clear cookies separately.

Can plugins cause redirect loops?

Yes. WordPress plugins that handle SSL, caching, or SEO redirects can conflict with server-level redirect rules. Try disabling plugins one by one (especially SSL or redirect plugins) to identify the conflict.

Related Errors

  • 404 Not Found — page does not exist (redirect destination missing).
  • ERR_SSL_PROTOCOL_ERROR — SSL issue that sometimes accompanies HTTPS redirect problems.
  • ERR_CONNECTION_RESET — connection dropped instead of redirected.
