ERR_FAILED

Last updated: March 8, 2026

Generic network failure with no specific error code

You might see this error as:

  • net::ERR_FAILED
  • ERR_FAILED Chrome
  • ERR_FAILED download
  • Failed to load resource
  • Network error ERR_FAILED

What Does This Error Mean?

ERR_FAILED is a generic catch-all error that Chrome and other Chromium-based browsers display when a network request fails and no more specific error code applies. Because it is a generic error, the underlying cause can vary widely. Diagnosing ERR_FAILED requires investigating the specific request in the browser's DevTools Network tab to determine what type of failure occurred, such as CORS violations, mixed content blocks, or service worker failures.

Common Causes

  • CORS (Cross-Origin Resource Sharing) violation — The server does not include the required Access-Control-Allow-Origin header in the response, causing the browser to block the cross-origin request and report a generic failure.
  • Service worker failure — A registered service worker intercepted the request but failed to provide a valid response, either by throwing an error or returning a malformed Response object.
  • Mixed content blocked in strict mode — The browser blocked an HTTP request from an HTTPS page because the site's upgrade-insecure-requests or block-all-mixed-content CSP directive prevented the insecure load.
  • Browser feature policy restriction — A Permissions-Policy or Feature-Policy header on the page restricts certain capabilities, and the blocked feature triggered a generic network failure.
  • Network adapter or driver issue — A low-level network adapter or driver problem is causing intermittent connection failures that do not map to a more specific error code.

How to Fix It

1. Check DevTools Console for details

Open DevTools (F12) and check the Console tab for more specific error messages. CORS violations, CSP blocks, and mixed content warnings will have detailed explanations in the console.

2. Fix CORS headers on the server

If the console shows a CORS error, add the appropriate Access-Control-Allow-Origin header to the server's response for the requested resource.

# Nginx: Add CORS header
add_header Access-Control-Allow-Origin "https://your-site.com";
add_header Access-Control-Allow-Methods "GET, POST, OPTIONS";

3. Check and update service workers

In DevTools, go to Application > Service Workers and check if a service worker is registered. Try unregistering it and reloading the page to see if the error resolves.

4. Reset network stack

Reset your network configuration to clear any corrupted state that may be causing generic failures.

# Windows: Reset network stack
netsh winsock reset
netsh int ip reset
ipconfig /flushdns

Frequently Asked Questions

Why doesn't the browser give a more specific error?

ERR_FAILED is used when the failure does not fit into a more specific category, or when providing details might leak security-sensitive information (such as with CORS violations).

Is ERR_FAILED the same as a network being down?

No. If the network were completely down, you would see ERR_INTERNET_DISCONNECTED or ERR_NAME_NOT_RESOLVED. ERR_FAILED means the network is functioning but a specific request failed for a non-network reason.

Can ERR_FAILED be caused by the website itself?

Yes, commonly. CORS misconfigurations, service worker bugs, and CSP issues are all website-side problems that cause ERR_FAILED for the visitor.
