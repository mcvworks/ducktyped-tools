ERR_EMPTY_RESPONSE

Last updated: March 8, 2026

Server closed the connection without sending any data

You might see this error as:

  • net::ERR_EMPTY_RESPONSE
  • ERR_EMPTY_RESPONSE Chrome
  • No data received
  • Empty response from server
  • This page isn't working
  • didn't send any data

What Does This Error Mean?

ERR_EMPTY_RESPONSE occurs when the browser successfully establishes a TCP connection to the server, but the server closes the connection without sending any HTTP response data. This means the server accepted the connection but then immediately disconnected, providing no status code, headers, or body. It often indicates server-side crashes, resource exhaustion, or firewall rules that terminate connections after they are established.

Common Causes

  • Server application crash on request — The server-side application crashes or throws an unhandled exception when processing the request, causing the process to terminate before any response is written to the connection.
  • Server resource exhaustion — The server has run out of memory, file descriptors, or worker threads and cannot process the request. It accepts the TCP connection but cannot allocate resources to generate a response.
  • Firewall or security rule dropping the connection — A firewall rule, WAF, or rate limiter is allowing the TCP handshake but then dropping the connection before the server can respond, typically based on request content inspection.
  • Misconfigured SSL/TLS on the server — The server expects a plain HTTP connection but receives HTTPS (or vice versa), causing it to close the connection because it cannot parse the incoming data.
  • Backend timeout in reverse proxy — A reverse proxy connected to the backend server, but the backend did not respond within the configured timeout, and the proxy closed the connection without sending an error page.

How to Fix It

1. Check server logs for crashes

Review server application logs, web server error logs, and system logs (dmesg, journalctl) for out-of-memory kills, segmentation faults, or unhandled exceptions occurring at the time of the error.

2. Verify the correct protocol (HTTP vs HTTPS)

Ensure you are using the correct protocol. Try accessing the URL with both http:// and https:// to determine if the server is configured for the protocol you are using.

3. Increase server resources and timeouts

If the server is under load, increase worker processes, memory limits, and connection timeouts. Monitor server resource usage to identify bottlenecks.

# Nginx: increase worker connections
worker_connections 2048;

# Increase proxy timeout
proxy_read_timeout 120s;

4. Clear browser DNS and socket caches

Navigate to chrome://net-internals/#dns and click 'Clear host cache', then go to chrome://net-internals/#sockets and click 'Flush socket pools'. Retry the request.

Frequently Asked Questions

Is ERR_EMPTY_RESPONSE the same as a blank page?

No. A blank page means the server sent a valid HTTP response with an empty body. ERR_EMPTY_RESPONSE means the server sent absolutely nothing — not even HTTP headers or a status code.

Can VPN software cause ERR_EMPTY_RESPONSE?

Yes. VPN software can sometimes interfere with connections, especially when switching networks or when the VPN tunnel drops momentarily during a request.

Why do I only see this error on one specific website?

The issue is specific to that server. It is likely experiencing application errors, resource exhaustion, or configuration problems that prevent it from responding to requests.
