ERR_INSECURE_RESPONSE

Last updated: March 8, 2026

Response was delivered over an insecure connection

You might see this error as:

  • net::ERR_INSECURE_RESPONSE
  • ERR_INSECURE_RESPONSE Chrome
  • Insecure response
  • Mixed content blocked

What Does This Error Mean?

ERR_INSECURE_RESPONSE occurs when the browser blocks a response because the SSL/TLS connection does not meet the browser's security requirements. This can happen when the server's certificate is invalid, self-signed, expired, or when the connection was downgraded from HTTPS to HTTP. The browser refuses to load the content to protect against man-in-the-middle attacks and data interception.

Common Causes

  • Self-signed or untrusted SSL certificate — The server is using a self-signed certificate or one signed by a certificate authority that is not in the browser's trusted root certificate store.
  • Expired SSL certificate — The server's SSL certificate has passed its expiration date and the browser no longer trusts it, blocking the response as insecure.
  • Mixed content blocked — An HTTPS page is attempting to load resources (scripts, stylesheets, or API calls) over plain HTTP, and the browser is blocking these insecure sub-requests.
  • Certificate hostname mismatch — The SSL certificate's Common Name (CN) or Subject Alternative Names (SAN) do not match the domain being accessed, causing the browser to treat the connection as insecure.

How to Fix It

1. Install a valid SSL certificate

Replace self-signed or expired certificates with a valid certificate from a trusted Certificate Authority. Let's Encrypt provides free certificates that are trusted by all major browsers.

# Install certbot and obtain a free certificate
certbot certonly --webroot -w /var/www/html -d example.com

2. Fix mixed content issues

Update all resource URLs on your HTTPS pages to use https:// instead of http://. Use Content-Security-Policy headers to enforce HTTPS and identify mixed content.

3. Verify certificate hostname matches

Ensure the SSL certificate covers the exact domain being accessed, including www and non-www variants. Use SAN certificates to cover multiple domain names.

4. Check system clock

An incorrect system clock can cause valid certificates to appear expired or not-yet-valid. Verify that your computer's date and time are set correctly and synced with a time server.

Frequently Asked Questions

Can I bypass ERR_INSECURE_RESPONSE?

In some cases you can proceed past the warning, but this is not recommended as it exposes you to potential data interception. For development, you can add a self-signed certificate to your system's trusted store.

Why did this error appear suddenly on a site that worked before?

The most common cause is an expired SSL certificate. Certificates have a limited validity period (typically 90 days to 1 year) and must be renewed before expiration.
