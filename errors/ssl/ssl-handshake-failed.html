SSL Handshake Failed

Last updated: March 8, 2026

SSL Handshake Failed means the browser and server could not complete TLS negotiation. No secure connection was established, so the browser blocks the page.

You might see this error as:

  • SSL handshake failed
  • TLS handshake failed
  • SSL handshake error
  • Handshake failure
  • SSL_ERROR_HANDSHAKE_FAILURE_ALERT
  • tlsv1 alert handshake failure

Where the Handshake Fails

What Does This Error Mean?

Every HTTPS connection begins with a TLS handshake — a sequence of messages where the client and server exchange cryptographic parameters, verify the server's certificate, and agree on an encryption method. If any step fails, the handshake fails and no data is exchanged.

Common browser messages for handshake failures include ERR_SSL_PROTOCOL_ERROR, ERR_SSL_VERSION_OR_CIPHER_MISMATCH, and SSL_ERROR_HANDSHAKE_FAILURE_ALERT in Firefox.

Common Causes

  • TLS version incompatibility — client and server do not share a supported TLS version.
  • No shared cipher suite — the client and server have no cipher in common.
  • Invalid or expired certificate — the server's certificate has expired, is self-signed, or has an invalid chain.
  • Missing intermediate certificate — server not sending the full certificate chain (root → intermediate → leaf).
  • Incorrect system time — if the client's clock is wrong, certificate validity dates will appear incorrect.
  • Certificate hostname mismatch — the certificate does not cover the hostname being accessed.
  • SNI not supported — very old clients or servers that do not support Server Name Indication.
  • Firewall or antivirus SSL inspection — security software interfering with the handshake.

How to Fix It

1. Check Your SSL Certificate

Use the SSL Checker to inspect the certificate chain, expiry, hostname coverage, and TLS configuration. A common issue is a missing intermediate certificate — the server must send the full chain from leaf to root.

2. Verify System Clock

Ensure your device's time and timezone are correct. Certificate validity checks are time-sensitive — an incorrect system clock causes valid certificates to appear expired or not yet valid.

3. Update TLS Configuration (Server Owners)

Ensure your server supports TLS 1.2 and TLS 1.3. Disable SSLv3, TLS 1.0, and TLS 1.1. Use a modern cipher suite list. Restart your web server after changes.

4. Install the Full Certificate Chain

Configure your web server to send intermediate certificates, not just the leaf certificate. Let's Encrypt certificates require the chain file to be configured.

5. Check Firewall and Security Software

Disable antivirus SSL scanning temporarily to test if it is interfering with the TLS handshake.

Frequently Asked Questions

Does SSL Handshake Failed affect all browsers equally?

Different browsers have different TLS policies. Chrome and Firefox have stricter minimum requirements than some other clients. An older browser may succeed where Chrome fails if the server only supports older TLS versions.

Can I be affected by SSL handshake failures without going to a problematic site?

Yes. Any HTTPS request — including those made by apps, OS update services, or background browser requests — can fail with a handshake error if the server does not meet modern TLS requirements.

Related Errors

  • ERR_SSL_PROTOCOL_ERROR — SSL protocol error.
  • ERR_SSL_VERSION_OR_CIPHER_MISMATCH — TLS version or cipher mismatch.
  • SSL Certificate Expired — certificate past its validity date.
  • NET::ERR_CERT_AUTHORITY_INVALID — untrusted certificate authority.
