NET::ERR_CERT_DATE_INVALID

Last updated: March 8, 2026

This error means the SSL certificate's validity dates do not match the current date — either the certificate has expired, or your device's clock is wrong.

You might see this error as:

  • NET::ERR_CERT_DATE_INVALID
  • Certificate date invalid
  • SSL certificate expired Chrome
  • Your connection is not private
  • Certificate not yet valid

What Does This Error Mean?

Every SSL certificate has a validity window: a Not Before date and a Not After date. Browsers check the current date against these values on every connection. NET::ERR_CERT_DATE_INVALID appears when the current date falls outside this window.

This most commonly means the certificate has expired, but it can also appear if your device's clock is set to the wrong date.

Causes

  • Certificate expired — the certificate's Not After date is in the past.
  • Certificate not yet valid — the certificate's Not Before date is in the future (rare, but can happen with pre-issued certificates or a wrong system clock).
  • Wrong system clock — the device's date/time is set incorrectly, making a valid certificate appear expired.
  • Timezone issue — incorrect timezone causing the clock to be off by hours.

How to Fix It

Step 1: Check Your Device's Clock

First, verify your system time is correct:

  • Windows: Settings → Time & Language → Date & Time → ensure "Set time automatically" is on
  • macOS: System Settings → General → Date & Time → enable "Set time and date automatically"
  • Android/iOS: Settings → General → Date & Time → enable automatic date/time

If the clock was wrong and you corrected it, reload the page — the error should disappear if the certificate itself is valid.

Step 2: Check the Certificate's Expiry Date

If your clock is correct, the certificate has genuinely expired. Use the SSL Checker to confirm the certificate's Not After date and see how long ago it expired.

Step 3: Renew the Certificate (Site Owners)

If you own the site, renew the certificate immediately. For Let's Encrypt:

sudo certbot renew --force-renewal

After renewal, reload your web server to apply the new certificate.

Step 4: Set Up Auto-Renewal

Configure certbot's systemd timer or a cron job to automatically renew certificates before they expire. Let's Encrypt certificates expire every 90 days; auto-renewal should run every 60 days.

Frequently Asked Questions

Can an expired certificate affect all sites or just one?

If the error only appears on specific sites, those certificates have expired. If the error appears on many or all HTTPS sites, your system clock is the more likely cause.

How do I prevent certificate expiry in the future?

Use automated certificate management (certbot with auto-renewal, Cloudflare managed certificates, or hosting provider auto-renewal). Set up expiry monitoring to alert you 30 days before expiry.
