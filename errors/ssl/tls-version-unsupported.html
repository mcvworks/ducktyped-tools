TLS Version Not Supported

Last updated: March 8, 2026

The TLS protocol version is not supported by the server or client

You might see this error as:

  • TLS version unsupported
  • ERR_SSL_VERSION_OR_CIPHER_MISMATCH
  • TLS 1.0 not supported
  • TLS 1.1 deprecated
  • Protocol version not supported
  • Unsupported TLS version

What Does This Error Mean?

TLS Version Not Supported occurs when the client and server cannot agree on a TLS protocol version during the handshake. The client proposes the TLS versions it supports, and if the server does not support any of them, the handshake fails. This commonly happens when a client supports only modern TLS versions (1.2 or 1.3) but the server only supports deprecated versions (1.0 or 1.1), or vice versa when an old client connects to a server that has disabled legacy TLS versions.

Common Causes

  • Server only supports deprecated TLS versions — The server is configured to use only TLS 1.0 or TLS 1.1, which modern browsers and clients have disabled. TLS 1.0 and 1.1 were deprecated in RFC 8996 due to known security vulnerabilities.
  • Client does not support server's TLS version — An older client or application only supports TLS 1.0/1.1, but the server requires TLS 1.2 or higher. This is common with legacy systems, embedded devices, or outdated software.
  • Server misconfiguration excluding TLS 1.2 — The server is misconfigured to only allow TLS 1.3, but the client does not yet support TLS 1.3. Both TLS 1.2 and 1.3 should typically be enabled for compatibility.
  • Network middlebox interference — A firewall or security appliance is modifying the TLS handshake and removing supported version indicators, causing the server to believe the client does not support any compatible version.

How to Fix It

1. Enable TLS 1.2 and 1.3 on the server

Configure the server to support both TLS 1.2 and TLS 1.3 for maximum compatibility while maintaining security.

# Nginx
ssl_protocols TLSv1.2 TLSv1.3;

# Apache
SSLProtocol -all +TLSv1.2 +TLSv1.3

# HAProxy
ssl-default-bind-options ssl-min-ver TLSv1.2

2. Update the client software

If the client does not support modern TLS versions, update the browser, operating system, or application. All current browsers support TLS 1.2 and 1.3.

3. Check with OpenSSL

Test which TLS versions the server supports using OpenSSL.

# Test TLS 1.2
openssl s_client -connect example.com:443 -tls1_2

# Test TLS 1.3
openssl s_client -connect example.com:443 -tls1_3

# Test all versions
nmap --script ssl-enum-ciphers -p 443 example.com

4. Disable legacy TLS versions

Remove support for TLS 1.0 and 1.1 on the server side. These versions have known vulnerabilities and are no longer accepted by modern clients.

Frequently Asked Questions

Which TLS versions should I support?

Support TLS 1.2 and TLS 1.3. TLS 1.0 and 1.1 are deprecated and have known security issues. TLS 1.2 provides broad compatibility, and TLS 1.3 provides the strongest security and performance.

Why did TLS 1.0 and 1.1 get deprecated?

TLS 1.0 and 1.1 use older cryptographic algorithms vulnerable to attacks like BEAST, POODLE, and others. They also lack modern features like authenticated encryption with associated data (AEAD) cipher suites that are mandatory in TLS 1.2+.

Can I force my browser to use an older TLS version?

Most modern browsers have removed the ability to enable TLS 1.0 and 1.1. Even if possible through advanced settings, doing so is not recommended as it exposes you to known attacks. The server should be updated instead.
