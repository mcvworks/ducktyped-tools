NET::ERR_CERT_WEAK_SIGNATURE_ALGORITHM

Last updated: March 8, 2026

This error means the SSL certificate uses a deprecated or weak cryptographic algorithm (such as SHA-1). Modern browsers reject these certificates as insufficiently secure.

You might see this error as:

  • NET::ERR_CERT_WEAK_SIGNATURE_ALGORITHM
  • Weak signature algorithm
  • SHA-1 certificate
  • Weak certificate signature

What Does This Error Mean?

SSL certificates are signed by a Certificate Authority using a cryptographic hash algorithm. The signature proves the certificate has not been tampered with. NET::ERR_CERT_WEAK_SIGNATURE_ALGORITHM appears when the signature algorithm is considered too weak for modern security standards.

This most commonly affects certificates signed with SHA-1 (also written as sha1WithRSAEncryption). SHA-1 was deprecated in 2017 after Google demonstrated a practical collision attack.

Common Causes

  • SHA-1 signed certificate — certificate was issued or signed with the SHA-1 algorithm.
  • MD5 signature — very old certificates using MD5 (deprecated much earlier than SHA-1).
  • Intermediate CA with weak algorithm — an intermediate certificate in the chain uses a weak algorithm, even if the leaf certificate uses SHA-256.
  • Old internal CA — an internal certificate authority created years ago that still uses older algorithms.

How to Fix It

1. Reissue the Certificate with SHA-256

All modern certificate authorities issue SHA-256 (or stronger) certificates by default. Simply reissue or renew your certificate and the new one will use the correct algorithm.

For Let's Encrypt, certbot renew --force-renewal will issue a new SHA-256 certificate.

2. Check Your CSR Generation

If you generate a Certificate Signing Request (CSR), ensure you specify SHA-256:

openssl req -new -sha256 -key private.key -out certificate.csr

3. Check the Full Certificate Chain

Use the SSL Checker to inspect every certificate in the chain. If an intermediate certificate uses SHA-1, you need to obtain an updated intermediate from your CA.

4. Update Internal CAs

If using an internal CA, regenerate the CA root and intermediate certificates using SHA-256 and redistribute the new root to all clients.

Frequently Asked Questions

Which signature algorithms are considered secure today?

SHA-256 (sha256WithRSAEncryption) and SHA-384 are currently considered secure. ECDSA with P-256 or P-384 curves are also widely used and considered strong. SHA-1 and MD5 are deprecated and rejected by all modern browsers.

Can this error appear on a recently issued certificate?

Extremely unlikely. All major CAs stopped issuing SHA-1 certificates in 2016. If you see this on a recently issued certificate, it may be an intermediate or root CA in the chain that still uses an older algorithm. Contact your CA.
