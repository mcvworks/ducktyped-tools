NET::ERR_CERT_AUTHORITY_INVALID

Last updated: March 8, 2026

This error means the certificate was signed by a Certificate Authority the browser does not trust — such as a self-signed cert, an internal CA, or a CA not in the browser's root store.

You might see this error as:

  • NET::ERR_CERT_AUTHORITY_INVALID
  • Certificate authority invalid
  • Your connection is not private
  • Self-signed certificate
  • Untrusted certificate authority
  • CA not trusted

Where the Handshake Fails

What Does This Error Mean?

Browsers maintain a list of trusted Certificate Authorities (called a root store). When a server presents an SSL certificate, the browser traces the certificate chain back to a root CA. If that root CA is not in the browser's trusted store, the connection is blocked with NET::ERR_CERT_AUTHORITY_INVALID.

This is different from certificate expiry or hostname mismatch — the certificate may be otherwise valid, but the issuer is not trusted.

Common Causes

  • Self-signed certificate — the certificate was signed with its own private key, not by a CA. Commonly used in development.
  • Internal/private CA — a certificate issued by a company's internal certificate authority, which is not in the public root store.
  • Missing intermediate certificate — the server is only sending the leaf certificate without the intermediate CA certificates, breaking the chain.
  • Expired root or intermediate CA — an intermediate CA in the chain has expired.
  • Antivirus SSL inspection — security software intercepting HTTPS with its own certificate, which may not be trusted.
  • Outdated OS/browser — older systems may not have the newest root CAs, causing newer certificates to appear untrusted.

How to Fix It

For Public Websites

1. Use a Certificate from a Trusted CA

Replace self-signed certificates with one from a publicly trusted CA. Let's Encrypt provides free, automatically trusted DV certificates. Other trusted CAs include Sectigo, DigiCert, and GlobalSign.

2. Install the Full Certificate Chain

Configure your web server to send intermediate CA certificates. For nginx, use the ssl_certificate directive with the full chain file (leaf + intermediate). For Apache, use SSLCertificateChainFile.

For Internal Networks

3. Distribute the Internal CA Certificate

Push your internal CA's root certificate to all devices through MDM, Group Policy, or manual installation. Once installed, all certificates issued by your internal CA will be trusted.

For Visitors

4. Check Antivirus HTTPS Inspection

Some antivirus products intercept HTTPS. If this error appears on many sites, check whether your security software has an "SSL inspection" or "HTTPS scanning" feature that may be inserting its own certificate.

Frequently Asked Questions

Why does Chrome trust some CAs but not others?

Chrome (and other browsers) include a root store — a list of CA root certificates that have been through an audit process and met industry-standard security requirements. CAs not in this list are not considered trusted for public use.

Can I add my own CA to the browser's trust store?

Yes. On Windows, you can add certificates to the Windows Certificate Store. On macOS, you can add them to the Keychain. Chrome on these platforms uses the OS trust store. Firefox has its own certificate store that must be configured separately.
