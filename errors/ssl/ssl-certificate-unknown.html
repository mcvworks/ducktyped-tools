SSL Certificate Unknown

Last updated: March 8, 2026

Browser does not recognize or trust the SSL certificate

You might see this error as:

  • SSL certificate unknown
  • Unknown certificate error
  • Certificate unknown
  • TLS alert certificate unknown

What Does This Error Mean?

SSL Certificate Unknown occurs when the browser or TLS client encounters a certificate that it cannot verify against its trusted certificate store. The certificate may be issued by an unknown Certificate Authority (CA), the intermediate certificates may be missing from the server's certificate chain, or the certificate may use a format or extension the client does not understand. The TLS handshake fails because the client cannot establish a trust path from the server's certificate to a known root CA.

Common Causes

  • Certificate issued by an untrusted CA — The certificate was issued by a Certificate Authority that is not in the browser's or operating system's trusted root store. This includes private CAs, less common public CAs, or CAs that have been removed from trust stores.
  • Missing intermediate certificates — The server is not sending the full certificate chain. The server's certificate was signed by an intermediate CA, but the intermediate certificate is not included in the TLS handshake, breaking the chain of trust.
  • Self-signed certificate — The certificate is self-signed and not issued by any CA. Browsers do not trust self-signed certificates by default because there is no third-party verification of the server's identity.
  • Outdated client trust store — The client's operating system or browser has an outdated certificate store that does not include newer root CAs. This can happen on old systems that no longer receive updates.
  • Certificate uses unsupported extensions — The certificate contains X.509 extensions that the client does not understand and has marked as critical, causing the client to reject the entire certificate.

How to Fix It

1. Install intermediate certificates on the server

Ensure the server sends the complete certificate chain including all intermediate certificates. Most CAs provide a bundle file containing the necessary intermediates.

# Nginx — include full chain
ssl_certificate /etc/ssl/fullchain.pem;
ssl_certificate_key /etc/ssl/private.key;

# Apache — specify chain file
SSLCertificateFile /etc/ssl/cert.pem
SSLCertificateChainFile /etc/ssl/chain.pem
SSLCertificateKeyFile /etc/ssl/private.key

2. Verify the certificate chain

Use OpenSSL to check whether the certificate chain is complete and valid.

# Check certificate chain
openssl s_client -connect example.com:443 -showcerts

# Verify chain completeness
openssl verify -CAfile /etc/ssl/certs/ca-certificates.crt cert.pem

3. Replace self-signed certificates

For public-facing servers, replace self-signed certificates with certificates from a trusted CA. Let's Encrypt provides free trusted certificates.

# Obtain a free certificate from Let's Encrypt
certbot certonly --webroot -w /var/www/html -d example.com

4. Update the client's trust store

On older systems, update the CA certificate bundle to include current root CAs. On Linux, update the ca-certificates package.

# Debian/Ubuntu
sudo apt update && sudo apt install ca-certificates
sudo update-ca-certificates

# RHEL/CentOS
sudo yum update ca-certificates

Frequently Asked Questions

Is it safe to bypass the certificate unknown warning?

Bypassing the warning means your connection may not be secure. For internal or development servers with self-signed certificates, it may be acceptable. For public websites, it is not safe — the certificate issue may indicate a man-in-the-middle attack or a compromised server.

Why does my certificate work in Chrome but not in other applications?

Different applications use different trust stores. Chrome uses the operating system's trust store, while applications like Java, Python, or curl may use their own. You need to ensure the CA certificate is trusted in the specific trust store used by the failing application.

How do I add a private CA to my trust store?

Import the private CA's root certificate into your operating system or application trust store. On Windows, use the Certificate Manager. On macOS, use Keychain Access. On Linux, add the certificate to /usr/local/share/ca-certificates/ and run update-ca-certificates.
