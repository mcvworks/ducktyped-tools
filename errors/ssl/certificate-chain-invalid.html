Certificate Chain Invalid

Last updated: March 8, 2026

SSL certificate chain validation failed

You might see this error as:

  • Certificate chain invalid
  • SSL certificate chain error
  • Incomplete certificate chain
  • Unable to verify certificate chain
  • SSL chain verification failed

What Does This Error Mean?

Certificate Chain Invalid occurs when the TLS client cannot build a valid trust path from the server's certificate through intermediate Certificate Authorities up to a trusted root CA. Every SSL certificate is part of a chain: the server certificate is signed by an intermediate CA, which is signed by another intermediate or the root CA. If any link in this chain is missing, expired, or uses an untrusted signer, the entire chain validation fails.

Common Causes

  • Missing intermediate certificate — The server is not sending one or more intermediate certificates. The server certificate is valid, but the client cannot trace the trust path because the intermediate CA certificate that signed it is missing from the handshake.
  • Certificates in wrong order — The certificate chain is sent with certificates in the wrong order. The correct order is: server certificate first, followed by intermediate certificates in order, up to (but not including) the root CA.
  • Expired intermediate certificate — An intermediate CA certificate in the chain has expired. Even if the server certificate is still valid, an expired intermediate invalidates the entire chain.
  • Cross-signed certificate path issue — The certificate relies on a cross-signed intermediate that has expired or been removed from trust stores, and the server is not providing the alternative valid chain.
  • Root CA removed from trust store — The root CA that anchors the certificate chain has been removed from the client's trust store, typically due to security incidents or policy changes.

How to Fix It

1. Install the complete certificate chain

Download the correct intermediate certificates from your CA and configure the server to send the full chain.

# Create the full chain file
cat server-cert.pem intermediate-cert.pem > fullchain.pem

# Nginx
ssl_certificate /etc/ssl/fullchain.pem;
ssl_certificate_key /etc/ssl/private.key;

# Apache
SSLCertificateFile /etc/ssl/server-cert.pem
SSLCertificateChainFile /etc/ssl/intermediate-cert.pem

2. Verify chain order

Check the certificate chain order using OpenSSL to ensure certificates are in the correct sequence.

# Check chain order
openssl s_client -connect example.com:443 -showcerts 2>/dev/null | grep 's:' 

# Should show:
# 0 s:CN = example.com (server cert)
# 1 s:CN = Intermediate CA (intermediate)
# 2 s:CN = Root CA (optional root)

3. Check intermediate certificate expiration

Verify that all certificates in the chain are within their validity period.

# Check each certificate's dates
openssl x509 -in intermediate.pem -noout -dates

# Check remotely
openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates

4. Use an online chain checker

Use the SSL Checker tool to verify your complete certificate chain configuration and identify any missing or invalid intermediate certificates.

Frequently Asked Questions

Why doesn't the server need to send the root CA certificate?

Root CA certificates are already embedded in the client's trust store. Sending the root certificate wastes bandwidth and adds nothing to the trust validation. The chain should include the server certificate and all intermediates, but stop before the root.

Why does my site work in Chrome but not in other applications?

Chrome and some browsers can automatically download missing intermediate certificates using the Authority Information Access (AIA) extension in the server certificate. Other browsers and applications (curl, Python, mobile apps) do not perform AIA fetching and require the complete chain from the server.

How do I know which intermediate certificates I need?

Your CA provides the intermediate certificate(s) when you purchase or obtain your SSL certificate. You can also find them by examining the Authority Information Access (AIA) field in your server certificate, which contains a URL to download the issuing CA's certificate.
