SSL Certificate Verify Failed

Last updated: March 8, 2026

SSL certificate verification failed during the TLS handshake

You might see this error as:

  • SSL certificate verify failed
  • CERTIFICATE_VERIFY_FAILED
  • SSL: CERTIFICATE_VERIFY_FAILED Python
  • unable to verify the first certificate
  • unable to get local issuer certificate

What Does This Error Mean?

SSL Certificate Verify Failed occurs when the TLS client cannot verify the server's certificate against its trusted certificate store. This error is common in programming languages (Python, Node.js, Ruby), command-line tools (curl, wget), and applications that perform their own certificate validation. The verification process checks the certificate chain, validity dates, revocation status, and hostname match — failure in any of these checks produces this error.

Common Causes

  • Missing CA certificates in the trust store — The application or system does not have the root CA certificate or intermediate CA certificates needed to verify the server's certificate chain. This is common in minimal Docker containers or freshly installed systems.
  • Certificate hostname mismatch — The hostname in the URL does not match any of the names in the certificate's Subject Alternative Name (SAN) field or Common Name (CN), causing verification to fail.
  • Expired certificate — The server's certificate or one of the intermediate certificates in the chain has expired. Certificate verification checks the notBefore and notAfter dates for all certificates in the chain.
  • Incorrect system time — The client system's clock is significantly wrong, causing valid certificates to appear expired or not yet valid during the date validation step.
  • Corporate proxy intercepting TLS — A corporate HTTPS proxy is performing TLS inspection by replacing the server's certificate with its own. If the proxy's CA certificate is not in the application's trust store, verification fails.

How to Fix It

1. Install or update CA certificates

Ensure the system or application has an up-to-date CA certificate bundle.

# Debian/Ubuntu
sudo apt install ca-certificates
sudo update-ca-certificates

# Python — install certifi
pip install --upgrade certifi

# Node.js — set CA bundle
export NODE_EXTRA_CA_CERTS=/path/to/ca-bundle.crt

2. Verify the certificate details

Check what certificate the server is presenting and identify which verification step fails.

# Check certificate details
openssl s_client -connect example.com:443 -servername example.com

# Check specific verification errors
curl -vI https://example.com 2>&1 | grep -i 'ssl\|verify'

3. Fix system clock

Synchronize your system clock with an NTP server to ensure certificate date validation works correctly.

# Linux — sync with NTP
sudo timedatectl set-ntp true

# Windows
w32tm /resync

4. Add corporate proxy CA to trust store

If behind a corporate proxy performing TLS inspection, obtain the proxy's CA certificate from your IT department and add it to the application's trust store.

Frequently Asked Questions

Should I disable SSL verification to fix this error?

No. Disabling SSL verification (such as using verify=False in Python or -k in curl) removes all certificate security and makes the connection vulnerable to man-in-the-middle attacks. Fix the root cause instead.

Why does this error occur in Docker containers but not on my host?

Minimal Docker base images often do not include CA certificates. Install the ca-certificates package in your Dockerfile. For Alpine-based images, run 'apk add ca-certificates'.

Can Python and Node.js use different certificate stores?

Yes. Python uses the certifi package bundle by default, while Node.js uses the system trust store. Each language may need its CA certificates configured separately, especially in environments with custom CAs.
