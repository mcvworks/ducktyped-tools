SSL Certificate Not Yet Valid

Last updated: March 8, 2026

SSL certificate's start date is in the future

You might see this error as:

  • SSL certificate not yet valid
  • Certificate not yet valid
  • Future certificate date
  • Certificate start date in future

What Does This Error Mean?

SSL Certificate Not Yet Valid occurs when the client's current date is before the certificate's 'Not Before' date, meaning the certificate is not yet within its validity period. Every X.509 certificate has a validity window defined by two dates: 'Not Before' (the earliest date the certificate is valid) and 'Not After' (the expiration date). If the client checks the certificate before the 'Not Before' date, validation fails.

Common Causes

  • Client system clock is wrong — The most common cause is an incorrect system clock on the client. If the clock is set to a date in the past, a perfectly valid certificate will appear to have a future start date.
  • Certificate installed before its validity period — The server administrator installed a new certificate before its validity period has started. This can happen when certificates are issued with a future start date to coordinate with planned deployments.
  • Time zone or daylight saving time issues — Incorrect time zone settings combined with a clock near the certificate's start date boundary can cause the system to believe the certificate is not yet valid.
  • Certificate was just issued — Some Certificate Authorities set the 'Not Before' date a few minutes or hours after issuance to account for clock skew. If the certificate is deployed immediately after issuance, clients with accurate clocks may see it as not yet valid for a brief period.

How to Fix It

1. Fix the system clock

Synchronize your system clock with an NTP time server to ensure the correct date and time.

# Windows
w32tm /resync

# Linux
sudo timedatectl set-ntp true
sudo systemctl restart systemd-timesyncd

# macOS
sudo sntp -sS time.apple.com

2. Check the certificate validity dates

Inspect the certificate to see its exact validity window.

# Check certificate dates
openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates

# Output:
# notBefore=Mar  1 00:00:00 2026 GMT
# notAfter=Mar  1 00:00:00 2027 GMT

3. Wait for the validity period to begin

If the certificate genuinely has a future start date and your clock is correct, wait until the 'Not Before' date passes. Contact the CA or server administrator if the start date seems incorrect.

4. Reissue the certificate with correct dates

If you control the server, reissue the certificate with a 'Not Before' date of now or slightly in the past to account for clock skew across different clients.

Frequently Asked Questions

Why would a CA issue a certificate with a future start date?

CAs sometimes issue certificates with a 'Not Before' date slightly in the future to prevent issues with clock skew or to allow time for deployment. Some enterprise CAs allow custom validity periods for planned certificate rotations.

How is this different from an expired certificate error?

An expired certificate has passed its 'Not After' date — its validity period is over. A 'not yet valid' certificate has not reached its 'Not Before' date — its validity period has not started yet. Both are validity window errors but in opposite directions.

Can CMOS battery failure cause this error?

Yes. If the CMOS battery on a desktop or server dies, the system clock resets to a default date (often in the past), which can cause certificates to appear not yet valid. Replacing the battery and setting the correct time resolves this.
