Can't Connect to Local MySQL Server Through Socket

Last updated: July 1, 2026

MySQL error 2002 — the client looked for the Unix socket file (usually /var/run/mysqld/mysqld.sock) and found nothing listening.

You might see this error as:

  • Can't connect to local MySQL server through socket
  • MySQL error 2002
  • ERROR 2002 (HY000)
  • /var/run/mysqld/mysqld.sock (2)
  • mysqld.sock missing
  • MariaDB can't connect through socket

What Does This Error Mean?

When you connect to host 'localhost', the MySQL client does not use TCP at all — it opens a Unix socket file on disk. Error 2002 means that file was missing or nothing was listening on it. Either the server is not running (by far the most common), the client and server disagree about where the socket lives, or the server exists somewhere the socket cannot reach — like inside a Docker container, where the host's client cannot use it.

Common Causes

  • MySQL is not running — The service crashed, failed to start (disk full, corrupted tables, bad configuration), or was never started after boot. No server process means no socket file.
  • Client and server use different socket paths — The server creates the socket where its config says (e.g. /var/lib/mysql/mysql.sock on RHEL-family), while the client looks at its own default (/var/run/mysqld/mysqld.sock on Debian-family). Mixed packages and custom builds disagree silently.
  • MySQL runs in Docker — The socket exists inside the container's filesystem. A client on the host connecting to 'localhost' looks for a socket on the host — which does not exist. Docker connections must use TCP (127.0.0.1 with the published port).
  • Disk full or permissions prevented socket creation — A full /var partition or wrong ownership on the socket directory stops the server from creating the socket even though the process starts.

How to Fix It

1. Check and start the server

Confirm whether MySQL is running before anything else; if it fails to start, the log tells you why.

sudo systemctl status mysql    # or mysqld / mariadb
sudo systemctl start mysql
sudo journalctl -u mysql -n 30
sudo tail -50 /var/log/mysql/error.log

2. Connect over TCP to bypass the socket

Using 127.0.0.1 instead of localhost forces TCP. If this works, the server is fine and the problem is purely the socket path.

mysql -h 127.0.0.1 -P 3306 -u root -p

3. Find the real socket path and align configs

Ask the running server where its socket is, then set the same path in the [client] section.

mysql -h 127.0.0.1 -u root -p -e "SHOW VARIABLES LIKE 'socket';"

# /etc/mysql/my.cnf
[client]
socket = /var/lib/mysql/mysql.sock

4. Check disk space if the server will not start

A full data or log partition is a classic silent startup failure.

df -h /var /var/lib/mysql
sudo du -sh /var/lib/mysql/*.log 2>/dev/null

Frequently Asked Questions

Why does 'localhost' behave differently from '127.0.0.1' in MySQL?

MySQL special-cases the hostname 'localhost' to mean the Unix socket, while '127.0.0.1' always means TCP. They are different transports with potentially different grants ('user'@'localhost' vs 'user'@'127.0.0.1'), which is why one can work while the other fails.

How do I connect to MySQL running in Docker?

Publish the port (-p 3306:3306) and connect with -h 127.0.0.1 -P 3306. From another container on the same Docker network, use the container/service name as the host. The socket file inside the container is only usable by clients inside that container.

The error shows socket path '(2)' — what does the number mean?

It is the OS errno: 2 means 'No such file or directory' (socket missing — server down or wrong path), while 13 means 'Permission denied' (socket exists but your user cannot access it).
