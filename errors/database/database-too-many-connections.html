Too Many Database Connections

Last updated: March 8, 2026

Database connection limit has been reached

You might see this error as:

  • Too many connections
  • Max connections reached
  • ERROR 1040 (HY000): Too many connections
  • Connection pool exhausted
  • FATAL: too many connections for role

What Does This Error Mean?

This error occurs when the number of simultaneous connections to the database has reached the configured maximum limit. Every database has a connection limit, and each application connection consumes server resources. When the limit is hit, new connections are rejected until existing ones are closed.

Common Causes

  • Connection leaks in application code — The application opens database connections but fails to close them properly, causing connections to accumulate over time until the limit is reached.
  • No connection pooling — Each request opens a new database connection instead of reusing connections from a pool. Under high traffic, this quickly exhausts the connection limit.
  • Connection pool size too large — Multiple application instances each maintain their own connection pool. The sum of all pool sizes exceeds the database's maximum connection limit.
  • Long-running transactions holding connections — Queries or transactions that take a long time to complete hold connections open, reducing the number available for other requests.

How to Fix It

1. Implement connection pooling

Use a connection pooler to manage and reuse database connections efficiently.

# PgBouncer for PostgreSQL:
[databases]
mydb = host=localhost port=5432 dbname=mydb

[pgbouncer]
listen_port = 6432
max_client_conn = 1000
default_pool_size = 20
pool_mode = transaction

2. Check and kill idle connections

Identify and terminate idle connections that are consuming connection slots.

-- PostgreSQL:
SELECT pid, usename, application_name, state, query_start
FROM pg_stat_activity WHERE state = 'idle';

-- Kill a specific connection:
SELECT pg_terminate_backend(pid);

-- MySQL:
SHOW PROCESSLIST;
KILL <process_id>;

3. Increase the connection limit

Raise the maximum connections setting if the server has sufficient resources.

-- PostgreSQL (postgresql.conf):
max_connections = 200

-- MySQL (my.cnf):
max_connections = 200

-- Restart required after change

Frequently Asked Questions

How many connections should I allow?

It depends on your server's RAM. Each PostgreSQL connection uses about 5-10MB of RAM. A server with 4GB RAM can typically handle 200-400 connections. Use connection pooling instead of increasing the limit excessively.

What is connection pooling?

Connection pooling maintains a set of reusable database connections. Instead of opening and closing connections for each request, the application borrows a connection from the pool, uses it, and returns it. This dramatically reduces the total number of connections needed.

How do I find connection leaks?

Monitor active connections over time. If the count keeps growing without decreasing, you have a leak. Check your application code for connections opened without corresponding close/release calls, especially in error handling paths.
