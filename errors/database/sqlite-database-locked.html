SQLite Database is Locked

Last updated: March 8, 2026

SQLite database file is locked by another process

You might see this error as:

  • SQLite database locked
  • database is locked
  • SQLITE_BUSY
  • OperationalError: database is locked
  • SQLite busy timeout

What Does This Error Mean?

SQLite uses file-level locking to manage concurrent access. The 'database is locked' error occurs when one process holds a lock on the database file and another process tries to write to it. Unlike client-server databases, SQLite runs in-process and uses the filesystem for locking, which limits concurrent write access.

Common Causes

  • Another process is writing to the database — SQLite allows only one writer at a time in the default journaling mode. If another process or thread is performing a write operation, all other write attempts will fail with a locked error.
  • Long-running transaction holding a lock — A transaction that takes a long time to complete (or was never committed/rolled back) holds the write lock, blocking other operations.
  • Multiple web server workers accessing same database — Web frameworks running multiple worker processes (like Gunicorn with multiple workers) cause concurrent access issues with SQLite.
  • Database file on a network filesystem — SQLite's file locking does not work reliably on network filesystems like NFS, SMB, or CIFS. Locks may not be properly coordinated between machines.

How to Fix It

1. Enable WAL mode

Write-Ahead Logging (WAL) mode allows concurrent reads during writes and improves concurrent access significantly.

PRAGMA journal_mode=WAL;

2. Set a busy timeout

Configure SQLite to wait and retry when the database is locked instead of failing immediately.

PRAGMA busy_timeout = 5000;  -- Wait up to 5 seconds

# In Python:
import sqlite3
conn = sqlite3.connect('mydb.sqlite', timeout=10)

3. Keep transactions short

Minimize the time transactions are open. Commit or rollback as quickly as possible to release locks.

-- Instead of:
BEGIN;
-- lots of operations over time
COMMIT;

-- Do:
BEGIN;
-- minimal operations
COMMIT;

Frequently Asked Questions

Should I use SQLite for a web application?

SQLite works well for low-to-medium traffic websites (fewer than 100K requests per day). For higher traffic or applications needing concurrent writes, use PostgreSQL or MySQL. SQLite is ideal for prototyping, embedded applications, and single-user tools.

What is WAL mode?

WAL (Write-Ahead Logging) changes how SQLite handles writes. Instead of locking the entire database file, changes are written to a separate WAL file. This allows readers to continue while a write is in progress, dramatically improving concurrency.

Can I use SQLite on a network share?

It is not recommended. Network filesystems do not reliably support the file locking that SQLite depends on. Data corruption can result. If multiple machines need to access the same database, use a client-server database like PostgreSQL.
