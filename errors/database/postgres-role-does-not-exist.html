PostgreSQL Role Does Not Exist

Last updated: July 1, 2026

PostgreSQL error 28000 — 'FATAL: role "username" does not exist'. The role you tried to connect as has never been created on this cluster.

You might see this error as:

  • FATAL: role does not exist
  • role "postgres" does not exist
  • psql: error: FATAL: role
  • createuser postgres
  • 28000 postgres

What Does This Error Mean?

PostgreSQL authenticates against roles (users) stored in the cluster. This error means the role name your client sent does not exist there. The classic trigger: running plain 'psql' makes PostgreSQL assume a role named after your operating-system user — which usually does not exist as a database role. The second classic: Homebrew's PostgreSQL creates a superuser named after your macOS account, not 'postgres', so tools expecting the traditional postgres role fail.

Common Causes

  • psql defaulted to your OS username — Without -U, psql connects as the current OS user. 'FATAL: role "alice" does not exist' just means nobody created a database role called alice.
  • The role genuinely was never created — New cluster, fresh install, or an application configured with a role name that no migration or setup script ever created.
  • No 'postgres' role on Homebrew installs — Homebrew initializes the cluster with your macOS username as the superuser. Anything hard-coded to connect as 'postgres' hits this error.
  • Wrong cluster or case-sensitivity confusion — The role exists on the other cluster (different port), or was created quoted with capitals ("MyUser") and is now case-sensitive.

How to Fix It

1. Connect as a role that exists

Specify the superuser explicitly, or become the postgres OS user for peer auth.

psql -U postgres -d postgres
# or on Linux with peer auth:
sudo -u postgres psql

2. Create the missing role

Create the role with login rights (and only the privileges it needs).

CREATE ROLE appuser WITH LOGIN PASSWORD 'secret';
GRANT ALL PRIVILEGES ON DATABASE appdb TO appuser;
-- or from the shell:
-- createuser --interactive appuser

3. On Homebrew, create the traditional postgres role

Add a postgres superuser so tools with conventional defaults work.

createuser -s postgres
# runs as your mac user, which is already a superuser

4. List existing roles to see what is really there

Check role names (and their exact case) before assuming.

psql -U postgres -c '\du'
-- or:
SELECT rolname FROM pg_roles ORDER BY 1;

Frequently Asked Questions

What is the difference between a role and a user in PostgreSQL?

They are the same object: a user is simply a role with the LOGIN attribute. CREATE USER is shorthand for CREATE ROLE ... LOGIN. Groups are roles without LOGIN that other roles are granted membership in.

Why does plain 'psql' try my OS username?

psql's defaults come from the environment: role = your OS user, database = same as the role. It makes local peer authentication seamless when matching roles exist — and produces this error when they do not. Set PGUSER/PGDATABASE or use -U/-d to override.

The role exists in \du but still 'does not exist' — how?

Either you are connecting to a different cluster (check the port — 5432 vs 5433 after version upgrades), or the role was created with quotes and mixed case, making "MyUser" and myuser different names. Re-create unquoted lowercase roles to avoid the trap.
