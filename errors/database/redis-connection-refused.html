Redis Connection Refused

Last updated: March 8, 2026

Redis server refused the connection

You might see this error as:

  • Redis connection refused
  • connect ECONNREFUSED 6379
  • Could not connect to Redis
  • Redis server not running
  • Error: connect ECONNREFUSED 127.0.0.1:6379

What Does This Error Mean?

This error occurs when a client cannot establish a TCP connection to the Redis server. Redis is either not running, not listening on the expected interface or port, or a firewall is blocking the connection. Redis defaults to binding only to localhost (127.0.0.1), so remote connections are refused unless explicitly configured.

Common Causes

  • Redis server is not running — The Redis service has stopped or was never started. This can happen after a reboot if Redis is not configured to start automatically.
  • Redis bound to localhost only — Redis defaults to binding to 127.0.0.1, which only accepts connections from the local machine. Remote clients cannot connect unless the bind address is changed.
  • Protected mode is enabled — Redis 3.2+ enables protected mode by default, which rejects connections from non-loopback addresses when no password is set.
  • Firewall blocking port 6379 — A firewall is blocking connections on Redis's default port (6379) or the custom port configured in redis.conf.

How to Fix It

1. Start Redis service

Start the Redis server and enable it for automatic startup.

sudo systemctl start redis
sudo systemctl enable redis
sudo systemctl status redis

2. Configure Redis for remote access

Update redis.conf to accept connections from other hosts and set a password for security.

# In redis.conf:
bind 0.0.0.0
protected-mode no
requirepass your_strong_password

# Restart Redis:
sudo systemctl restart redis

3. Test connectivity

Verify that Redis is listening and responding on the expected port.

redis-cli ping
# Should return: PONG

# For remote server:
redis-cli -h server-ip -p 6379 -a password ping

Frequently Asked Questions

Is it safe to bind Redis to 0.0.0.0?

Only if you set a strong password with 'requirepass' and use firewall rules to limit which IPs can connect. Exposing Redis to the internet without authentication is extremely dangerous and is a common attack vector.

What is Redis protected mode?

Protected mode is a security feature in Redis 3.2+ that rejects connections from non-loopback addresses when no password is configured. It prevents accidentally exposing an unsecured Redis instance to the network.
