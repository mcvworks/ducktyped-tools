MySQL Access Denied for User

Last updated: March 8, 2026

MySQL authentication failed for the specified user

You might see this error as:

  • MySQL access denied
  • Access denied for user
  • ERROR 1045 (28000)
  • Authentication failed MySQL
  • Access denied for user 'root'@'localhost'

What Does This Error Mean?

This error occurs when MySQL rejects a connection because the provided credentials are incorrect, the user does not exist, or the user does not have permission to access the specified database from the connecting host. MySQL's authentication is host-specific, meaning a user may be able to connect from localhost but not from a remote IP.

Common Causes

  • Incorrect password — The password provided does not match what MySQL has stored for the user. This includes typos, using an old password, or environment variables with the wrong value.
  • User does not exist for the connecting host — MySQL user accounts are defined as 'user'@'host'. A user 'app'@'localhost' cannot authenticate when connecting from a remote IP. A separate 'app'@'%' or 'app'@'specific-ip' entry is needed.
  • Authentication plugin mismatch — MySQL 8.0+ defaults to caching_sha2_password authentication, which older clients may not support. Clients expecting mysql_native_password will fail to authenticate.
  • Database does not exist or user lacks privileges — The user exists but does not have GRANT privileges on the specified database. MySQL reports this as an access denied error.

How to Fix It

1. Reset user password

Update the user's password from a MySQL root session.

ALTER USER 'username'@'localhost' IDENTIFIED BY 'new_password';
FLUSH PRIVILEGES;

2. Create user for the correct host

Create the user account for the host from which connections are being made.

CREATE USER 'username'@'%' IDENTIFIED BY 'password';
GRANT ALL PRIVILEGES ON database_name.* TO 'username'@'%';
FLUSH PRIVILEGES;

3. Change authentication plugin

Switch to mysql_native_password if your client does not support caching_sha2_password.

ALTER USER 'username'@'localhost' IDENTIFIED WITH mysql_native_password BY 'password';
FLUSH PRIVILEGES;

Frequently Asked Questions

How do I reset the MySQL root password?

Stop MySQL, restart it with --skip-grant-tables, connect without a password, run ALTER USER 'root'@'localhost' IDENTIFIED BY 'new_password', then restart MySQL normally. The exact steps vary by OS.

Why does 'user'@'localhost' work but 'user'@'%' does not?

MySQL treats localhost connections differently from TCP/IP connections, even on the same machine. Connecting via 127.0.0.1 uses TCP and matches '%', while connecting via localhost uses the Unix socket and matches 'localhost'.

What does FLUSH PRIVILEGES do?

FLUSH PRIVILEGES reloads the grant tables from the mysql database. It is required after directly modifying the privilege tables. When using ALTER USER or GRANT statements, FLUSH PRIVILEGES is technically not needed but is good practice.
