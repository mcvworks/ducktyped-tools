Redis NOAUTH Authentication Required

Last updated: July 1, 2026

The Redis error returned when the server requires a password (requirepass or ACLs) but the client sent commands without authenticating first.

You might see this error as:

  • NOAUTH Authentication required
  • redis NOAUTH
  • ReplyError: NOAUTH
  • redis.exceptions.AuthenticationError
  • WRONGPASS invalid username-password pair

What Does This Error Mean?

Redis answers every command with NOAUTH until the client authenticates, whenever authentication is enabled — via the classic requirepass directive or Redis 6+ ACL users. The error appears after someone enables auth on a previously open instance (a common security hardening step, since exposed unauthenticated Redis is a major attack target), or when connection strings lose their password piece — a surprisingly frequent bug because the redis:// URL format puts the password in an unusual position.

Common Causes

  • requirepass was enabled and clients were not updated — The server now demands AUTH, but application configs still hold password-less connection details.
  • Password missing or misplaced in the redis:// URL — The correct form is redis://:password@host:6379 (note the colon before the password — the 'username' slot is empty for classic auth). Passwords put in the username slot silently fail.
  • Redis 6 ACLs expect a username and password — With ACL users, authentication needs both parts (AUTH username password). Clients doing classic single-argument AUTH authenticate as the 'default' user — which fails if that user is disabled or has a different password.
  • Connecting to the wrong instance — Managed Redis (ElastiCache, Azure Cache, Upstash) is provisioned with auth (and often TLS) mandatory. Local dev configs pointed at production endpoints hit NOAUTH immediately.

How to Fix It

1. Authenticate in redis-cli

Provide the password at launch or with the AUTH command; then verify with PING.

redis-cli -a 'yourpassword' PING
# or interactively:
redis-cli
> AUTH yourpassword
> PING
# Redis 6 ACL user:
> AUTH myuser userpassword

2. Fix the connection URL in applications

Use the correct URL anatomy — empty username, colon, password.

# classic requirepass:
REDIS_URL=redis://:s3cret@redis-host:6379/0
# ACL user:
REDIS_URL=redis://myuser:s3cret@redis-host:6379/0
# TLS (managed providers):
REDIS_URL=rediss://:s3cret@redis-host:6380/0

3. Check what the server actually requires

On the server, inspect the auth configuration to know whether you are dealing with requirepass, ACLs, or both.

redis-cli -a 'yourpassword' CONFIG GET requirepass
redis-cli -a 'yourpassword' ACL LIST

4. Handle auth added after clients connected

CONFIG SET requirepass takes effect for new commands on existing connections too — deploy updated client configuration first, then enable auth, to avoid a window of NOAUTH crash-loops.

Frequently Asked Questions

What is the difference between NOAUTH and WRONGPASS?

NOAUTH: you have not authenticated at all — the client never sent AUTH. WRONGPASS: you did send AUTH and the credentials were wrong. NOAUTH points at missing configuration; WRONGPASS points at incorrect credentials.

Is it safe to run Redis without a password?

Only when the port is genuinely unreachable from untrusted networks — bound to 127.0.0.1 or inside a private network with protected-mode on. Any Redis reachable from the internet without auth will be found and exploited quickly; enable auth and TLS for anything exposed.

Why does my client work in dev but NOAUTH in production?

Dev Redis typically runs auth-less on localhost while production (especially managed Redis) enforces a password and often TLS. Make the connection URL — including password and rediss:// scheme — part of per-environment configuration.
