PostgreSQL Connection Refused

Last updated: March 8, 2026

PostgreSQL server refused the connection

You might see this error as:

  • PostgreSQL connection refused
  • could not connect to server
  • Connection refused port 5432
  • FATAL: password authentication failed
  • psql: could not connect to server

What Does This Error Mean?

This error occurs when a client cannot establish a TCP connection to the PostgreSQL server. The server is either not running, not listening on the expected port or address, or a firewall is blocking the connection. Unlike authentication errors, this error means the connection was rejected at the network level before any credentials were exchanged.

Common Causes

  • PostgreSQL service is not running — The PostgreSQL server process has stopped or was never started. This can happen after a system reboot if the service is not enabled to start automatically.
  • Server not listening on the expected address — PostgreSQL's listen_addresses setting in postgresql.conf defaults to 'localhost', which only accepts connections from the local machine. Remote connections require listen_addresses to include the server's IP or '*'.
  • Wrong port number — The client is trying to connect on a port different from what PostgreSQL is listening on. The default is 5432, but it may be configured differently.
  • Firewall blocking the port — A host-level firewall (iptables, ufw, Windows Firewall) or network firewall is blocking connections to PostgreSQL's port.

How to Fix It

1. Start PostgreSQL service

Start the PostgreSQL service and enable it to start on boot.

sudo systemctl start postgresql
sudo systemctl enable postgresql
sudo systemctl status postgresql

2. Configure listen_addresses for remote access

Edit postgresql.conf to listen on all interfaces and pg_hba.conf to allow connections from your IP range.

# In postgresql.conf:
listen_addresses = '*'

# In pg_hba.conf (add a line):
host  all  all  0.0.0.0/0  md5

# Restart PostgreSQL:
sudo systemctl restart postgresql

3. Check port and connectivity

Verify that PostgreSQL is listening on the expected port.

sudo ss -tlnp | grep 5432
# Or:
sudo netstat -tlnp | grep postgres

Frequently Asked Questions

What is pg_hba.conf?

pg_hba.conf (PostgreSQL Host-Based Authentication) controls which hosts can connect, which users they can log in as, which databases they can access, and what authentication method is required. It is separate from listen_addresses in postgresql.conf.

How do I find the PostgreSQL configuration files?

Run 'SHOW config_file;' in a psql session, or check common locations: /etc/postgresql/<version>/main/ on Ubuntu/Debian, /var/lib/pgsql/<version>/data/ on RHEL/CentOS, or /usr/local/var/postgres/ on macOS with Homebrew.
