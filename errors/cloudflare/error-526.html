Cloudflare Error 526 — Invalid SSL Certificate

Last updated: July 3, 2026

Under Full (strict) SSL mode, the origin presented a certificate that failed validation — expired, self-signed, untrusted, or issued for a different hostname.

You might see this error as:

  • Cloudflare Error 526
  • invalid ssl certificate cloudflare
  • error 526
  • http 526

What Does This Error Mean?

Full (strict) means Cloudflare validates the origin's certificate the way a browser would: trusted issuer, matching hostname, valid dates. Error 526 is that validation failing. The classic sequence: a site runs Full (non-strict) with a self-signed origin cert for years, someone tightens the mode to strict, and 526 appears — or an origin's Let's Encrypt certificate silently expired because renewal broke after the site went behind Cloudflare (HTTP-01 challenges can fail through the proxy).

Common Causes

  • Self-signed certificate under strict mode — Fine for Full (non-strict), rejected by Full (strict). Common on origins set up before the mode was tightened.
  • Expired origin certificate — Renewal automation broke — often exactly because the domain moved behind Cloudflare and the ACME HTTP-01 challenge no longer reaches the origin the way it used to.
  • Hostname mismatch — The certificate covers a different name than the one being requested (server default vhost cert, or a cert missing the www/subdomain variant).
  • Incomplete chain from the origin — Leaf served without its intermediates — some validators tolerate it, strict validation does not.

How to Fix It

1. Inspect what the origin actually serves

Check issuer, dates, and names as Cloudflare sees them.

openssl s_client -connect ORIGIN_IP:443 -servername example.com </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -dates
# full chain listing:
openssl s_client -connect ORIGIN_IP:443 -servername example.com -showcerts </dev/null 2>/dev/null | grep -c 'BEGIN CERT'

2. Install a Cloudflare Origin CA certificate

The simplest permanent answer for origins behind Cloudflare: free, 15-year validity option, always passes Full (strict), no renewal automation to break.

# dashboard: SSL/TLS -> Origin Server -> Create Certificate
# install like any cert:
ssl_certificate     /etc/ssl/cf-origin/example.com.pem;
ssl_certificate_key /etc/ssl/cf-origin/example.com.key;

3. Or repair Let's Encrypt renewal behind the proxy

Switch the ACME challenge to DNS-01 (immune to the proxy) or ensure HTTP-01 paths pass through, then renew.

sudo certbot renew --dry-run
# DNS-01 with the Cloudflare plugin:
sudo apt install python3-certbot-dns-cloudflare
sudo certbot certonly --dns-cloudflare -d example.com -d '*.example.com'

4. Serve the full chain for the right hostname

Point the vhost at fullchain.pem (not the leaf alone) and confirm the cert's SAN list covers every hostname Cloudflare requests.

Frequently Asked Questions

Should I downgrade to Full (non-strict) to fix 526?

It silences the error by skipping validation — meaning anyone able to intercept traffic between Cloudflare and your origin could present any certificate. Since a passing certificate is free (Origin CA) and quick, fixing the origin is strictly better. Keep strict.

Why did my origin's certificate stop renewing after moving to Cloudflare?

HTTP-01 renewals need Let's Encrypt to fetch a challenge file from your domain; with the proxy, security features (or Always Use HTTPS rewrites) can break that fetch. DNS-01 challenges avoid the web path entirely — the Cloudflare DNS plugin makes them the natural choice for proxied domains.

Does 526 affect visitors' browser padlock?

Visitors never see the origin certificate — their TLS terminates at Cloudflare's edge with Cloudflare's certificate. 526 is about the second leg (edge to origin). The visitor just sees the 526 error page; the padlock on working pages comes from the edge certificate either way.
