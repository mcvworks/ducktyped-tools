Cloudflare Error 1020 — Access Denied

Last updated: July 3, 2026

The request matched a firewall or WAF rule on the site — country, network, user-agent, path, or bot-score conditions the owner configured (or a managed rule).

You might see this error as:

  • Cloudflare Error 1020
  • access denied error 1020
  • error 1020
  • cloudflare firewall rule blocked
  • 1020 access denied fix

What Does This Error Mean?

Error 1020 is the general 'a security rule said no': WAF custom rules, managed rulesets, bot-management verdicts, or zone lockdowns matched some attribute of the request — source country or ASN, user-agent string, path pattern, TLS fingerprint, bot score. Unlike the 1006 family (explicit IP bans), the trigger can be anything the rule language can express, which is why the visitor experience feels arbitrary: same person, different browser, different result. For owners, every 1020 is one Security-Events lookup away from an explanation.

Common Causes

  • Country/ASN rules — Blocking traffic from specific countries or networks (data centers, VPN providers' ASNs) — legitimate travelers and VPN users match instantly.
  • Bot management and fingerprint heuristics — Unusual browsers, automation frameworks, privacy tools that strip headers, or odd TLS stacks can score as bots and match a blocking rule.
  • Path/method rules — Rules protecting /wp-admin, /xmlrpc.php, or API paths block anyone touching them from outside an allowlist.
  • Overbroad custom expressions — A rule written during an attack ('block everything with this header pattern') that keeps matching normal traffic afterwards.

How to Fix It

1. Visitors: change the obvious attributes

Turn the VPN off (or pick another exit country), try a mainstream browser without aggressive privacy extensions, and avoid tools that modify your user-agent. If the site blocks your whole country, only the owner can allow you.

2. Visitors: report with the Ray ID

The Ray ID at the bottom of the 1020 page lets the owner find the exact rule that fired for your request — a report containing it usually gets a real answer.

3. Owners: look up the event

Security → Events, filter by the Ray ID (or IP/time). The event names the service (WAF custom rule, managed rule ID, IP Access Rule, Bot Fight Mode) and the matched expression — no guessing.

# via API:
curl -s 'https://api.cloudflare.com/client/v4/zones/ZONE_ID/security/events?ray_id=RAY_ID' \
  -H 'Authorization: Bearer API_TOKEN' | head -60

4. Owners: soften or scope the rule

Switch block actions to Managed Challenge for gray-area matches, add exceptions (paths, known partners' ASNs), and re-review incident-era rules on a schedule so they do not fossilize.

Frequently Asked Questions

1020 vs 1006 — what is the difference?

1006/1007/1008 are specifically IP Access Rules (explicit address/range bans). 1020 is everything else in the firewall toolbox — custom WAF expressions, managed rules, bot verdicts, country blocks. For owners the practical difference is which dashboard page holds the fix.

Why does one browser work while another gets 1020 on the same machine?

Because the rule may match browser attributes rather than your IP: user-agent, header order, TLS fingerprint, or a bot score derived from them. That is the tell that a fingerprint/bot rule (not an IP rule) is firing.

As a small crawler/integration developer, how do I avoid tripping 1020 on partner sites?

Identify honestly (stable, descriptive user-agent with contact info), respect robots.txt and rate limits, and ask the site owner to allowlist your ASN/IPs or user-agent. Evading bot rules by spoofing tends to escalate blocks — the allowlist conversation works better.
