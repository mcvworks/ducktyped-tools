Nginx Errors

Nginx errors show up in the error log ([emerg], [crit], [warn]) or reach visitors as 502/504 responses. These guides cover the config, upstream, TLS, and resource-limit failures behind them, with the exact log lines and the commands that fix each one.

Nginx
Nginx bind() Failed — Address Already in Use
The startup error 'nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)' — another process already owns the port nginx wants.
 Nginx
Nginx Cannot Load Certificate
Startup/reload errors like 'nginx: [emerg] cannot load certificate' or 'SSL_CTX_use_PrivateKey_file failed (key values mismatch)' — the TLS files are missing, unreadable, or mismatched.
 Nginx
Nginx Conflicting Server Name
The warning 'nginx: [warn] conflicting server name "example.com" on 0.0.0.0:80, ignored' — two server blocks claim the same name, and nginx is silently ignoring one of them.
 Nginx
Nginx Connection Refused While Connecting to Upstream
The error-log line 'connect() failed (111: Connection refused) while connecting to upstream' — nginx reached the backend host, but nothing was listening. Visitors see a 502.
 Nginx
Nginx Directory Index Forbidden
The error-log line 'directory index of "/var/www/html/" is forbidden' — a request hit a directory, no index file matched, and autoindex is off, so nginx returned 403.
 Nginx
Nginx No Live Upstreams
The error-log line 'no live upstreams while connecting to upstream' — every server in the upstream block is currently marked failed, so nginx has nowhere to send the request.
 Nginx
Nginx Permission Denied While Connecting to Upstream
The error-log line 'connect() to ... failed (13: Permission denied) while connecting to upstream' — the OS blocked nginx's connection to the backend, classically SELinux.
 Nginx
Nginx Primary Script Unknown (PHP-FPM)
The error-log line 'FastCGI sent in stderr: "Primary script unknown"' — PHP-FPM could not find the script nginx asked it to run. Browsers show a bare 'File not found.'
 Nginx
Nginx Too Many Open Files
Error-log lines like 'socket() failed (24: Too many open files)' or 'accept4() failed' — nginx hit its file-descriptor limit and is dropping connections.
 Nginx
Nginx Unknown Directive
The config-test error 'nginx: [emerg] unknown directive' — a directive is misspelled, belongs to a module that is not loaded, or is not an nginx directive at all.
 Nginx
Nginx Upstream Sent Too Big Header
The error-log line 'upstream sent too big header while reading response header from upstream' — the backend's response headers overflowed nginx's buffer. Visitors see a 502.
 Nginx
Nginx Upstream Timed Out
The error-log line 'upstream timed out (110: Connection timed out) while reading response header from upstream' — the backend took longer than nginx was willing to wait. Visitors see a 504.
