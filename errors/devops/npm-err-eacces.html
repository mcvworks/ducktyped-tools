npm ERR! code EACCES

Last updated: March 8, 2026

npm permission denied error

You might see this error as:

  • npm ERR! EACCES
  • EACCES: permission denied
  • npm permission error
  • Error: EACCES: permission denied
  • npm install permission denied

What Does This Error Mean?

EACCES (permission denied) occurs when npm tries to access a file or directory that the current user does not have permission to read or write. This most commonly happens when installing global packages on Linux or macOS, where the default global prefix (/usr/local/lib/node_modules) is owned by root.

Common Causes

  • Global prefix owned by root — The default npm global directory (/usr/local/lib/node_modules) requires root permissions. Running 'npm install -g' as a normal user fails because it cannot write to this directory.
  • Previous sudo install corrupted ownership — Running 'sudo npm install' changed ownership of files in node_modules or npm cache to root, and now normal npm operations cannot modify those files.
  • Incorrect npm cache permissions — The npm cache directory (~/.npm) has files owned by root from a previous sudo npm command.

How to Fix It

1. Change npm global directory to user-owned location

Configure npm to install global packages in your home directory instead of /usr/local.

mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
# Add to ~/.bashrc or ~/.zshrc:
export PATH=~/.npm-global/bin:$PATH

2. Use nvm to manage Node.js

nvm installs Node.js in your home directory, avoiding system-level permission issues entirely.

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install --lts
nvm use --lts

3. Fix ownership of npm directories

Correct the ownership of npm cache and global directories.

sudo chown -R $(whoami) ~/.npm
sudo chown -R $(whoami) /usr/local/lib/node_modules

Frequently Asked Questions

Should I use sudo with npm?

No. Using 'sudo npm install' is an anti-pattern that creates permission problems. Instead, fix the underlying permission issue using nvm, or by changing the global prefix to a user-owned directory.

Does this affect local project installations?

Usually not. Local 'npm install' (without -g) writes to the project's node_modules directory, which is typically owned by the user. However, if someone previously ran 'sudo npm install' in the project, the permissions may be corrupted.
