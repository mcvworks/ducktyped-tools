fatal: repository not found

Last updated: September 23, 2026

Git found the hosting service but cannot access this repository. Check the exact URL, the account used by Git, and that account’s repository permissions.

You might see this error as:

  • Git repository not found
  • fatal: repository not found
  • remote: Repository not found
  • ERROR: Repository not found
  • The requested URL returned error: 403

What Does This Error Mean?

This error occurs when Git cannot access the remote repository specified in the command. The repository URL may be incorrect, the repository may have been deleted or renamed, or the user may lack permission to access it. This is one of the most common Git errors when cloning or pushing.

Common Causes

  • Incorrect repository URL — The URL specified in the git clone or remote configuration is wrong. This includes typos in the username, repository name, or hostname.
  • Repository was deleted or renamed — The repository existed previously but has since been deleted, made private, or renamed on the hosting platform.
  • Authentication credentials are invalid — Your stored credentials (personal access token, SSH key, or password) have expired or been revoked. GitHub returns 'repository not found' instead of 'access denied' for private repos when credentials fail.
  • Insufficient permissions — Your account does not have access to the repository. For GitHub, you need at least read access. The platform intentionally shows 'not found' instead of 'forbidden' for security reasons.

How to Fix It

1. Check the repository and remote URL

Open the repository in a browser while signed into the intended account. Copy its clone URL from the Code menu. In an existing checkout, compare both fetch and push URLs. Replace OWNER and REPO below with the real values; for a failed initial clone, use the copied URL directly.

git remote -v
# Only if the existing origin URL is wrong:
git remote set-url origin https://github.com/OWNER/REPO.git

2. Check which GitHub account is active

Your browser login and command-line credentials can belong to different accounts. If you use GitHub CLI, check its active account and whether it can see the repository. This checks the CLI’s identity; an HTTPS credential helper or SSH key can still use a different one.

gh auth status --hostname github.com
gh repo view OWNER/REPO

3. Repair HTTPS authentication

GitHub does not accept account passwords for HTTPS Git operations. With GitHub CLI installed, use browser sign-in and configure Git to use those credentials. Otherwise, update the entry for this host in your credential manager. Do not put a token in the remote URL or a pasted command.

gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com

4. Check the SSH identity when using an SSH remote

For a git@github.com:OWNER/REPO.git remote, check which username GitHub recognizes. If it is the wrong account, select the correct key in your SSH configuration. The authenticated account still needs repository access. HTTPS login changes do not repair an SSH key.

ssh -T git@github.com
# Once the SSH identity and access are correct:
git ls-remote git@github.com:OWNER/REPO.git

5. Verify private-repository, token, and organization access

Accept any pending repository invitation and confirm the account has read access; pushing requires write access. If using a fine-grained token, check its resource owner, selected repository, expiry, and Contents permission. Organization approval or SSO authorization may also be required. GitHub’s token guide explains the available restrictions.

6. Test access without changing local files

In an existing checkout, list the remote references. This does not merge, reset, or replace your work. Success confirms read access, even if an empty repository returns no references. A later push failure can still mean missing write permission or a branch rule. For GitLab or another host, use that host’s URL, account, and credential settings.

git ls-remote origin

Frequently Asked Questions

Why does GitHub show 'not found' instead of 'access denied'?

This is intentional. Revealing that a private repository exists (but you cannot access it) is an information leak. By returning 'not found' for both missing and inaccessible repos, GitHub protects the privacy of repository owners.

Do I need a personal access token for GitHub?

You do not have to create a personal access token manually. GitHub CLI browser sign-in, a credential manager, or an SSH key can authenticate Git. If you choose token-based HTTPS authentication, use a token with access to the repository; an ordinary GitHub account password will not work.

How do I check if my SSH key is configured correctly?

Run 'ssh -T git@github.com' (or the appropriate host). If configured correctly, you will see a message confirming your username. If it fails, check that your key is added to ssh-agent and your GitHub account.

Why can I open the repository in my browser but Git cannot clone it?

The browser and Git can be signed into different accounts. Check the HTTPS credential helper or SSH identity used by the clone URL, then confirm that account has repository access. For organization repositories, also check SSO authorization or token approval.
