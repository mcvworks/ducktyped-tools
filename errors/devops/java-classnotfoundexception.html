Java ClassNotFoundException

Last updated: March 8, 2026

Java cannot find the specified class at runtime

You might see this error as:

  • ClassNotFoundException
  • java.lang.ClassNotFoundException
  • Class not found Java
  • NoClassDefFoundError
  • Could not find or load main class

What Does This Error Mean?

ClassNotFoundException is thrown when the Java Virtual Machine (JVM) tries to load a class by its fully qualified name but cannot find it in the classpath. This happens at runtime, not at compile time, and is common when dependencies are missing from the deployment, the classpath is misconfigured, or class names are dynamically loaded via reflection.

Common Causes

  • Missing dependency in classpath — The JAR file containing the class is not included in the application's classpath. This commonly happens when a dependency is declared with 'provided' scope in Maven or when a JAR is missing from the deployment.
  • Incorrect class name in reflection — Code using Class.forName() or ClassLoader.loadClass() specifies an incorrect fully qualified class name, including typos or wrong package names.
  • Wrong version of a dependency — The deployed dependency version does not contain the class that exists in newer or different versions. Package restructuring between versions can move or remove classes.
  • ClassLoader isolation in application servers — Application servers like Tomcat and WildFly use hierarchical ClassLoaders that can prevent classes from being visible across different modules or web applications.

How to Fix It

1. Add the missing dependency

Identify which JAR contains the class and add it to your project's dependencies.

<!-- Maven -->
<dependency>
  <groupId>com.example</groupId>
  <artifactId>library</artifactId>
  <version>1.0.0</version>
</dependency>

// Gradle
implementation 'com.example:library:1.0.0'

2. Verify the classpath

Check that all required JARs are present in the classpath.

# Check classpath:
java -cp myapp.jar:lib/* com.example.Main

# List contents of a JAR:
jar tf library.jar | grep ClassName

3. Check for dependency conflicts

Use build tool commands to analyze the dependency tree and find conflicts or missing transitive dependencies.

# Maven:
mvn dependency:tree

# Gradle:
gradle dependencies

Frequently Asked Questions

What is the difference between ClassNotFoundException and NoClassDefFoundError?

ClassNotFoundException occurs when explicitly loading a class by name (e.g., Class.forName()). NoClassDefFoundError occurs when the JVM cannot find a class that was present at compile time but is missing at runtime. They indicate similar problems but at different levels.

Why does my code compile but throw ClassNotFoundException at runtime?

Compilation and runtime have different classpaths. A class can be available to the compiler (in your IDE or build tool) but missing from the runtime classpath (the deployed JAR or server's lib directory).
