Yarn Integrity Check Failed

Last updated: March 8, 2026

Yarn detected a mismatch between node_modules and yarn.lock

You might see this error as:

  • Yarn integrity check failed
  • error Integrity check failed
  • yarn install --check-files
  • Integrity hash mismatch
  • yarn cache corruption

What Does This Error Mean?

Yarn's integrity check verifies that the installed node_modules directory matches the yarn.lock file. When this check fails, it means something has modified node_modules outside of Yarn, the lockfile is out of sync, or there was a corruption during a previous install. Yarn refuses to proceed to prevent inconsistent dependency states.

Common Causes

  • Mixed package manager usage — Running npm install or another package manager in a Yarn project modifies node_modules in a way that Yarn does not expect, breaking the integrity check.
  • Manual modifications to node_modules — Files in node_modules were manually edited, deleted, or added outside of the package manager workflow.
  • Corrupted node_modules from interrupted install — A previous yarn install was interrupted (killed, crashed, or lost power), leaving node_modules in a partial state.

How to Fix It

1. Reinstall dependencies from scratch

Delete node_modules and reinstall everything cleanly.

rm -rf node_modules
yarn install

2. Clear Yarn cache and reinstall

If the cache is corrupted, clear it and reinstall.

yarn cache clean
rm -rf node_modules
yarn install

3. Check for mixed package manager usage

Ensure no package-lock.json exists alongside yarn.lock, which would indicate npm was also used.

ls package-lock.json
# If it exists, remove it:
rm package-lock.json
rm -rf node_modules
yarn install

Frequently Asked Questions

Can I disable the integrity check?

You can skip it by running 'yarn install --check-files' or setting 'yarn install --force'. However, this masks the underlying problem and may lead to inconsistent dependencies.

Should I commit yarn.lock to version control?

Yes. yarn.lock should always be committed. It ensures all team members and CI/CD systems install the exact same dependency versions. Never add it to .gitignore.
