Permission Denied (publickey)

Last updated: March 8, 2026

SSH authentication failed using public key

You might see this error as:

  • Permission denied (publickey)
  • SSH permission denied
  • git@github.com: Permission denied (publickey)
  • Could not read from remote repository
  • Host key verification failed

What Does This Error Mean?

This error occurs when an SSH connection attempt fails because the server does not accept any of the public keys presented by the client. SSH key authentication requires the client's public key to be registered on the server (in authorized_keys) or with the service (GitHub, GitLab). If no matching key is found, the connection is rejected.

Common Causes

  • SSH key not added to the remote service — Your public key has not been added to your GitHub, GitLab, or server account. The service does not recognize your key and rejects the connection.
  • SSH key not loaded in ssh-agent — The SSH key exists on disk but is not loaded into the ssh-agent, so the SSH client does not present it during authentication.
  • Wrong key being used — Multiple SSH keys exist and the client is presenting the wrong one. SSH tries keys in order, and if the correct key is not tried before the server's authentication limit, the connection fails.
  • Incorrect file permissions on SSH keys — SSH refuses to use private keys with overly permissive file permissions. The private key file must be readable only by the owner (600 or 400 on Unix).

How to Fix It

1. Generate and add SSH key

Generate a new SSH key and add it to your GitHub/GitLab account or remote server.

ssh-keygen -t ed25519 -C "your@email.com"
# Copy public key:
cat ~/.ssh/id_ed25519.pub
# Add to GitHub: Settings > SSH Keys > New SSH Key

2. Add key to ssh-agent

Start the ssh-agent and add your private key.

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

3. Fix SSH key permissions

Set correct permissions on SSH files. Incorrect permissions cause SSH to silently ignore keys.

chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub

4. Test SSH connection

Verify that SSH authentication works with the target service.

ssh -T git@github.com
ssh -vT git@github.com  # Verbose mode for debugging

Frequently Asked Questions

Should I use RSA or Ed25519 keys?

Ed25519 is recommended. It is faster, more secure, and produces shorter keys than RSA. Use 'ssh-keygen -t ed25519'. Only use RSA if the server does not support Ed25519.

How do I use different SSH keys for different services?

Configure the ~/.ssh/config file to specify which key to use for each host. For example, set IdentityFile for github.com and a different IdentityFile for your company's GitLab.

Why does this work on one machine but not another?

Each machine has its own SSH keys. You need to either copy your keys to the new machine or generate new keys and add them to the remote service.
