Docker Container Name Already in Use

Last updated: March 8, 2026

A container with the specified name already exists

You might see this error as:

  • Docker container already exists
  • Conflict. The container name is already in use
  • docker: Error response from daemon
  • Container name conflict

What Does This Error Mean?

This error occurs when you try to create a new container with a name that is already assigned to an existing container, even if that container is stopped. Docker requires unique container names, so the conflicting container must be removed or the new container must use a different name.

Common Causes

  • Previous container was not removed — A container with the same name was created previously and was stopped but not removed. Stopped containers still occupy their name until explicitly deleted.
  • Script or Compose file re-run without cleanup — A deployment script or docker run command is being executed again without first removing the container from the previous run.
  • Docker Compose service conflict — Multiple Compose files or projects are trying to create containers with overlapping names due to identical service names and project names.

How to Fix It

1. Remove the existing container

Stop and remove the conflicting container so the name becomes available.

docker rm -f my-container
# Then retry:
docker run --name my-container nginx

2. Use --rm flag for ephemeral containers

Add --rm to your docker run command to automatically remove the container when it stops, preventing name conflicts on subsequent runs.

docker run --rm --name my-container nginx

3. Rename the existing container

If you want to keep the existing container, rename it instead of removing it.

docker rename my-container my-container-old
docker run --name my-container nginx

Frequently Asked Questions

Why does Docker keep stopped containers?

Docker preserves stopped containers so you can inspect their logs, restart them, or copy files from them. Use 'docker container prune' to remove all stopped containers at once.

Does Docker Compose handle this automatically?

Yes. Docker Compose manages container lifecycle automatically. Running 'docker-compose up' reuses existing containers, and 'docker-compose up --force-recreate' replaces them cleanly.
