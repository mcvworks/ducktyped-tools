Docker No Space Left on Device

Last updated: March 8, 2026

Docker ran out of disk space

You might see this error as:

  • Docker no space left on device
  • no space left on device
  • Error: write /var/lib/docker
  • Docker disk full
  • docker system prune

What Does This Error Mean?

This error occurs when Docker runs out of disk space on the partition where Docker stores its data (typically /var/lib/docker on Linux). Docker images, containers, volumes, and build cache can accumulate over time and consume significant disk space, eventually preventing new operations.

Common Causes

  • Accumulated unused images — Old and unused Docker images pile up over time, especially in CI/CD environments or development machines where many different images are pulled and built.
  • Dangling build cache — Docker's build cache from previous image builds can grow very large, particularly when building images frequently with many layers.
  • Orphaned volumes — Volumes from removed containers may remain on disk. These orphaned volumes are not automatically cleaned up when containers are deleted.
  • Large container logs — Container log files can grow unbounded if no log rotation is configured, especially for containers that produce verbose output.

How to Fix It

1. Run Docker system prune

Remove all unused containers, networks, dangling images, and build cache in one command.

docker system prune -a --volumes
# -a removes all unused images, not just dangling
# --volumes also removes unused volumes

2. Clean up selectively

Remove specific types of Docker objects to reclaim space without affecting everything.

docker image prune -a
docker container prune
docker volume prune
docker builder prune

3. Check Docker disk usage

See exactly how much space each type of Docker object is consuming before deciding what to clean.

docker system df
docker system df -v

4. Configure log rotation

Set default log rotation in Docker daemon configuration to prevent logs from consuming unlimited disk space.

# Add to /etc/docker/daemon.json:
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}

Frequently Asked Questions

How much disk space does Docker typically use?

This varies enormously. A single image can range from 5MB (Alpine) to over 1GB (full OS images). Active development machines commonly accumulate 10-50GB of Docker data. Use 'docker system df' to check.

Is it safe to run docker system prune?

It removes only unused objects, so running containers and their associated images/volumes are preserved. However, you will need to re-pull or rebuild any removed images. Add --volumes carefully as it deletes data in unnamed volumes.

Can I move Docker's data directory to a larger disk?

Yes. Set the 'data-root' option in /etc/docker/daemon.json to point to a directory on a larger partition, then restart Docker.
