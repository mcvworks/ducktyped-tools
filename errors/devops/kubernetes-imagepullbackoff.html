Kubernetes ImagePullBackOff

Last updated: March 8, 2026

Kubernetes cannot pull the container image

You might see this error as:

  • ImagePullBackOff
  • ErrImagePull
  • Kubernetes ImagePullBackOff
  • Failed to pull image
  • Back-off pulling image
  • rpc error: code = Unknown desc = Error response from daemon

What Does This Error Mean?

ImagePullBackOff means Kubernetes is unable to download the container image specified in the pod specification. After the initial failure (ErrImagePull), Kubernetes backs off and retries with increasing delays. Common causes include wrong image names, missing tags, authentication failures, and network issues.

Common Causes

  • Image name or tag does not exist — The image name or tag specified in the pod spec is incorrect or does not exist in the registry. Typos in the image name are a frequent cause.
  • Private registry authentication missing — The image is in a private registry but no imagePullSecrets are configured in the pod spec or service account.
  • Registry is unreachable — The Kubernetes nodes cannot reach the container registry due to network policies, firewall rules, or DNS resolution failures.
  • Image pull policy prevents using cached image — The imagePullPolicy is set to 'Always' and the registry is unreachable, or it is set to 'Never' and the image is not present locally on the node.

📡 Them or you? Before changing anything, check live Docker Hub status on DTMonitor — during a provider incident this error shows up on perfectly healthy setups, and the fix is to wait.

How to Fix It

1. Verify the image name and tag

Check that the image exists in the registry and the tag is correct.

# Check the pod spec:
kubectl get pod <pod-name> -o jsonpath='{.spec.containers[0].image}'

# Verify the image exists:
docker pull <image-name>

2. Create and attach imagePullSecrets

For private registries, create a Kubernetes secret with registry credentials and reference it in the pod spec.

kubectl create secret docker-registry my-registry-key \
  --docker-server=registry.example.com \
  --docker-username=user \
  --docker-password=pass

3. Check node connectivity to registry

SSH into a node and verify it can reach the registry.

# From a debug pod on the node:
kubectl run debug --image=busybox --rm -it -- wget -q -O- https://registry-1.docker.io/v2/

Frequently Asked Questions

What is the difference between ErrImagePull and ImagePullBackOff?

ErrImagePull is the initial failure state. ImagePullBackOff occurs after Kubernetes starts applying exponential backoff delays between pull retries. They represent the same underlying problem at different stages.

How do I use images from a private Docker Hub repository?

Create a docker-registry secret with your Docker Hub credentials and add it to imagePullSecrets in the pod spec. You can also attach the secret to a service account to apply it to all pods in a namespace.
