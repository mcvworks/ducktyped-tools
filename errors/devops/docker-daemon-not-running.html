Docker Daemon Not Running

Last updated: March 8, 2026

Cannot connect to the Docker daemon

You might see this error as:

  • Docker daemon not running
  • Cannot connect to the Docker daemon
  • Is the docker daemon running?
  • docker.sock: connect: permission denied
  • Error: Cannot connect to the Docker daemon

What Does This Error Mean?

This error occurs when the Docker CLI cannot communicate with the Docker daemon (dockerd). The daemon is the background service that manages containers, images, networks, and volumes. Without a running daemon, no Docker commands will work.

Common Causes

  • Docker service is not started — The Docker daemon service has not been started after a system reboot or was manually stopped. On Linux, systemd manages the service; on macOS and Windows, Docker Desktop must be running.
  • Docker Desktop is not running — On macOS and Windows, Docker Desktop must be launched before using Docker CLI commands. The daemon runs inside Docker Desktop's managed VM.
  • Permission denied on Docker socket — The current user does not have permission to access /var/run/docker.sock. This typically happens when the user is not in the 'docker' group on Linux.
  • Docker socket file is missing or corrupted — The Unix socket file at /var/run/docker.sock may have been accidentally deleted or the daemon crashed without cleaning up properly.

How to Fix It

1. Start the Docker service on Linux

Use systemctl to start the Docker daemon and enable it to start on boot automatically.

sudo systemctl start docker
sudo systemctl enable docker

2. Launch Docker Desktop

On macOS or Windows, open Docker Desktop from the Applications folder or Start menu. Wait for the whale icon in the system tray to indicate the daemon is ready.

3. Add your user to the docker group

On Linux, add your user to the docker group so you can run Docker commands without sudo. You need to log out and back in for the change to take effect.

sudo usermod -aG docker $USER
newgrp docker

4. Check Docker daemon status and logs

Inspect the daemon status and logs to identify why it failed to start. Common issues include port conflicts, storage driver problems, or configuration errors.

sudo systemctl status docker
sudo journalctl -u docker.service --no-pager -n 50

Frequently Asked Questions

Why does Docker daemon stop after a reboot?

Docker is not always enabled to start at boot by default. Run 'sudo systemctl enable docker' on Linux to ensure it starts automatically. On macOS/Windows, enable 'Start Docker Desktop when you log in' in Docker Desktop settings.

Can I run Docker without the daemon?

Standard Docker requires the daemon. However, Podman is a daemonless alternative that can run containers without a background service. For Docker, the daemon is required for all operations.

Is this error related to Docker Compose too?

Yes. Docker Compose relies on the Docker daemon. If the daemon is not running, both docker and docker-compose commands will fail with the same error.
