Git Merge Conflict

Last updated: March 8, 2026

Conflicting changes prevent automatic merge

You might see this error as:

  • Git merge conflict
  • CONFLICT (content): Merge conflict
  • Automatic merge failed
  • fix conflicts and then commit
  • Unmerged paths
  • both modified

What Does This Error Mean?

A merge conflict occurs when Git cannot automatically combine changes from two branches because the same lines in a file were modified differently in each branch. Git marks the conflicting sections in the file and stops the merge, requiring manual resolution before the merge can be completed.

Common Causes

  • Same lines modified in both branches — Two developers edited the same lines in the same file on different branches. Git cannot determine which version to keep, so it marks both versions in the file.
  • File deleted in one branch and modified in another — One branch deleted a file while another branch modified it. Git cannot decide whether to keep the modified version or honor the deletion.
  • Diverged branches with overlapping changes — Branches that have been separate for a long time often accumulate overlapping changes in the same files, making conflicts more likely when they are finally merged.

How to Fix It

1. Resolve conflicts manually

Open each conflicted file, look for conflict markers (<<<<<<, =======, >>>>>>), choose the correct code, remove the markers, and stage the file.

# After resolving conflicts in the file:
git add resolved-file.txt
git commit -m "Resolve merge conflict"

2. Accept one side entirely

If you want to accept all changes from one side of the conflict, use the --ours or --theirs strategy.

# Accept current branch's version:
git checkout --ours file.txt

# Accept incoming branch's version:
git checkout --theirs file.txt

git add file.txt

3. Abort the merge

If you want to cancel the merge entirely and return to the state before the merge started.

git merge --abort

4. Use a merge tool

Configure and use a graphical merge tool to visually resolve conflicts.

git mergetool

Frequently Asked Questions

How do I prevent merge conflicts?

Merge frequently from the main branch into your feature branch to keep divergence small. Communicate with team members about which files you are modifying. Keep commits small and focused.

What do the conflict markers mean?

<<<<<<< HEAD marks the start of your current branch's version. ======= separates the two versions. >>>>>>> branch-name marks the end of the incoming branch's version. Delete all markers and keep only the correct code.

Does rebasing cause conflicts too?

Yes. Rebasing replays commits one by one, so you may need to resolve conflicts at each step. However, rebase conflicts are resolved the same way as merge conflicts.
