Git Detached HEAD State

Last updated: March 8, 2026

Git HEAD is not pointing to a branch

You might see this error as:

  • Git detached HEAD
  • HEAD detached at
  • detached HEAD state
  • You are in detached HEAD state
  • git checkout detached

What Does This Error Mean?

A detached HEAD state means that Git's HEAD pointer is pointing directly to a specific commit instead of to a branch reference. Any new commits made in this state are not associated with any branch and can be lost if you switch to another branch without saving them.

Common Causes

  • Checked out a specific commit — Running 'git checkout <commit-hash>' moves HEAD to that commit directly, detaching it from any branch.
  • Checked out a tag — Tags point to specific commits. Checking out a tag with 'git checkout v1.0' puts you in detached HEAD state because tags are not branches.
  • Interactive rebase or bisect — Git operations like rebase and bisect temporarily put the repository into a detached HEAD state as they work through commits.

How to Fix It

1. Create a branch from the current position

If you have made commits in detached HEAD state and want to keep them, create a new branch at the current position.

git checkout -b my-new-branch

2. Return to an existing branch

If you have not made any commits you want to keep, simply switch back to an existing branch.

git checkout main
# or
git switch main

3. Cherry-pick commits onto a branch

If you made commits in detached HEAD and already switched away, recover them using reflog and cherry-pick.

git reflog
# Find the commit hash, then:
git checkout main
git cherry-pick <commit-hash>

Frequently Asked Questions

Will I lose my commits in detached HEAD?

Not immediately. Commits remain in Git's object database and can be found via 'git reflog' for at least 30 days. However, they are not on any branch and will eventually be garbage collected if not saved to a branch.

Is detached HEAD always bad?

No. It is normal during rebase and bisect operations. It is also useful for temporarily inspecting old commits. It only becomes a problem if you make new commits without creating a branch to save them.
