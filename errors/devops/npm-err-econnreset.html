npm ERR! code ECONNRESET

Last updated: March 8, 2026

npm connection to registry was reset

You might see this error as:

  • npm ERR! ECONNRESET
  • network error ECONNRESET
  • npm network error
  • socket hang up npm
  • npm ERR! network request failed

What Does This Error Mean?

ECONNRESET means the TCP connection between npm and the registry was forcibly closed by the remote server or a network intermediary. This typically happens during package downloads and can be caused by network instability, proxy interference, or registry-side issues.

Common Causes

  • Unstable network connection — An intermittent network connection causes the TCP connection to drop during package downloads, especially when downloading large packages.
  • Proxy or firewall interference — A corporate proxy, firewall, or antivirus software is terminating the connection due to SSL inspection, timeout settings, or content filtering rules.
  • npm registry overload — The npm registry is experiencing high traffic or temporary issues that cause it to reset connections.

How to Fix It

1. Retry the installation

Network issues are often transient. Simply retrying the command may work.

npm install
# Or with more verbose output:
npm install --verbose

2. Increase npm timeout and retry settings

Configure npm to wait longer and retry failed requests.

npm config set fetch-retries 5
npm config set fetch-retry-mintimeout 20000
npm config set fetch-retry-maxtimeout 120000

3. Try a different registry mirror

Use an alternative registry mirror if the main registry is unreliable from your location.

npm install --registry https://registry.npmmirror.com

Frequently Asked Questions

Why does this error happen only with large packages?

Large packages take longer to download, giving more time for network instability to cause a connection reset. Proxies and firewalls may also have transfer size limits or idle connection timeouts that trigger on larger downloads.

Should I switch to Yarn if npm keeps failing?

Yarn may handle network issues differently due to its parallel download approach and retry logic. However, the underlying network problem should be fixed regardless of the package manager.
