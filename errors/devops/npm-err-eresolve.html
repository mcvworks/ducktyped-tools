npm ERR! code ERESOLVE

Last updated: March 8, 2026

npm dependency resolution conflict

You might see this error as:

  • npm ERR! ERESOLVE
  • ERESOLVE unable to resolve dependency tree
  • npm peer dependency conflict
  • Could not resolve dependency
  • npm ERR! ERESOLVE overriding peer dependency

What Does This Error Mean?

ERESOLVE occurs when npm cannot find a valid dependency tree that satisfies all peer dependency requirements. This is common in npm 7+ which enforces strict peer dependency resolution by default, unlike npm 6 which only warned about conflicts. The error indicates that two or more packages require incompatible versions of a shared dependency.

Common Causes

  • Incompatible peer dependency versions — Two packages in your dependency tree require different, incompatible versions of the same peer dependency. For example, package A needs React 17 and package B needs React 18.
  • Outdated packages with strict peer dependencies — An older package specifies a narrow peer dependency range that does not include the version you have installed. The package works fine with newer versions but its peerDependencies field was never updated.
  • npm 7+ strict peer dependency enforcement — npm 7 changed to treat peer dependency conflicts as errors by default. Projects that installed fine with npm 6 may fail with npm 7+ due to this stricter behavior.

How to Fix It

1. Use --legacy-peer-deps flag

Install with the legacy peer dependency resolution algorithm that npm 6 used, which ignores peer dependency conflicts.

npm install --legacy-peer-deps

2. Use --force flag

Force npm to proceed with the installation despite conflicts. This may result in an incorrect dependency tree but often works.

npm install --force

3. Update conflicting packages

Update the packages that have conflicting requirements to versions that are compatible with each other.

npm outdated
npm update <package-name>
# Or install specific compatible versions:
npm install package-a@latest package-b@latest

4. Set legacy-peer-deps permanently

Configure npm to always use legacy peer dependency resolution for this project.

echo 'legacy-peer-deps=true' >> .npmrc

Frequently Asked Questions

Is --legacy-peer-deps safe to use?

It is generally safe. It restores the npm 6 behavior of treating peer dependency conflicts as warnings. However, it may result in packages using incompatible versions of shared dependencies, which could cause runtime errors.

What is the difference between --force and --legacy-peer-deps?

--legacy-peer-deps skips peer dependency resolution entirely (npm 6 behavior). --force overrides various protections including peer deps but is more aggressive. For peer dep issues, --legacy-peer-deps is the more targeted solution.

Does Yarn have this problem?

Yarn handles peer dependencies differently. Yarn 1 (Classic) is lenient like npm 6. Yarn 2+ (Berry) with PnP is strict but provides different resolution mechanisms like the 'packageExtensions' field.
