URL Encoding: Spaces, Plus Signs, and Query Parameters

Last updated: September 24, 2026

Encode a value where you add it to a URL. Query parameters, path segments, and complete URLs have different rules. These examples explain %20 versus +, literal percent signs, Unicode, and double encoding.

Build Query Parameters from Raw Values

Pass unencoded text to URLSearchParams. It encodes keys and values, keeping data separate from the & and = delimiters.

const url = new URL("https://example.com/search");
url.searchParams.set("q", "cats & dogs");
url.searchParams.set("language", "C++");
url.toString();
// "https://example.com/search?q=cats+%26+dogs&language=C%2B%2B"

Do not call encodeURIComponent() before searchParams.set(). That would encode a percent sign twice. The URLSearchParams reference describes its form-encoding behavior.

Why Do Spaces Become %20 or +?

%20 is the percent-encoded space byte. Form encoding uses + for a space, including query strings produced by URLSearchParams. A plus sign is not universally a space in every URL component: it remains literal in a path, and a generic percent decoder does not replace it.

encodeURIComponent("a b+c");
// "a%20b%2Bc"

new URLSearchParams({ q: "a b+c" }).toString();
// "q=a+b%2Bc"

decodeURIComponent("a+b%2Bc");
// "a+b+c"

new URLSearchParams("q=a+b%2Bc").get("q");
// "a b+c"

To preserve a plus sign in a query value, pass the raw value through set() or append(). Constructing a query-string parser from an already concatenated string containing raw plus signs will interpret those signs as spaces.

Percent-Encoding Represents Bytes

Each encoded byte is written as % and two hexadecimal digits. JavaScript's component encoder uses UTF-8, so one visible character can need multiple encoded bytes.

encodeURIComponent("café ☕");
// "caf%C3%A9%20%E2%98%95"

encodeURIComponent("100% ready");
// "100%25%20ready"

The URI unreserved set is A–Z a–z 0–9 - . _ ~. Reserved characters have a structural role that depends on the component. Encode a reserved character when it is data and would otherwise act as a delimiter. Do not encode all slashes in a complete URL: that removes the structure you meant to preserve. See RFC 3986's character definitions.

encodeURIComponent() Is Not Strict RFC 3986 Encoding

JavaScript leaves ! ' ( ) * unchanged as well as the unreserved characters. If an API's signing specification requires strict RFC 3986 component encoding, escape those five characters too:

function encodeRFC3986Component(value) {
  return encodeURIComponent(value).replace(/[!'()*]/g, character =>
    "%" + character.charCodeAt(0).toString(16).toUpperCase()
  );
}

Use the encoding required by the receiving API. Percent-encoding is not HTML escaping, encryption, or a general security sanitizer. The encodeURIComponent reference lists its unescaped characters and error cases.

encodeURI() Preserves Delimiters

encodeURI() preserves characters such as :, /, ?, #, &, and =. That makes it unsuitable for escaping a raw query value containing those characters. It also does not determine which part of a concatenated URL was intended as data.

encodeURI("https://example.com/?q=cats & dogs");
// "https://example.com/?q=cats%20&%20dogs"
// The literal & still splits the query.

For user-provided query values, construct a URL and set its search parameters. For a single path segment, component encoding can preserve an embedded slash as %2F, but the receiving router or proxy may decode or reject it. Follow that application's path rules.

Avoid Double Encoding and Guesswork

encodeURIComponent("hello world");
// "hello%20world"
encodeURIComponent("hello%20world");
// "hello%2520world"

Keep raw values and encoded components distinct in your application. A raw string can legitimately contain the characters %20; successfully decoding it does not prove that it was intended as encoded data. Do not automatically decode unfamiliar input before re-encoding it, or repeatedly decode until it stops changing. Apply decoding once at the boundary defined by your protocol.

Encoding and decoding run locally; the text you enter is not sent to our servers. Malformed percent escapes or invalid UTF-8 produce an error. A lone UTF-16 surrogate also cannot be encoded by encodeURIComponent.

Frequently Asked Questions

Does the URL decoder turn + into a space?

No. This tool uses decodeURIComponent, which leaves literal plus signs unchanged. Use URLSearchParams or the Query String Parser for form-encoded query strings, where + represents a space.

Should I encode a complete URL with encodeURIComponent?

No. It would also encode structural characters such as the scheme colon and path slashes. Use a URL object and encode or set the individual values you add.

Why did %20 become %2520?

An already encoded percent sign was encoded again. Pass raw values to URLSearchParams and avoid applying component encoding twice.

Why does decoding report malformed percent-encoding?

A percent escape may be incomplete or contain non-hexadecimal digits, or the decoded bytes may not be valid UTF-8. Check the original value and the encoding expected by its source.
