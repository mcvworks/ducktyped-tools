What Causes DNS_PROBE_FINISHED_NXDOMAIN?

Last updated: March 8, 2026

DNS_PROBE_FINISHED_NXDOMAIN is a browser error indicating that the domain name you tried to visit does not exist in the DNS system. This guide explains what NXDOMAIN means, why it happens, and how to diagnose the root cause.

What NXDOMAIN Means

NXDOMAIN stands for Non-Existent Domain. It is a specific DNS response code (RCODE 3) returned by DNS servers when the queried domain name has no records of any type in the DNS system. This is different from other DNS errors:

  • NXDOMAIN -- the domain itself does not exist in DNS.
  • NODATA -- the domain exists but has no records of the requested type (for example, the domain has MX records but no A record).
  • SERVFAIL -- the DNS server encountered an error while processing the query.
  • REFUSED -- the DNS server refused to answer the query.

When Chrome (or another Chromium-based browser) receives an NXDOMAIN response, it displays the error as DNS_PROBE_FINISHED_NXDOMAIN. Firefox displays a similar "Hmm. We're having trouble finding that site" message. Safari shows "Safari Can't Find the Server."

Common Causes

Typo in the Domain Name

The most frequent cause is simply a misspelled domain name. A single wrong character -- gogle.com instead of google.com -- results in a query for a domain that does not exist. Always double-check the URL in your address bar.

Domain Not Registered

The domain may genuinely not be registered. Someone may have shared a link to a domain that has not been purchased, or a domain registration may have expired without renewal. You can use a WHOIS lookup to check whether the domain is currently registered.

Expired Domain

When a domain registration expires, the registrar eventually removes its DNS records. The domain enters a grace period, then a redemption period, and finally becomes available for re-registration. During and after this process, DNS queries for the domain return NXDOMAIN.

Missing DNS Records

The domain may be registered but have no DNS records configured. This can happen if the domain was recently purchased and the owner has not yet set up hosting, or if nameserver delegation is pointed to servers that do not have a zone configured for the domain.

Nameserver Misconfiguration

If the domain's NS records at the registrar point to nameservers that do not have a zone file for the domain, the authoritative servers will return NXDOMAIN or REFUSED. This commonly occurs when switching DNS providers without properly setting up the zone on the new provider first.

DNS Propagation

If a domain was recently registered or had its nameservers changed, some resolvers may not yet have the updated information. During this propagation window, some resolvers will return NXDOMAIN while others correctly resolve the domain. Propagation typically completes within 24-48 hours.

Local DNS Issues

Sometimes the problem is on the user's side rather than the domain's:

  • Stale DNS cache -- your computer or router may have cached an old NXDOMAIN response.
  • DNS resolver problems -- your ISP's DNS resolver may be experiencing issues or filtering certain domains.
  • VPN or proxy interference -- a VPN or proxy may be using DNS servers that return different results.
  • Hosts file override -- an entry in your system's hosts file may be interfering with resolution.

How to Diagnose

  1. Verify the domain name -- check for typos carefully.
  2. Use a DNS lookup tool -- query the domain using duckTyped's DNS Record Checker to see if authoritative servers return any records.
  3. Check WHOIS -- verify the domain is registered and has not expired.
  4. Try a different DNS resolver -- switch to 8.8.8.8 (Google) or 1.1.1.1 (Cloudflare) to rule out resolver-specific issues.
  5. Flush your DNS cache -- on Windows, run ipconfig /flushdns. On macOS, run sudo dscacheutil -flushcache. On Linux, run sudo systemd-resolve --flush-caches.
  6. Test from another device or network -- if the domain resolves on another network, the problem is likely with your local DNS configuration.
