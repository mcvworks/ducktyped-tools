.env File Example and Syntax Guide

Last updated: September 23, 2026

Start with a small .env file for your API token, then check the loading and quoting rules for your application. The same file can behave differently in Node, Python, Docker Compose, and a shell.

A .env Example with an API Token Placeholder

Create a plain-text file named .env in the location your application expects. This example leaves the token empty so you can fill it in locally:

APP_ENV=development
API_BASE_URL=https://api.example.com
API_TOKEN=
PORT=3000
LOG_LEVEL=info

Download env.example. Save a working copy as .env, replace the example URL, and enter your token after API_TOKEN=. Rename keys to match your app’s documentation. The empty token is a placeholder, not a working credential.

Keep the example blank when sharing it. For a token containing spaces or #, use quotes and check your loader’s rules for $ and backslashes. There is no single .env syntax that every loader implements identically.

Syntax: Keys, Values, Spaces, and Comments

Use one KEY=value pair per line, with simple key names such as API_TOKEN or DATABASE_URL. Values arrive as strings: DEBUG=false is not automatically a Boolean. An empty assignment such as API_TOKEN= is different from an absent key.

# A comment on its own line
APP_NAME="My local app"
TOKEN_WITH_HASH="example#placeholder"
EMPTY_VALUE=

Spaces around = are accepted by several common loaders. Node’s built-in loader, Node dotenv, python-dotenv, and Docker Compose accept them. Bash assignments do not. Writing KEY=value consistently avoids that particular difference; it does not make a file safe to execute as shell code. See the Node .env specification.

Comment handling also varies. Basic Node dotenv treats an unquoted # as the start of a comment. Compose requires a preceding space for an inline comment on an unquoted value. Put comments on their own lines and quote a literal # to reduce surprises.

Which Loader Reads Your File?

LoaderWhitespace around =Variable references
Node dotenvAcceptedBasic parsing leaves references literal; expansion requires an additional tool.
python-dotenvAcceptedSupports ${NAME}; bare $NAME is not expanded.
Docker ComposeAcceptedInterpolates unquoted and double-quoted values; single-quoted values are literal.
Bash assignmentNot acceptedApplies shell expansion and can execute commands.

Escape sequences and multiline values need the same care. Node dotenv converts \n in double-quoted values to a newline, while python-dotenv supports additional escapes. Neither a universal “all backslashes are literal” rule nor a universal “all escapes work” rule is reliable. Follow the dotenv parsing rules or the python-dotenv format documentation for your loader.

Load the File Before Reading a Variable

A .env file is configuration, not an automatic operating-system setting. With a Node version supporting --env-file, you can start an application with:

node --env-file=.env app.js

If your Node app already uses dotenv, load it before modules that read process.env. For Python projects using python-dotenv, an explicit path makes the intended file clear:

from dotenv import load_dotenv

load_dotenv(".env")
# Read configuration after loading the file.

Node dotenv and python-dotenv normally preserve variables already present in the process environment. Their override options change that behavior. Check the existing deployment configuration before assuming your edited file should win.

Docker Compose: .env and Container Variables Are Different

Compose can use .env values to substitute into compose.yaml. That alone does not place every key inside a container. To pass a file to a service, use env_file, or explicitly map selected values with environment:

services:
  app:
    image: your-image:tag
    env_file:
      - .env

Replace your-image:tag with your application image. An explicit environment value can override env_file; a docker compose run -e argument can override the container’s value. Shell variables matter when Compose interpolates or passes them through, rather than automatically entering every container. See Docker’s interpolation guide and container environment precedence.

Keep Real Tokens Out of Shared Files

Add local secret files to .gitignore and commit a template with empty or clearly fake values. For a project that uses .env variants, an example ignore rule is:

.env
.env.*
!.env.example

These rules do not remove files already tracked by Git. If a real credential was exposed, revoke or rotate it with its provider. A replacement password from a generator does not replace an API token issued by a service.

Values included in browser code are visible to visitors. Keep server credentials out of client-side configuration and use your application’s documented public-variable rules.

Frequently Asked Questions

What is a .env file?

A .env file stores configuration as KEY=value lines. An application, framework, or loader must read it; creating the file alone does not add variables to every process.

How do I create a .env file with a place for my token?

Copy the example to a file named .env, replace the empty API_TOKEN value locally, and use the variable name your application expects. Keep a blank .env.example for sharing and keep real tokens out of Git.

Are spaces around the equals sign invalid?

Node’s built-in loader, Node dotenv, python-dotenv, and Docker Compose accept surrounding whitespace. A Bash assignment does not. KEY=value is a useful common style, but KEY = value is not universally invalid.

Do quotes prevent variable expansion?

That depends on the loader. Basic Node dotenv does not expand variable references; Docker Compose and python-dotenv support interpolation with different rules. Do not assume that the same quoted value behaves identically in every runtime.

Why is my .env variable missing?

Check the filename and path, whether the loader ran before the value was read, the exact key name, and whether an existing process variable takes precedence. Restart the application after changing its configuration.

Should I commit .env files to Git?

Keep files containing real secrets out of Git and share an .env.example containing placeholders. If a credential has been exposed, revoke or rotate it; deleting the file does not revoke the credential.
