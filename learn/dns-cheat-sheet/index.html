DNS Records Cheat Sheet

Last updated: March 11, 2026

Email DNS Records — SPF, DKIM, DMARC

SPF (Sender Policy Framework)

SPF declares which servers are allowed to send email for your domain. It is a TXT record at the root domain.

MechanismSyntaxMeaning
Includeinclude:_spf.google.comAllow Google's mail servers
IP4ip4:203.0.113.0/24Allow this IP range
IP6ip6:2001:db8::/32Allow this IPv6 range
AaAllow IPs from domain's A record
MXmxAllow IPs from domain's MX records
All (soft fail)~allSoft-fail everything else (recommended)
All (hard fail)-allReject everything else (strict)

Example SPF record:

v=spf1 include:_spf.google.com include:sendgrid.net ip4:203.0.113.5 ~all

DKIM (DomainKeys Identified Mail)

DKIM adds a cryptographic signature to outgoing email. The public key is published as a TXT record at selector._domainkey.example.com.

Example DKIM record:

v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNA...

Common selectors: google._domainkey (Google Workspace), selector1._domainkey (Microsoft 365), s1._domainkey (generic).

DMARC (Domain-based Message Authentication)

DMARC ties SPF and DKIM together and tells receivers what to do when checks fail. It is a TXT record at _dmarc.example.com.

TagValuesMeaning
vDMARC1Version (required)
pnone / quarantine / rejectPolicy for failures (required)
ruamailto:dmarc@example.comSend aggregate reports to this address
rufmailto:forensics@example.comSend forensic (failure) reports
pct100Percentage of messages to apply policy to
spnone / quarantine / rejectPolicy for subdomains

Example DMARC record:

v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@example.com; pct=100

Common DNS Configurations

New Domain Setup

; A record — point domain to your server
example.com.    A       203.0.113.10

; AAAA record — IPv6
example.com.    AAAA    2001:db8::1

; www subdomain — alias to root
www             CNAME   example.com.

; Email — Google Workspace
@               MX  1   ASPMX.L.GOOGLE.COM.
@               MX  5   ALT1.ASPMX.L.GOOGLE.COM.
@               MX  10  ALT2.ASPMX.L.GOOGLE.COM.

; SPF
@               TXT     "v=spf1 include:_spf.google.com ~all"

; DMARC
_dmarc          TXT     "v=DMARC1; p=none; rua=mailto:dmarc@example.com"

; CAA — only Let's Encrypt can issue certs
@               CAA  0  issue "letsencrypt.org"

Microsoft 365 Email

; MX
@               MX  0   example-com.mail.protection.outlook.com.

; SPF
@               TXT     "v=spf1 include:spf.protection.outlook.com ~all"

; DKIM (two selectors)
selector1._domainkey    CNAME   selector1-example-com._domainkey.example.onmicrosoft.com.
selector2._domainkey    CNAME   selector2-example-com._domainkey.example.onmicrosoft.com.

; Autodiscover
autodiscover    CNAME   autodiscover.outlook.com.

CDN Setup (Cloudflare example)

; Proxy through CDN
@               A       104.26.10.1    (proxied)
www             CNAME   example.com.   (proxied)

; Direct — bypass CDN
api             A       203.0.113.20   (DNS only)

Frequently Asked Questions

Can I use a CNAME at the zone apex (root domain)?

No, the DNS specification (RFC 1034) prohibits CNAME records at the zone apex because they conflict with other required records (SOA, NS). Many DNS providers offer a workaround called ALIAS or ANAME records that flatten the CNAME at query time.

What happens if I have conflicting DNS records?

If you have both an A record and a CNAME for the same name, behavior is undefined and varies by DNS resolver. Always use one or the other, never both. Multiple A records for the same name is valid (round-robin load balancing).

How do I verify my DNS changes propagated?

Use the DNS Propagation Checker to query your domain from multiple DNS servers worldwide. If all servers return the updated records, propagation is complete.

What is DNSSEC?

DNSSEC (DNS Security Extensions) adds cryptographic signatures to DNS records to prevent spoofing and cache poisoning. It uses DNSKEY, DS, RRSIG, and NSEC record types to create a chain of trust from the root zone to your domain.
