Complete HTTP Status Code Reference

Last updated: March 11, 2026

Every HTTP status code explained in one page. Bookmark this reference for quick lookups when building APIs, debugging servers, or troubleshooting web applications.

HTTP status codes are three-digit numbers returned by a web server in response to a client request. The first digit defines the class of response, while the last two digits provide specificity. Understanding these codes is essential for web development, API design, and troubleshooting.

1xx — Informational

The server has received the request and is continuing to process it.

CodeNameDescription
100ContinueThe server has received the request headers; the client should send the body

102ProcessingThe server is processing the request but has no response yet (WebDAV)
103Early HintsUsed with the Link header to preload resources while the server prepares a response

Status Code Decision Tree

Quick decision guide for choosing the right response code:

  • Did the request succeed?
    • Yes, returning data → 200 OK
    • Yes, resource created → 201 Created
    • Yes, nothing to return → 204 No Content
    • Yes, processing async → 202 Accepted
  • Should the client go elsewhere?
    • Permanently moved → 301 (may change method) or 308 (preserves method)
    • Temporarily moved → 302 (may change method) or 307 (preserves method)
    • Cached version is fine → 304 Not Modified
  • Is it the client's fault?
    • Bad syntax → 400
    • Not authenticated → 401
    • Not authorized → 403
    • Resource missing → 404
    • Validation failed → 422
    • Too fast → 429
  • Is it the server's fault?
    • Unknown error → 500
    • Upstream failed → 502
    • Overloaded/maintenance → 503
    • Upstream too slow → 504

Frequently Asked Questions

What are HTTP status codes?

HTTP status codes are three-digit numbers returned by servers to indicate the result of a client's request. They are grouped into five classes: 1xx (informational), 2xx (success), 3xx (redirection), 4xx (client error), and 5xx (server error).

What is the difference between 401 and 403?

401 Unauthorized means the request lacks valid authentication credentials — the user needs to log in. 403 Forbidden means the server understood the request but refuses to authorize it — the user is authenticated but does not have permission for this specific resource.

What is the difference between 301 and 302 redirects?

A 301 redirect is permanent — search engines transfer link equity to the new URL and update their index. A 302 redirect is temporary — search engines keep the original URL indexed. Use 301 for permanent URL changes and 302 for temporary situations.

Which status code should I use for form validation errors?

Use 422 Unprocessable Entity for validation errors where the request body is syntactically correct but semantically invalid (e.g., missing required fields, invalid email format). Use 400 Bad Request for malformed syntax (e.g., invalid JSON).

Why am I getting a 502 Bad Gateway error?

A 502 error means a reverse proxy (like nginx or Cloudflare) received an invalid response from the upstream application server. Check that your application server is running, not crashing, and responding within the proxy's timeout. See the 502 troubleshooting guide for step-by-step fixes.
