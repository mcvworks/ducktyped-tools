Port Ranges Explained

Well-Known Ports (0–1023)

Assigned by IANA for specific services. Binding to these ports requires administrative (root/admin) privileges on most operating systems. Examples: HTTP (80), HTTPS (443), SSH (22), DNS (53), SMTP (25).

Registered Ports (1024–49151)

Assigned to applications and services but not as tightly controlled as well-known ports. Non-administrative users can bind to these. Common development choices: Node.js (3000), Django (8000), Flask (5000), general HTTP alt (8080, 8443). These are the ports you'll choose for your own services.

Ephemeral Ports (49152–65535)

Dynamic or private ports — not pre-assigned. Operating systems use these for outgoing connections (the source port in client-server communication). When a client connects to a server, the OS picks an available port in this range automatically. You generally don't configure ephemeral ports manually.

Ports and Firewalls

A firewall's job is to control which ports can be accessed from outside your network. Every production server should follow these rules:

  • Whitelist explicitly, deny by default: Only open the ports your application needs. Close everything else.
  • Restrict by source IP: If you can, limit access to specific IPs (your office, VPN, load balancer) rather than 0.0.0.0.
  • Keep databases private: Database ports (3306, 5432, 6379, 27017) should NEVER be visible from the internet. Use a bastion host, private subnet, or SSH tunnel instead.
  • Use non-standard ports if possible: Services on ports other than their defaults (e.g., SSH on 2222 instead of 22) reduce automated attack noise, but this is security through obscurity — don't rely on it alone.
  • Monitor unexpected open ports: Periodically scan your servers for open ports you didn't authorize. A compromised service might open new ports for persistence.

Troubleshooting Connection Refused

If you get a <service> connection refused error:

  1. Is the service running? (Check logs, process list.)
  2. Is it listening on the expected port? (Use lsof -i :PORT on Unix, netstat -ano | findstr :PORT on Windows.)
  3. Is there a firewall rule blocking the port? (Check OS firewall and upstream network firewalls.)
  4. If connecting over the network, is the hostname/IP correct? (Check DNS resolution.)

For specific database connection errors, see: PostgreSQL connection refused, Redis connection refused, MongoDB connection failed, MySQL access denied.
