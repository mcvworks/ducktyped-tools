Regex Cheat Sheet

Last updated: March 11, 2026

Complete regular expression reference. Bookmark this page for quick lookups when writing patterns for validation, search, and text processing.

Regular expressions (regex) are patterns that describe sets of strings. They are supported in virtually every programming language and are essential for text search, validation, parsing, and transformation. Learn more about regex fundamentals or test your patterns live.

Quantifiers

PatternMatchesExample
*0 or more (greedy)ab*c → "ac", "abc", "abbc"
+1 or more (greedy)ab+c → "abc", "abbc" (not "ac")
?0 or 1 (optional)colou?r → "color", "colour"
{n}Exactly n times\d{4} → "2026"
{n,}n or more times\d{2,} → "12", "123", "1234"
{n,m}Between n and m times\d{2,4} → "12", "123", "1234"
*?0 or more (lazy/non-greedy)<.*?> → matches shortest tag
+?1 or more (lazy/non-greedy)".+?" → matches shortest quoted string

Special Characters to Escape

These characters have special meaning in regex and must be escaped with \ to match literally:

. * + ? ^ $ { } [ ] ( ) | \ /

For example, to match a literal dot: \. — to match a literal dollar sign: \$

Frequently Asked Questions

What is the difference between greedy and lazy matching?

Greedy quantifiers (*, +) match as many characters as possible. Lazy quantifiers (*?, +?) match as few as possible. For example, given the string <b>bold</b>, the pattern <.*> (greedy) matches the entire string, while <.*?> (lazy) matches just <b>.

Should I use regex to parse HTML?

No. HTML is a context-free language that regex cannot fully parse. Use a proper HTML parser (DOMParser, cheerio, Beautiful Soup) instead. Regex is fine for simple pattern extraction from known HTML structures, but not for general HTML parsing.

How do I match across multiple lines?

Use the s (dotAll) flag to make . match newlines, or use [\s\S] as a cross-platform alternative. The m (multiline) flag makes ^ and $ match line boundaries instead of string boundaries.

Why is Go regex different?

Go uses the RE2 engine which guarantees linear-time matching by disallowing backtracking features like backreferences, lookahead, and lookbehind. This makes Go regex safer against ReDoS (Regular Expression Denial of Service) but less feature-rich.
