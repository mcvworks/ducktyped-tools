HTTP Headers Cheat Sheet

Last updated: June 11, 2026

Quick reference for every HTTP header you'll meet in practice — request, response, security, caching, CORS, authentication, and content negotiation. Each entry shows direction, format, and a real example.

Inspect live headers by sending requests with the HTTP Request Builder, audit your security headers with the Security Headers checker, and look up response codes in the HTTP Status Codes guide.

Request Headers

Sent by the client (browser, curl, API consumer) to describe the request.

HeaderExamplePurpose
HostHost: example.comTarget hostname (and optional port). Required in HTTP/1.1; lets one IP serve many sites.
AcceptAccept: text/html, application/json;q=0.9Media types the client can process, with quality weights.
AuthorizationAuthorization: Bearer eyJhbGciOi...Credentials for the request (see Authentication section).
Cache-ControlCache-Control: no-cacheCaching directives from the client (e.g., force revalidation).
CookieCookie: session=abc123; theme=darkCookies previously set by the server, sent back on each request.
User-AgentUser-Agent: Mozilla/5.0 (X11; Linux x86_64) ...Identifies the client software.
RefererReferer: https://example.com/pageURL of the page that triggered the request. (Yes, the misspelling is in the spec.)
OriginOrigin: https://app.example.comScheme + host + port of the requesting context; basis of CORS checks.
Content-TypeContent-Type: application/jsonMedia type of the request body (POST/PUT/PATCH).
Content-LengthContent-Length: 348Size of the request body in bytes.
If-None-MatchIf-None-Match: "33a64df5"Conditional request: only send the body if the ETag changed.
If-Modified-SinceIf-Modified-Since: Tue, 09 Jun 2026 14:00:00 GMTConditional request based on modification date.
RangeRange: bytes=0-1023Request part of a resource (resumable downloads, video seeking).
ConnectionConnection: keep-aliveConnection handling for the current hop (HTTP/1.1 only).
UpgradeUpgrade: websocketRequest a protocol switch (WebSocket handshake).
ExpectExpect: 100-continueWait for server approval before sending a large body.
X-Forwarded-ForX-Forwarded-For: 203.0.113.5, 70.41.3.18Original client IP(s) added by proxies. Standardized replacement: Forwarded.
X-Forwarded-ProtoX-Forwarded-Proto: httpsOriginal scheme before a TLS-terminating proxy.

Response Headers

Sent by the server to describe the response and control client behavior.

HeaderExamplePurpose
Content-TypeContent-Type: text/html; charset=utf-8Media type and charset of the body.
Content-LengthContent-Length: 5120Body size in bytes (absent when chunked).
Content-EncodingContent-Encoding: brCompression applied to the body (gzip, br, zstd, deflate).
Content-DispositionContent-Disposition: attachment; filename="report.pdf"Display inline or force a download with a filename.
LocationLocation: https://example.com/new-pathRedirect target (3xx) or created resource URL (201). Trace chains with the Redirect Checker.
Set-CookieSet-Cookie: session=abc; Path=/; HttpOnly; Secure; SameSite=LaxStore a cookie on the client. One header per cookie.
Cache-ControlCache-Control: public, max-age=86400Primary caching policy (see caching section).
ETagETag: "33a64df5"Opaque version identifier for conditional requests.
Last-ModifiedLast-Modified: Tue, 09 Jun 2026 14:00:00 GMTWhen the resource last changed.
VaryVary: Accept-Encoding, OriginRequest headers that affect the response — keys the cache entry.
ServerServer: nginxServer software. Keep it vague; version numbers help attackers.
DateDate: Thu, 11 Jun 2026 09:00:00 GMTWhen the response was generated.
AllowAllow: GET, HEAD, POSTMethods supported by the resource (sent with 405).
Retry-AfterRetry-After: 120Seconds (or date) to wait before retrying (429, 503).
WWW-AuthenticateWWW-Authenticate: Basic realm="admin"Challenge sent with 401 stating the required auth scheme.
Accept-RangesAccept-Ranges: bytesServer supports range requests.
Transfer-EncodingTransfer-Encoding: chunkedBody sent in chunks of unknown total length (HTTP/1.1).
Alt-SvcAlt-Svc: h3=":443"; ma=86400Advertises HTTP/3 (QUIC) availability.

Content-Security-Policy Quick Syntax

Content-Security-Policy:
  default-src 'self';
  script-src 'self' https://cdn.example.com;
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  connect-src 'self' https://api.example.com;
  frame-ancestors 'none';
  upgrade-insecure-requests
DirectiveControls
default-srcFallback for all fetch directives
script-src / style-srcWhere JS / CSS may load from
img-src / font-src / media-srcImages, fonts, audio/video sources

Caching Headers Deep-Dive

Cache-Control Directives

DirectiveMeaning
max-age=3600Fresh for N seconds from the time of the response
s-maxage=86400Like max-age, but only for shared caches (CDNs, proxies)
publicAny cache may store it, even when authenticated
privateOnly the browser may store it — never CDNs/proxies
no-cacheMay store, but must revalidate with the origin before reuse
no-storeNever store anywhere — use for sensitive data
must-revalidateOnce stale, must revalidate — never serve stale
immutableWill never change during max-age — skip revalidation on reload
stale-while-revalidate=60Serve stale for N seconds while refreshing in the background
stale-if-error=600Serve stale for N seconds if the origin errors

Common Caching Recipes

# Fingerprinted static assets (app.4f3a2b.js) — cache forever
Cache-Control: public, max-age=31536000, immutable

# HTML pages — always revalidate
Cache-Control: no-cache

# API responses — short browser cache, longer CDN cache
Cache-Control: private, max-age=0, s-maxage=60, stale-while-revalidate=30

# Sensitive data (banking, PII) — never store
Cache-Control: no-store

# Legacy compatibility trio
Cache-Control: no-store
Pragma: no-cache
Expires: 0

Validators: ETag and Last-Modified

# First response
HTTP/1.1 200 OK
ETag: "33a64df5"
Last-Modified: Tue, 09 Jun 2026 14:00:00 GMT

# Next request — client revalidates
GET /style.css HTTP/1.1
If-None-Match: "33a64df5"
If-Modified-Since: Tue, 09 Jun 2026 14:00:00 GMT

# Unchanged — no body sent
HTTP/1.1 304 Not Modified

ETag wins over Last-Modified when both are present: it has no one-second granularity limit and survives content-identical regenerations. See the 304 Not Modified guide for troubleshooting.

Vary

Vary tells caches which request headers produce different responses. Vary: Accept-Encoding keeps gzip and brotli copies separate; Vary: Origin is essential when CORS responses are cached. Vary: * effectively disables caching.

CORS Headers

Cross-Origin Resource Sharing controls which web origins may read responses from your server.

HeaderDirectionExamplePurpose
OriginRequestOrigin: https://app.example.comRequesting origin — sent automatically by the browser
Access-Control-Allow-OriginResponsehttps://app.example.com or *Origins allowed to read the response. * cannot be combined with credentials.
Access-Control-Allow-MethodsResponse (preflight)GET, POST, PUT, DELETEMethods allowed for the actual request
Access-Control-Allow-HeadersResponse (preflight)Content-Type, AuthorizationRequest headers the client may send
Access-Control-Allow-CredentialsResponsetrueAllow cookies/auth on cross-origin requests; requires an explicit (non-*) origin
Access-Control-Expose-HeadersResponseX-Request-Id, ETagExtra response headers JavaScript may read
Access-Control-Max-AgeResponse (preflight)86400Seconds to cache the preflight result
Access-Control-Request-MethodRequest (preflight)PUTMethod the actual request intends to use
Access-Control-Request-HeadersRequest (preflight)content-typeHeaders the actual request intends to send

Preflight Example

# Browser sends preflight before a cross-origin PUT with JSON
OPTIONS /api/items/42 HTTP/1.1
Host: api.example.com
Origin: https://app.example.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: content-type, authorization

# Server approves
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 86400

Content Negotiation

The client states preferences; the server picks the best representation and echoes the decision in Vary.

Request HeaderExampleNegotiatesServer Responds With
Acceptapplication/json, text/html;q=0.8Media typeContent-Type
Accept-Languageen-US, en;q=0.9, de;q=0.5LanguageContent-Language
Accept-Encodingbr, gzip;q=0.9, zstdCompressionContent-Encoding

Quality values (q=) range 0–1 and express preference order; omitted q means 1.0. A server that cannot satisfy Accept may return 406 Not Acceptable.

Frequently Asked Questions

Are HTTP header names case-sensitive?

No — header names are case-insensitive per the spec. HTTP/2 and HTTP/3 transmit them in lowercase. Header values, however, may be case-sensitive depending on the header (ETag values are, for example).

Is there a size limit on headers?

The spec sets no limit, but servers do: Nginx defaults to 8 KB per header line, Apache to 8 KB, Node.js to 16 KB total. Exceeding the limit yields 431 Request Header Fields Too Large or a generic 400. Bloated cookies are the usual culprit.

What do the X- prefixed headers mean?

The X- prefix marked experimental/custom headers. RFC 6648 deprecated the convention in 2012, but established names (X-Forwarded-For, X-Content-Type-Options, X-Frame-Options) persist for compatibility. New standards drop the prefix — e.g., Forwarded replaces X-Forwarded-For.

What's the difference between Set-Cookie SameSite values?

SameSite=Strict never sends the cookie on cross-site requests. Lax (the modern default) sends it on top-level navigations only (clicking a link), blocking CSRF-prone cross-site POSTs. None sends it everywhere but requires Secure.

Do headers behave differently in HTTP/2 and HTTP/3?

Semantics are identical, but headers are compressed (HPACK in HTTP/2, QPACK in HTTP/3), names are lowercase, and connection-specific headers (Connection, Keep-Alive, Transfer-Encoding, Upgrade) are forbidden. The status line becomes the :status pseudo-header.
